Verilog for absolute beginners

Verilog is a language for describing a circuit: which wires go into which gates, and where the outputs go. It is not a list of steps. Everything you write exists at the same time, like real wires on a board.

Think of it like this: a recipe says "first do this, then do that". A house wiring plan says "this switch is connected to that lamp". Verilog is the wiring plan. When you flip a switch, the lamp changes straight away. Nobody "runs" the plan line by line.

Key terms

HDL
Hardware Description Language. A language that describes circuits. Verilog is one.
Module
One circuit block, like a chip. It has a name, pins, and the wiring inside.
Port
A pin on the module. It is an input or an output.
Signal
A value carried on a wire: 0 (low, off) or 1 (high, on).
wire (a "net")
A real wire. It stores nothing. It always shows whatever is driving it.
reg (a "variable")
A signal that keeps its value until it is given a new one inside an always or initial block.
Vector / bus
A group of wires with one name, e.g. 8 wires called data.
Testbench
A second module that feeds test inputs into your circuit and records what comes out.
DUT
Design Under Test: the circuit the testbench is checking.
Simulation
Pretending the circuit exists, on your laptop, to check it. Nothing is built.
Synthesis
Turning Verilog into a real list of gates (a netlist) that can be made into a chip.
X
"Unknown" value. A signal nobody has set yet shows X (drawn red in GTKWave).

1. Software thinking vs hardware thinking

This is the most important idea on the page. A program does one step, then the next. A circuit does everything at once.

Software (a to-do list)

for (i=0; i<4; i++) lamp[i]=1;

In plain words: "Set i to 0. Turn on lamp i. Add 1 to i. Repeat while i is less than 4." The four lamps turn on one after another.

Hardware (a wiring plan)

assign lamp = switch;

In plain words: "Connect the 4 switch wires to the 4 lamp wires." All four connections exist together, all the time.

The instructor's warning

"Every bug this mismatch causes in Lab 1 traces back to reading Verilog like a to-do list instead of a wiring diagram." When you read a line of Verilog, picture a wire, not a step.

3. Your first module: an AND gate

A module is a box with pins. You say which pins are inputs and outputs, then describe the wiring inside.

verilog · and_gate.vcode → what it means
// a 2-input AND gateA comment: a note for humans. Verilog ignores everything after // on that line. Use /* ... */ for notes over several lines.
module and_gate (Start a circuit block called and_gate. The pin list starts after (.
input wire a, input wire b,Two input pins, a and b. Each one is a plain wire. Commas separate pins.
output wire yOne output pin, y. The last pin has no comma after it.
);End of the pin list. Most lines in Verilog end with a semicolon ;.
assign y = a & b;Connect y to "a AND b". & means AND. This is a permanent connection: whenever a or b changes, y changes too.
endmoduleEnd of the block. Note: no semicolon here.
Three small rules
  • Case matters. and_gate and AND_GATE are two different names. Keywords like module are always lowercase.
  • Ports are wires by default. input a means the same as input wire a.
  • A missing ; is the most common error. The tool usually complains about the line after the real mistake.

4. wire vs reg

wire (net)

A physical wire. It holds nothing by itself. It just shows what is connected to it.

Gets its value from assign or from a module's output pin.

reg (variable)

Keeps its value until something gives it a new one.

Gets its value inside always or initial blocks.

reg does NOT always mean a flip-flop (a memory cell). Inside always @(*) a reg is still just plain gates.

wire ↔ assign   |   reg ↔ always / initialThe most-tested rule: anything on the left of = inside an always block must be declared reg.

integer k; is another kind of variable. It holds a whole number. Use it only in testbenches, e.g. as a loop counter.

5. Vectors (buses): many wires, one name

wire [7:0] data; makes 8 wires named data[7] down to data[0]. Always write the range as [MSB:LSB]: the left number is the most significant (biggest) bit, the right number is the least significant bit.

Writing numbers in Verilog

4'b1010 means: 4 bits wide, written in binary, value 1010. Similarly 8'hFF is 8 bits in hex, and 8'd10 is 8 bits in decimal. A plain 10 is just decimal ten. See Number systems for binary and hex.

& is not &&

For single-bit signals they give the same answer. For buses they don't: & works on each bit pair; && gives one true/false bit. For gates, use the single-symbol bitwise operators.

7. assign: a permanent connection

assign y = expression; is called a continuous assignment. In the lab's words: "No clock, no trigger, no waiting." The output always follows the inputs. The left side must be a wire. The order of several assign lines does not matter, because they all exist at once.

8. always blocks: describing behaviour

Sometimes it is easier to describe what a circuit does than to list its gates. An always block does that. The part after @ is the sensitivity list: it says when the block should update.

always @(*)

Combinational logic: output depends only on the inputs right now (like gates). * means "update whenever any input changes".

always @(posedge clk)

Sequential logic: output changes only at the rising edge of the clock (the moment clk goes from 0 to 1). This makes memory (flip-flops).

verilog · always examplescode → what it means
module and_beh (input a, input b,Same AND gate, written with an always block.
output reg y);y is reg because it is set inside always.
always @(*) beginRecalculate whenever a or b changes. begin ... end groups lines, like brackets.
y = a & b;Give y the value a AND b. Built as a plain AND gate, not memory.
endEnd of the group.
endmodule
module dff (input clk, input d,A D flip-flop: a 1-bit memory cell.
output reg q);
always @(posedge clk)Only wake up when the clock rises from 0 to 1.
q <= d;At that moment, copy d into q. Between edges q holds its value.
endmodule

= vs <=

Blocking =

Takes effect immediately. The next line already sees the new value.

Use in always @(*) (combinational).

a=1, b=0. a = b; b = a; → a becomes 0, then b gets the new a (0). Both end as 0.

Non-blocking <=

All right-hand sides are read first, then all left sides update together at the end.

Use in always @(posedge clk) (sequential).

a=1, b=0. a <= b; b <= a; → both read old values. a becomes 0, b becomes 1. They swap, like real flip-flops.

Don't confuse the two meanings of <=

As a statement (q <= d;) it means "non-blocking assign". Inside a comparison (if (a <= b)) it means "less than or equal".

Other things you will see

  • initial begin ... end: runs once, starting at time 0. A module can have several; they all start together. Used in testbenches.
  • `timescale 1ns/1ps: at the top of a file. "One time unit = 1 nanosecond, measured to 1 picosecond accuracy." So #10 = 10 ns.
  • `define WIDTH 8: a text shortcut, used as `WIDTH. Prefer parameter WIDTH = 8; inside a module.
  • `include "file.v": paste another file in here.

9. Testbench anatomy

A design module does nothing on its own: nobody is flipping its inputs. A testbench is a separate module that plays the role of the person at the lab bench. It sets inputs, waits, and records the outputs.

verilog · and_tb.vcode → what it means
`timescale 1ns/1psOptional. Makes one time unit = 1 ns.
module and_tb;The testbench is a module with no ports. Nothing plugs into it; it is the whole test world.
reg a, b;The inputs we will drive. They are reg because we set them inside initial and they must hold their value.
wire y;The output we will watch. It is a wire because the AND gate drives it.
and_gate dut (.a(a), .b(b), .y(y));Place one copy (an instance) of and_gate, named dut. .a(a) = "connect its pin a to my signal a".
initial beginThe test script. Runs once from time 0. Here lines do run in order.
$dumpfile("and.vcd");Name the waveform file to create (VCD = Value Change Dump).
$dumpvars(0, and_tb);Record every signal in and_tb and everything inside it (0 = all levels). Without this line, the VCD is empty.
$monitor("t=%0t a=%b b=%b y=%b",Print a line every time one of the listed signals changes. %b = show as binary, %0t = show a time.
$time, a, b, y);$time is the current simulation time. The values fill the % slots in order.
a=0; b=0; #10;Set both inputs to 0, then wait 10 time units (#10 = delay).
a=0; b=1; #10;Next row of the truth table, wait again.
a=1; b=0; #10;Third row.
a=1; b=1; #10;Fourth row. y should become 1 now.
$finish;End the simulation (at time 40). $stop would only pause it.
end
endmodule

What vvp prints because of $monitor:

t=0 a=0 b=0 y=0
t=10 a=0 b=1 y=0
t=20 a=1 b=0 y=0
t=30 a=1 b=1 y=1

After these lines, vvp prints a short note that $finish was called at time 40. Each printed line matches one row of the AND truth table.

Testing every row with a loop

With more inputs, use a counter: integer k; then for (k = 0; k < 4; k = k + 1) begin {a, b} = k; #10; end. In plain words: "k goes 0, 1, 2, 3. Each time, split k's two lowest bits into a and b, then wait 10." {a, b} = k puts bit 1 of k into a and bit 0 into b.

11. How to read a GTKWave waveform

In GTKWave: click and_tb in the top-left panel (SST), select the signals, click Append (or drag them into the Signals pane), then press Zoom Fit. You will see this:

  1. Find the time axis along the top or bottom. Each #10 in the testbench is one slot.
  2. Pick a time slot (click to place the cursor). The value panel shows every signal at that moment.
  3. Read the inputs, then check the output matches your truth table row.
  4. Look for red (X) or a flat line that never moves. That usually means a missing connection or an input nobody set.
  5. Buses (like sum[3:0]) appear as a band with the value written inside. Right-click → Data Format to switch between binary, hex and decimal.

12. The other gates (and a slide correction)

verilog · gates.vcode → what it means
module or_gate (input a, input b, output y);Whole module on one line. Ports default to wires.
assign y = a | b;| is OR: y is 1 if at least one input is 1.
endmodule
module not_gate (input a, output y);NOT has one input.
assign y = ~a;~ flips the bit: 0 → 1, 1 → 0.
endmodule
module xor_gate (input a, input b, output y);
assign y = a ^ b;^ is XOR: y is 1 when a and b are different.
endmodule
module xnor_gate (input a, input b, output y);Take-home task.
assign y = ~(a ^ b);XNOR = NOT XOR: 1 when a and b are the same.
endmodule
Slide correction

The slide says XOR is "1 if either input is 1". That describes OR. XOR is 1 when the inputs are different: XOR(1,1) = 0, but OR(1,1) = 1. Always check the 1,1 row.

Take-home: build NAND by connecting your and_gate output into a not_gate (two instances and one internal wire), and build NOR from primitives. More on gates in Boolean algebra & logic gates.

Common mistakes & exam traps

Slips that cost marks
  • Reading Verilog as a to-do list. assign lines are wires; their order does not matter.
  • Setting a wire inside always. The left side inside any always block must be reg.
  • Thinking reg always means a flip-flop. In always @(*) it is plain gates.
  • Using = in clocked blocks or <= in combinational blocks.
  • Writing a bus backwards: use [7:0] (MSB first), not [0:7].
  • Using && when you meant the bitwise gate &.
  • $dumpfile alone gives an empty VCD. You also need $dumpvars.
  • Unset signals are X, not 0.
  • XOR is "different", not "either".

Practice

What does wire [3:0] n; create? Which bit is the MSB?

Four wires: n[3], n[2], n[1], n[0]. The left number in the range is the MSB, so n[3] is the MSB.

Evaluate 4'b1100 & 4'b1010 and 4'b1100 && 4'b1010.

Bitwise, bit by bit: 1&1=1, 1&0=0, 0&1=0, 0&0=0 → 4'b1000.

Logical: both values are non-zero, so both count as "true" → 1 (one bit).

Why are a and b declared reg in the testbench, but y is a wire?

The testbench sets a and b inside an initial block, and they must hold their values during each #10 wait, so they are variables (reg). y is driven by the AND gate's output pin, so it is a wire.

Write one line of Verilog for an XNOR gate with inputs a, b and output y.

assign y = ~(a ^ b); (or assign y = a ~^ b;). y is 1 when a and b are equal.

a = 1 and b = 0. What are a and b after a = b; b = a;? And after a <= b; b <= a; at a clock edge?

Blocking: a becomes 0 first, then b takes the new a → a = 0, b = 0.

Non-blocking: both right sides are read first (b=0, a=1), then updated together → a = 0, b = 1 (swapped).

Your GTKWave shows y as a red band the whole time. Give two likely causes.

Red means X (unknown). (1) An input of the gate was never assigned in the testbench. (2) A port is not connected in the instance line, e.g. a typo in .b(b). Check the instance and give every input a value at time 0.

At what time does the and_tb simulation end, and when does y first become 1?

Four waits of 10 → it ends at t = 40. y becomes 1 at t = 30, when a = 1 and b = 1 are set.

Put in order: gtkwave, write testbench, vvp, write design, iverilog.

Write design → write testbench → iverilog (compile) → vvp (run, makes the .vcd) → gtkwave (view).
