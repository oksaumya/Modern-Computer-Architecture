Logic minimization & K-maps

A truth table tells you what a circuit must do. Minimization finds the smallest circuit that does it. A Karnaugh map (K-map) is a picture of the truth table where simplifications jump out as rectangles.

Think of it like this: "Open on Monday, Tuesday, Wednesday, Thursday, Friday" is five rules. "Open on weekdays" is one rule that means the same thing. A K-map helps you spot the "weekdays": groups of 1s that share a pattern, so one short term replaces many long ones.

Key terms

Literal
A variable or its complement: A, A', B, …
Product term
Literals ANDed together, e.g. AB'C.
Sum term
Literals ORed together, e.g. (A + B' + C).
Minterm (m)
A product term that is 1 on exactly one row of the truth table. Uses every variable.
Maxterm (M)
A sum term that is 0 on exactly one row. Uses every variable.
SOP
Sum of Products: products ORed together, e.g. AB + C.
POS
Product of Sums: sums ANDed together, e.g. (A+B)(A'+C).
Gray code
A counting order where neighbours differ in only one bit: 00, 01, 11, 10.
Prime implicant (PI)
A group of 1s on the K-map that can't be made any bigger.
Essential PI (EPI)
A PI that covers some 1 that no other PI covers. It must be in the answer.
Don't-care (X)
An output we don't care about, usually because that input can never happen.
Universal gate
NAND or NOR: either one alone can build any circuit.

1. Why minimize?

The lecture's headline: "16 → 2". A 4-variable function can shrink from 16 gates to 2. Fewer gates means less area (chip space), less power, more speed (fewer gates for a signal to pass through) and lower cost. It matters at scale: Apple's M3 has about 98 billion transistors on a 3 nm process.

Where minimization fits in making a chip (the VLSI design flow; VLSI = Very Large Scale Integration):

2. SOP and POS: reading an equation off a truth table

SOP (use the 1 rows)

For each row where F = 1, write a minterm: a 1 becomes X, a 0 becomes X'. AND the letters. Then OR all the minterms.

Row 5: A=1, B=0, C=1 → m5 = A·B'·C

POS (use the 0 rows)

For each row where F = 0, write a maxterm: a 1 becomes X', a 0 becomes X. OR the letters. Then AND all the maxterms.

Row 2: A=0, B=1, C=0 → M2 = (A + B' + C)

THE trap: the rules are opposite

SOP: 0 → complemented. POS: 1 → complemented. Why? A maxterm must be 0 on its row, and an OR is 0 only when every letter is 0. So on a row where A = 1, you need A' (which is 0).

Example: F is 1 on rows 1, 3, 5, 7. The row number is just the binary value of ABC written in decimal (101 = 5).

Both are correct, but long. Notice that F = 1 exactly when C = 1. A K-map will show that F = C in seconds (see below).

3. Karnaugh maps (K-maps)

A K-map lays the truth table out as a grid. Rows and columns are labelled in Gray code (00, 01, 11, 10), not binary order. So any two touching cells differ in exactly one variable, and that variable cancels when you group them: AB + AB' = A.

Grouping rules
  • Groups are rectangles of 1, 2, 4, 8 or 16 cells. Never 3, 5 or 6.
  • No diagonal groups.
  • Make each group as big as possible, and use as few groups as possible.
  • Groups may overlap. Every 1 must be in at least one group.
  • The map wraps around: the left edge touches the right edge, and the top touches the bottom.
  • A group of 2 removes 1 variable, 4 removes 2, 8 removes 3. Keep only the variables that stay the same across the whole group.

Slide correction

The class answer is F = A'B + BD + A'D'. It gives the right output, but it is not minimal. The row-01 group A'B only covers cells that BD and A'D' already cover, so drop it: F = BD + A'D'. Check: row 01 gives D + D' = 1 ✓, row 00 gives D' ✓, row 11 gives D ✓, row 10 gives 0 ✓.

Prime implicants and essential prime implicants

In the map above, the groups that can't grow any bigger (the PIs) are A'B, BD and A'D'.

  1. Find the EPIs. Cell 0000 (m0) is only inside A'D', so A'D' is essential. Cell 1101 (m13) is only inside BD, so BD is essential.
  2. Take all EPIs. A'D' + BD already cover all eight 1s.
  3. Add the fewest other PIs for any 1s left over. Here none are left, so A'B is not needed.
  4. Minimal cover: F = BD + A'D'. In general: all EPIs + the fewest extra PIs.

Wrap-around: "THINK: DONUT"

Roll the map into a tube and then into a donut: the top row touches the bottom row, and the left column touches the right column. So the four corners are neighbours.

Don't-cares (X)

Sometimes an input can never happen. Example: a BCD digit (0–9 stored in 4 bits) never uses the codes 10–15. We mark those outputs X and treat each X as 0 or 1, "whichever makes your groups BIGGER". You never have to cover an X.

Read the map. Columns CD = 00 and CD = 01 are 1 in every row. That's F = Σm(0,1,4,5,8,9,12,13): eight minterms.

The slide says F = B'. That is wrong: B = 1 in rows 01 and 11, and those rows are also 1. The column heading that stays fixed is C = 0, so the correct answer is F = C'.

4. Bubble pushing (De Morgan on diagrams)

A bubble means NOT. De Morgan says you can move bubbles from a gate's output to its inputs if you also swap the shape (AND ↔ OR):

NAND = (AB)' = A' + B' = OR with bubbles on both inputsand NOR = (A+B)' = A'·B' = AND with bubbles on both inputs. Diagrams are on Boolean algebra & gates.

Worked example: push the bar all the way in

  1. Start: ~(A·B + C). The bar covers an OR of two parts.
  2. Break the outer bar, flip + to ·: ~(A·B) · ~C
  3. Don't stop! ~(A·B) still has a bar over a group. Break it, flip · to +: ~A + ~B
  4. Result: (~A + ~B) · ~C. Now every bar sits on a single letter.

5. NAND and NOR are universal

With only NAND gates (or only NOR gates) you can build NOT, AND and OR, and so any circuit. The key trick: tie both inputs together and a NAND or NOR becomes a NOT gate.

GateNAND onlyNOR only
NOT ANAND(A, A)NOR(A, A)
A AND BNAND(NAND(A,B), NAND(A,B))NOR(NOR(A,A), NOR(B,B))
A OR BNAND(NAND(A,A), NAND(B,B))NOR(NOR(A,B), NOR(A,B))
Why chips love NAND

In CMOS (the transistor technology in almost every chip), a NAND needs only 4 transistors, but an AND needs 6 (a NAND plus a 2-transistor NOT). So NAND is the cheaper building block. NAND and NOR flash memory are named after these gates. Universal does not mean "more powerful": it computes nothing that AND/OR/NOT can't.

Common mistakes & exam traps

Slips that cost marks
  • Flipping the SOP/POS rule. SOP: 0 → X'. POS: 1 → X'.
  • Labelling K-map rows/columns 00, 01, 10, 11 (binary). It must be 00, 01, 11, 10 (Gray code).
  • Grouping diagonally, or making a group of 3 or 6.
  • Forgetting wrap-around, especially the four-corner group.
  • Making groups too small. Always try the biggest group first.
  • Adding groups you don't need. After taking the EPIs, check what is still uncovered.
  • Thinking every X must be covered. It doesn't; use an X only if it makes a group bigger.
  • Stopping De Morgan after one bar.
  • Calling NAND "more powerful". It is universal, which is different.

Practice

Write the minterm for A=1, B=0, C=1, D=0.

1010₂ = 10. 1 → letter, 0 → complemented letter: m10 = AB'CD'.

Write the maxterm for A=0, B=1, C=1.

011₂ = 3. For a maxterm, 0 → letter, 1 → complemented letter: M3 = (A + B' + C').

A truth table's F column (rows 0–7) is 0,1,1,0,1,0,0,1. Give Σ, Π and the canonical SOP.

1s at rows 1, 2, 4, 7 → Σm(1,2,4,7). 0s at rows 0, 3, 5, 6 → ΠM(0,3,5,6).

SOP: A'B'C + A'BC' + AB'C' + ABC. (This is A ⊕ B ⊕ C: 1 when an odd number of inputs are 1.)

Minimize F = Σm(0,2,5,7,8,10,13,15).

Corners m0, m2, m8, m10 → B'D'. Centre m5, m7, m13, m15 → BD. F = B'D' + BD.

Why are K-map columns in the order 00, 01, 11, 10?

That is Gray code: neighbours differ in only one bit, even across the wrap (10 → 00). In binary order, 01 and 10 would sit side by side but differ in two bits, so grouping them would be wrong.

Push the bubbles: simplify ~(A·B + C) until every NOT is on a single letter.

~(AB) · ~C → (~A + ~B) · ~C.

Build XOR from four 2-input NAND gates.

N = NAND(A, B) = (AB)'.
P = NAND(A, N) = (A·(AB)')' = (AB')'.
Q = NAND(B, N) = (A'B)'.
Y = NAND(P, Q) = AB' + A'B = A ⊕ B.

Why P works: A·(AB)' = A·(A' + B') = AB'.

How many NOR gates does an AND need? How many NAND gates does an OR need?

Both need 3: two to invert the inputs, and one to combine them.
