MUX, DEMUX & decoders: the CPU's switches

A multiplexer (MUX) picks one of many inputs and sends it to a single output. A demultiplexer (DEMUX) does the reverse: it sends one input to one of many outputs. A decoder turns a binary code into "switch on exactly one line". A CPU uses these three blocks everywhere to choose where data comes from and where it goes.

Think of it like this: a railway switch. Many tracks join into one (MUX), or one track splits into many (DEMUX). A lever, called the select input, decides which track is connected. A decoder is like a hotel key card system: you type a room number, and exactly one door unlocks.

Key terms

Data input
A signal we want to pass along, such as I0, I1, I2 or I3.
Select line (S)
A control input that decides which data input or output is used. n select lines can choose between 2ⁿ options.
2ⁿ:1 MUX
A MUX with 2ⁿ data inputs, n select lines and 1 output. For example, a 4:1 MUX has 4 inputs and 2 selects.
One-hot
A group of wires where exactly one wire is 1 and all the others are 0, such as 0100.
Minterm
An AND term that is 1 for exactly one row of a truth table. For example, A'·B is 1 only when A = 0 and B = 1.
Enable (EN)
An on/off input. When EN = 0, every output stays 0.
Latch
An accidental memory element. It holds its old value instead of following its inputs. In a MUX, a latch is a bug.

Why learn these blocks? The course calls them building blocks. About five core block types cover most of a CPU. Building with blocks gives you abstraction (you can ignore the gates inside), reuse, easier testing and scale.

1. The 2:1 multiplexer

It has two data inputs, A (also called I0) and B (I1), and one select line S. When S = 0, the output is A. When S = 1, the output is B.

SY
0A
1B

This is a short-form truth table. The output column names an input instead of listing 0 or 1.

Y = S'·A + S·BS' means NOT S. When S = 0, S' = 1, so the A term passes and the B term is blocked.

Parts: 1 NOT, 2 AND, 1 OR. Each AND gate acts like a gate that opens only when its select condition is true.

2. The 4:1 multiplexer

Four data inputs need two select lines, S1 and S0, because 2 bits can count 00, 01, 10, 11. Read S1 S0 as a binary number: it is the index of the input that gets through.

S1S0Y
00I0
01I1
10I2
11I3
Y = S1'S0'·I0 + S1'S0·I1
  + S1S0'·I2 + S1S0·I3Each AND term is a minterm of the selects, and it is 1 for exactly one select value.

Rule: a MUX with 2ⁿ inputs needs n select lines. For example, 8:1 needs 3 and 16:1 needs 4.

Cascading: a 4:1 MUX from three 2:1 MUXes

Picture a knockout tournament. In round one, S0 picks a winner from each pair (I0 or I1, and I2 or I3). In the final, S1 picks between the two winners.

The same idea scales up. An 8:1 MUX = two 4:1 MUXes + one 2:1 MUX. The two 4:1 MUXes share S1 S0, and the final 2:1 MUX uses S2.

The missing-default latch trap (the most common Lab 0011 bug)

Suppose you leave out the default line and list only three cases:

always @(*) begin
  case ({s1, s0})
    2'b00: y = i0;
    2'b01: y = i1;
    2'b10: y = i2;
    // no line for 11, and no default!
  endcase
end

When the selects are 11, nothing tells y what to be, so Verilog makes y keep its old value. Keeping a value needs memory, so the tool builds a latch instead of a MUX. Now the output depends on the past, which is a real hardware bug. Fix: always include default, or set y to a value before the case, as the DEMUX code below does.

3. MUX as a "universal function" block

A 2ⁿ:1 MUX can build any function of n variables. Connect the variables to the select lines, then wire each data input to the value you want in that row of the truth table. The MUX simply looks up the answer. This is exactly how an FPGA LUT (look-up table) works. An FPGA is a chip you can rewire with code.

Example 1: XOR with a 4:1 MUX

A (S1)B (S0)A⊕Bwire to
000I0 = 0
011I1 = 1
101I2 = 1
110I3 = 0

Put S1 = A, S0 = B, and wire the inputs to the constants I0..I3 = 0, 1, 1, 0. That is the XOR column copied straight in.

No gates needed, just the MUX and some wires tied to 0 or 1.

Example 2 (exit ticket): F(A,B,C) = Σm(1,3,5,6) with a 4:1 MUX

Σm(1,3,5,6) means "F is 1 on rows 1, 3, 5 and 6" (see minterms). There are three variables but only two selects. The trick: use A and B as selects, then describe F in each pair of rows using the leftover variable C.

  1. AB = 00 covers rows 0 and 1 (C = 0, 1). F = 0, 1. F equals C, so I0 = C.
  2. AB = 01 covers rows 2 and 3. F = 0, 1. Again F = C, so I1 = C.
  3. AB = 10 covers rows 4 and 5. F = 0, 1, so I2 = C.
  4. AB = 11 covers rows 6 and 7. F = 1, 0. F is the opposite of C, so I3 = C'.
S1 = A, S0 = B · I0 = C, I1 = C, I2 = C, I3 = C'Each data input is one of four things: 0, 1, C or C'. Look at the pair of rows and decide which one.

4. The demultiplexer (DEMUX)

A DEMUX is "a MUX run backwards". It has one data input D and n select lines, and it sends D to one of 2ⁿ outputs. Every output that is not selected is 0. The course calls them "1:2" and "1:4" DEMUXes.

A B (select)Y0Y1Y2Y3
00D000
010D00
1000D0
11000D
Y0 = A'B'·D   Y1 = A'B·D   Y2 = AB'·D   Y3 = AB·DEach output is D ANDed with one minterm of the selects.

Where DEMUXes are used: writing data into one chosen register, network switches (sending a packet out of one port), and chip selects (waking up one memory chip).

verilog · demux1_2.vcode → what it means
module demux1_2 (A 1-to-2 DEMUX.
input wire i, sel,One data input i and one select line.
output wire y0, y1Two outputs.
);
assign y0 = ~sel & i;~ is NOT. y0 = S'·I, so y0 copies i only when sel = 0.
assign y1 = sel & i;y1 = S·I, so y1 copies i only when sel = 1.
endmodule
verilog · demux1_4.vcode → what it means
module demux1_4 (A 1-to-4 DEMUX.
input wire d,The data bit to route.
input wire [1:0] sel,A 2-bit select bus: sel[1] and sel[0].
output reg [3:0] yA 4-bit output bus. It is reg because it is set inside always.
);
always @(*) beginCombinational logic: re-check whenever an input changes.
y = 4'b0000; // clear all outputs firstStart with every output at 0. This guarantees unselected outputs are 0 and prevents a latch.
case (sel)Compare sel with each option.
2'b00: y[0] = d;For select 00, only output bit 0 gets d.
2'b01: y[1] = d;For 01, only bit 1 gets d.
2'b10: y[2] = d;For 10, only bit 2 gets d.
default: y[3] = d;Otherwise (11), bit 3 gets d.
endcase
end
endmodule
Why can the later line "win"?

Inside an always block, if a signal is set twice, the last setting is the one that counts. So y = 0000 sets a safe starting value, and the case then changes just one bit.

5. Decoders

An n-to-2ⁿ decoder takes an n-bit code and switches on exactly one of its 2ⁿ outputs. The outputs are one-hot, and each output is one minterm of the inputs.

A1 A0D0D1D2D3
001000
010100
100010
110001

Key link: "A decoder is a DEMUX whose data input is a constant 1." Look at the DEMUX table and replace D with 1. You get this table.

Cost: a 3-to-8 decoder needs 8 AND gates (one per minterm) and 3 NOT gates. Outputs double with every extra input bit, so the cost grows exponentially.

Any function = decoder + OR gate

Each decoder output is one minterm, so just OR together the outputs for the rows where F = 1. For the exit-ticket function, F = Σm(1,3,5,6) = D1 + D3 + D5 + D6, using a 3-to-8 decoder and one 4-input OR gate.

The lab does not include decoder code. Here is a short 2-to-4 decoder with enable, written in the same style, so you can see the minterms in Verilog:

In shortmany → oneone → manycode → one-hot
Typical useChoosing an ALU operand or the next PCWriting to one registerMemory address decoding, choosing a register
Quick check

"Select one of 8 sensor readings" needs an 8:1 MUX (with 3 select lines), not a decoder. You are picking one value from many, which is a MUX's job. A decoder only produces one-hot lines; it does not carry data.

The ALU (arithmetic logic unit) is the CPU's calculator. The PC (program counter) holds the address of the next instruction. The select signals (PCSrc, ALUSrc) come from the CPU's control unit.

Common mistakes & exam traps

Slips that cost marks
  • Mixing up MUX and DEMUX (many → one vs one → many), or DEMUX and decoder (a decoder has no data input; its "data" is a constant 1).
  • Wrong number of select lines. 2ⁿ inputs need n selects, so an 8:1 MUX needs 3, not 8 and not 4.
  • Missing default in a case creates a latch instead of a MUX. This is the most common bug.
  • y declared as a wire but assigned inside always. That is a compile error; it must be reg.
  • {s1,s0} is not {s0,s1}. The left bit is the MSB. Swapping them swaps I1 and I2.
  • In gate primitives such as and u1 (a0, a, sel_n);, the output is listed first.
  • For a 3-variable function on a 4:1 MUX, the data inputs can be 0, 1, C or C'. Don't forget the C' case.

Practice

How many select lines does a 16:1 MUX need? And a 1:8 DEMUX?

16 = 2⁴, so a 16:1 MUX needs 4. 8 = 2³, so a 1:8 DEMUX needs 3.

A 4:1 MUX has I0..I3 = 1, 0, 0, 1 and S1 S0 = 11. What is Y?

11 in binary is 3, so Y = I3 = 1.

Build a 4:1 MUX from 2:1 MUXes. How many do you need, and how are the selects wired?

Three. Two first-level MUXes pick (I0 or I1) and (I2 or I3), both controlled by S0. A third MUX, controlled by S1, picks between their outputs.

Build an 8:1 MUX from 4:1 MUXes (take-home).

Use two 4:1 MUXes: one for I0–I3 and one for I4–I7, both with selects S1 S0. Then a 2:1 MUX with select S2 picks between them. Check with select 101 (= 5): S1 S0 = 01 picks I1 and I5, then S2 = 1 picks I5 ✓.

Implement F(A,B,C) = Σm(1,3,5,6) with a 4:1 MUX, using A and B as the selects.

Look at each pair of rows: AB = 00 gives F = 0,1 (so C); 01 gives 0,1 (C); 10 gives 0,1 (C); 11 gives 1,0 (C').

I0 = C, I1 = C, I2 = C, I3 = C'.

Implement F(A,B) = A + B (OR) with a 4:1 MUX.

S1 = A, S0 = B. The OR column for rows 00, 01, 10, 11 is 0, 1, 1, 1, so I0..I3 = 0, 1, 1, 1.

How many AND gates does a 3-to-8 decoder need? Why?

8, one for each minterm (each output). It also needs 3 NOT gates to make A', B' and C'.

A 1:4 DEMUX has D = 1 and select AB = 01. What are Y0..Y3? And if D = 0?

With D = 1: Y0..Y3 = 0, 1, 0, 0. With D = 0, all outputs are 0, because the selected output copies D and the others are always 0.
