Adders: half, full, ripple-carry & look-ahead

An adder is a small circuit that adds binary numbers. Every CPU is full of them. They add numbers, subtract (by adding a negative number), and move the program counter forward (PC ← PC + 4).

Think of it like this: adding by hand, column by column. You add one column, write the digit, and carry the extra 1 to the next column. A half adder does one column with no carry coming in. A full adder does one column that also has a carry coming in. Chain full adders together and you can add numbers of any size.

Key terms

Sum (S)
The digit you write down for this column.
Carry out (Cout)
The extra 1 sent to the next column when the column total is 2 or more.
Carry in (Cin)
The carry arriving from the column on the right.
LSB / MSB
Least significant bit is the rightmost bit, a[0]. Most significant bit is the leftmost bit.
Gate delay
The tiny time a gate takes to update its output. More gates in a row means a longer wait.
Ripple
A carry travelling bit by bit from right to left, one full adder after another.

Binary addition has only four facts to remember:

0 + 00 + 11 + 11 + 1 + 1
0110 (write 0, carry 1)11 (write 1, carry 1)

1. Half adder: adds two bits

It has two inputs (A, B) and two outputs (Sum, Carry). Look at the truth table. Sum is 1 when the inputs are different, which is exactly what XOR does. Carry is 1 only when both inputs are 1, which is exactly what AND does.

ABSumCarry
0000
0110
1010
1101
Sum = A ⊕ B⊕ means XOR
Carry = A · B· means AND

Why "half"?

It has no carry-in input, so it can't accept the carry from the column on its right. That means it can only add the rightmost column.

2. Full adder: adds three bits

Adding 11 + 01 shows the problem. Column 1 has to add A[1], B[1] and the carry from column 0. That's three inputs, so we need a full adder.

00110

01101
10010
10101
11001
11111
Sum = A ⊕ B ⊕ Cin1 when an odd number of inputs are 1 ("parity")
Cout = A·B + Cin·(A ⊕ B)1 when two or more inputs are 1 ("majority"). + means OR.

Quick read of the table: count the 1s in the row. 0 ones gives 00, 1 one gives 01, 2 ones gives 10, 3 ones gives 11 (written as Cout Sum).

Build it from two half adders + one OR gate

Why is a plain OR safe here?

c1 and c2 can never both be 1. If A = B = 1, then c1 = 1, but s1 = 0, so c2 = s1·Cin = 0. Only one carry can happen at a time, so OR gives the right answer. XOR would work too.

3. 4-bit ripple-carry adder

Put four full adders in a row. Each carry-out plugs into the next adder's carry-in. Bit 0 (the rightmost adder) gets cin, which is usually 0.

verilog · adder4.vcode → what it means
module adder4 (
input wire [3:0] a, b,[3:0] makes a 4-wire bus: a[3], a[2], a[1], a[0]. Always written as [MSB:LSB].
input wire cin,A single carry-in wire.
output wire [3:0] sum,A 4-bit answer.
output wire coutThe carry out of the last adder.
);
wire c1, c2, c3;The carries between the adders.
full_adder fa0(.a(a[0]),.b(b[0]),.cin(cin),Bit 0 (LSB) takes the outside carry-in.
.sum(sum[0]),.cout(c1));Its carry-out goes to c1.
full_adder fa1(.a(a[1]),.b(b[1]),.cin(c1),Bit 1 takes c1 as its carry-in.
.sum(sum[1]),.cout(c2));
full_adder fa2(.a(a[2]),.b(b[2]),.cin(c2),Same pattern for bit 2.
.sum(sum[2]),.cout(c3));
full_adder fa3(.a(a[3]),.b(b[3]),.cin(c3),Bit 3 (MSB).
.sum(sum[3]),.cout(cout));The last carry leaves the block as cout.

Worked example: 0111 + 0001 (7 + 1)

Bit 0: 1 + 1 + cin 0 = 2 = 10. Write sum0 = 0 and carry c1 = 1.

Bit 1: 1 + 0 + c1 1 = 2 = 10. Write sum1 = 0 and carry c2 = 1. The carry is rippling.

Bit 2: 1 + 0 + c2 1 = 2 = 10. Write sum2 = 0 and carry c3 = 1.

Bit 3: 0 + 0 + c3 1 = 1 = 01. Write sum3 = 1 and carry cout = 0.

Answer: sum = 1000 (8), cout = 0. The carry travelled through bits 0, 1 and 2 before bit 3 could settle.

The problem: ripple is slow

Each full adder takes about 2 gate delays to produce its carry, and every bit has to wait for the bit on its right. So total delay grows in step with the number of bits:

Ripple delay ≈ 2 × n gate delays4-bit gives 8 delays · 16-bit gives 32 · 32-bit gives 64 · 64-bit gives 128

4. Carry look-ahead adder (CLA)

The fix: don't wait for the carry. Predict it. For every bit, ask two quick questions. Both can be answered right away, because they only use that bit's own A and B.

G = A · B  (Generate)
"This bit makes a carry on its own." Both inputs are 1, so a carry comes out no matter what came in.
P = A ⊕ B  (Propagate)
"This bit passes along any carry it receives." Exactly one input is 1, so a carry coming in goes straight out.
c(i+1) = G(i) + P(i) · c(i)A carry comes out if this bit generates one, OR if it propagates the incoming one.

Now substitute each equation into the next. Every carry becomes a formula in the G's, P's and the first carry-in (c0) only. No carry has to wait for another:

c1 = G0 + P0·c0
c2 = G1 + P1·G0 + P1·P0·c0
c3 = G2 + P2·G1 + P2·P1·G0 + P2·P1·P0·c0
c4 = G3 + P3·G2 + P3·P2·G1 + P3·P2·P1·G0 + P3·P2·P1·P0·c0
sum(i) = P(i) ⊕ c(i)

Ripple vs look-ahead: when does each carry arrive?

Ripple-carryCarry look-ahead
SpeedSlow: delay grows with the number of bitsFast: all carries are computed at once
HardwareSmall and simpleMore gates, and very wide gates for large n
Used inTiny or low-speed designsReal CPUs (usually as grouped or hybrid designs such as Kogge-Stone or Brent-Kung)

module cla4 (A 4-bit carry look-ahead adder.
input wire [3:0] a, b,
input wire cin,
output wire [3:0] sum,
output wire cout
);
wire [3:0] g = a & b;Generate for all 4 bits at once. Bitwise AND works on each pair of bits.
wire [3:0] p = a ^ b;Propagate for all 4 bits (bitwise XOR).
wire c1, c2, c3, c4;
assign c1 = g[0] | (p[0] & cin);c1 = G0 + P0·c0
assign c2 = g[1] | (p[1] & g[0])c2 is written out in full, so it does not wait for c1.
| (p[1] & p[0] & cin);
assign c3 = g[2] | (p[2] & g[1])The same idea, one level deeper.
| (p[2] & p[1] & g[0])
| (p[2] & p[1] & p[0] & cin);
assign c4 = g[3] | (p[3] & g[2])The final carry out.
| (p[3] & p[2] & g[1])
| (p[3] & p[2] & p[1] & g[0])
| (p[3] & p[2] & p[1] & p[0] & cin);
assign sum = p ^ {c3, c2, c1, cin};{ } joins wires into a bus. Each sum bit = P(i) XOR the carry into that bit.
assign cout = c4;
endmodule

Common mistakes & exam traps

Slips that cost marks
  • cout is always 0? You probably wrote c1 & c2 instead of c1 | c2.
  • Sum bits in reverse order? a[0] is the LSB (rightmost bit).
  • Last sum bit shows X (unknown)? fa3's cin is not wired up.
  • Everything happens at time 0 in the waveform? Your testbench has no #10 delays between test cases.
  • iverilog says "unknown module"? Pass all the .v files on the command line.
  • Don't call a ripple adder "fast". Delay grows with every bit you add.
  • You can't chain half adders, because they have no carry-in.

Practice

A = 1, B = 1, Cin = 1. What are Sum and Cout?

There are three 1s. 3 = 11, so Sum = 1, Cout = 1.

How many gate delays does a 16-bit ripple adder take (about 2 per stage)?

2 × 16 = 32 gate delays.

For one bit with A = 1, B = 0, what are G and P? What does that mean?

G = 1·0 = 0 and P = 1⊕0 = 1. This bit won't create a carry by itself, but it will pass along any carry that comes in.

Use CLA equations: a = 1011, b = 0110, cin = 0. Find g, p, the carries, sum and cout.

g = a & b = 0010, p = a ^ b = 1101

c1 = g0 + p0·c0 = 0 + 1·0 = 0
c2 = g1 + p1·c1 = 1 + 0 = 1
c3 = g2 + p2·c2 = 0 + 1·1 = 1
c4 = g3 + p3·c3 = 0 + 1·1 = 1

sum = p ⊕ {c3,c2,c1,c0} = 1101 ⊕ 1100 = 0001, cout = 1.
Check: 11 + 6 = 17 = 1 0001 ✓

Why is it safe to use OR (not XOR) to combine the two carries in a full adder?

The two half-adder carries can never be 1 together. If A = B = 1, the first sum s1 is 0, so the second carry (s1·Cin) is 0.

Why does subtraction need an adder?

A − B = A + (~B) + 1. Flip B's bits, set the carry-in to 1, and add. The same adder does both jobs. See the adder-subtractor.
