Adder-subtractor & overflow detection

Overflow means the true answer does not fit in the available bits, so the stored result is wrong. The hardware gives no error: overflow is silent. It only raises two flags. CF (carry flag) warns about unsigned overflow, and OF (overflow flag) warns about signed overflow. One adder, with a few XOR gates added, can both add and subtract.

Think of it like this: a 4-digit odometer that reads 9999 rolls over to 0000 after one more kilometre. The car doesn't stop or beep. You only know something happened if you watch for the roll-over. The flags are the CPU's way of watching.

Key terms

Overflow
The correct result is outside the range the bits can hold. 4-bit unsigned holds 0 … 15, and 4-bit signed holds −8 … +7.
CF (carry flag)
CF = the carry out of the MSB (C4 in a 4-bit adder). It signals unsigned overflow.
OF (overflow flag)
OF = C3 ⊕ C4. It signals signed overflow.
C3 and C4
C3 is the carry into the MSB (bit 3). C4 is the carry out of the MSB.
Flag
A single status bit the CPU sets after an operation. Later instructions can check it. On x86 processors these flags are named OF and CF.
K (mode bit)
The control input of the adder-subtractor: 0 means add, 1 means subtract. The lab code calls it m.

1. What overflow looks like

Add +5 and +4 in 4-bit signed numbers:

0101 + 0100 = 1001The true answer is +9, but 4-bit signed only goes up to +7. The pattern 1001 reads as −8 + 1 = −7. Two positives gave a negative!

The adder did its job perfectly. The bits are right; the meaning is wrong. The result has wrapped around the number wheel. Nothing crashes, which is why overflow is so dangerous.

2. Signed vs unsigned: same bits, two flags

The adder does not know whether you meant signed or unsigned. "The ALU doesn't know if YOU meant signed or unsigned. It computes both flags." Your program then checks the flag that matches your meaning. (The ALU, or arithmetic logic unit, is the CPU's calculator.)

Unsigned (0 … 15)

CF = C4 (carry out)A carry out of 1 means the answer needed a 5th bit.

0001+0001 = 0010, CF = 0
1111+0001 = 0000, CF = 1
1000+1000 = 0000, CF = 1

Signed (−8 … +7)

OF = C3 ⊕ C4Here the carry out on its own "is meaningless".

Example: 1111+0001 (−1 + 1 = 0) has C4 = 1, but the signed answer 0 is correct, so OF = 0.

3. The signed-overflow rule: OF = C3 ⊕ C4

OF = Cin(MSB) ⊕ Cout(MSB) = C3 ⊕ C4Signed overflow happens exactly when the carry into the sign bit is different from the carry out of it.

Why it works: look only at the MSB column

Bit 3 adds A3 + B3 + C3. List every case:

A3B3C3 inResult sign S3C4 outOFWhat happened
000000(+) + (+) = (+), fine
001101(+) + (+) = (−), overflow
110011(−) + (−) = (+), overflow
111110(−) + (−) = (−), fine
0 / 11 / 00100Mixed signs: never overflows
0 / 11 / 01010Mixed signs: never overflows

OF is 1 in exactly the rows where C3 and C4 differ. That is the definition of XOR.

The intuitive sign rule (check by eye)

  1. (+) + (+) → (−)Overflow
  2. (−) + (−) → (+)Overflow
  3. (+) + (−)Never overflows
OF = A3·B3·S3' + A3'·B3'·S3The same rule written with the sign bits: both inputs share a sign, and the result's sign is different. (S3 is the result's MSB.)
Why can't mixed signs overflow?

Adding a positive to a negative gives an answer between the two inputs. Both inputs already fit, so the answer fits too.

Bit 0: 1 + 1 + 0 = 10. Sum bit 0, carry c1 = 1.

Bit 1: 1 + 0 + 1 = 10. Sum bit 0, carry c2 = 1.

5. The 4-bit adder-subtractor

Subtraction is addition of a negative: A − B = A + (~B) + 1 (see two's complement). So we need two things: a way to invert B when we want to subtract, and a way to add the extra 1. Both come from one control bit, K.

The XOR trick

XOR with 0 leaves a bit unchanged (b ⊕ 0 = b). XOR with 1 flips it (b ⊕ 1 = b'). So an XOR gate is a controllable inverter.

K = 0: add

Each XOR passes b unchanged, and cin = 0.
Result = A + B.

K = 1: subtract

Each XOR inverts b, and cin = 1.
Result = A + ~B + 1 = A − B.

The lab Verilog, line by line

module adder_subtractor(A chip named adder_subtractor.

assign {cout, s} = a + b_in + m;Add a, the modified b, and m (m acts as the carry-in). {cout, s} glues cout in front of s to make a 5-bit result, so the 5th bit of the sum lands in cout.
endmodule

Worked examples with the adder-subtractor

  1. 5 − 3 (K = 1): b = 0011 becomes b_in = 1100, and cin = 1. 0101 + 1100 + 1 = 1 0010, so s = 0010 = 2 and cout = 1.
  2. 3 − 5 (K = 1): b = 0101 becomes 1010. 0011 + 1010 + 1 = 0 1110, so s = 1110 = −2 and cout = 0.
  3. 7 − (−8) (K = 1), a subtraction that overflows: b = 1000 becomes 0111. 0111 + 0111 + 1 = 0 1111, so s = 1111 = −1. The true answer is +15. The carries are c3 = 1 and c4 = 0, so OF = 1 ✓.
Carry-out when subtracting

With K = 1, cout = 1 means "no borrow was needed" (unsigned A ≥ B), and cout = 0 means A < B. That's why 5 − 3 gave cout = 1 and 3 − 5 gave cout = 0. Don't read cout = 1 as an error here.

6. CLA adder with overflow flags (Lab 1B)

This is the carry look-ahead adder with two flag outputs added. Here is the full body. G (generate) = a·b means "this bit makes a carry". P (propagate) = a⊕b means "this bit passes a carry along".

verilog · cla_adder_4bit_ovf.vcode → what it means
module cla_adder_4bit_ovf (A 4-bit CLA adder with overflow flags.
input wire [3:0] a, b,Two 4-bit inputs.
input wire cin,The carry-in (0 for plain addition).
output wire [3:0] sum,The 4-bit result.
output wire cout, cf, ofThree 1-bit outputs: carry out, carry flag and overflow flag.
);
wire [3:0] g = a & b;Generate for all 4 bits (bitwise AND).
wire [3:0] p = a ^ b;Propagate for all 4 bits (bitwise XOR).
wire c1, c2, c3, c4;The internal carries. c3 goes into bit 3, and c4 comes out of bit 3.
assign c1 = g[0] | (p[0] & cin);c1 = G0 + P0·c0
assign c2 = g[1] | (p[1] & g[0])c2 written out in full, so it does not wait for c1.
| (p[1] & p[0] & cin);
assign c3 = g[2] | (p[2] & g[1])c3: a carry is made at bit 2, or made lower down and passed up.
| (p[2] & p[1] & g[0])
| (p[2] & p[1] & p[0] & cin);
assign c4 = g[3] | (p[3] & g[2])c4: the carry out of the MSB.
| (p[3] & p[2] & g[1])
| (p[3] & p[2] & p[1] & g[0])
| (p[3] & p[2] & p[1] & p[0] & cin);
assign sum = p ^ {c3, c2, c1, cin};Each sum bit = P(i) XOR the carry into that bit. { } joins the carries into a 4-bit bus.
assign cf = c4; // unsigned overflowCarry flag = the carry out.
assign of = c3 ^ c4; // signed overflowOverflow flag = carry into the MSB XOR carry out of it.
assign cout = c4;The plain carry-out pin (the same signal as cf).
endmodule

7. Real-world overflow failures

EventWhat overflowedResult
Ariane 5 rocket (1996)A 64-bit floating-point value was converted into a 16-bit signed integer, and it was too big to fit.The rocket self-destructed about 37 s after launch, a loss of about $370M.
"Gangnam Style" on YouTube (2014)The view counter was a 32-bit signed integer, with a maximum of about 2.1 billion.The video approached the limit, and YouTube moved the counter to 64 bits.

Common mistakes & exam traps

Slips that cost marks
  • Mixing up the flags. The carry out (CF) flags unsigned overflow. A carry mismatch at the sign bit (OF = C3 ⊕ C4) flags signed overflow.
  • "Carry out = 1, so the signed answer is wrong." Not true: −1 + 1 = 0 has C4 = 1 but is correct. For signed numbers, the carry out alone means nothing.
  • Using C4 ⊕ S3 or A3 ⊕ B3. The rule uses the carry into the MSB (C3) and the carry out (C4).
  • Saying a positive plus a negative can overflow. It never can.
  • Forgetting that K also feeds cin. Inverting B alone gives A + ~B = A − B − 1, which is off by one.
  • Expecting an error message. Overflow is silent. Only the flags change.
  • In {cout, s} = …, swapping the order. The left item gets the top (5th) bit.

Practice

4-bit: 0110 + 0011. Give the result, CF and OF.

6 + 3 = 9. Result 1001. Carries: c1 = 0, c2 = 1, c3 = 1, c4 = 0.

CF = 0 (9 fits in unsigned). OF = 1 ⊕ 0 = 1 (signed: +6 + +3 gave −7).

4-bit: 1010 + 1011 (−6 + −5). Give the result, CF and OF.

1010 + 1011 = 1 0101, so the result is 0101 = +5. Carries: c3 = 0, c4 = 1.

CF = 1, OF = 1. Two negatives gave a positive; the true answer −11 is below −8.

4-bit: 1100 + 0111 (−4 + 7). Is there overflow?

1100 + 0111 = 1 0011, so the result is 0011 = +3 ✓. Carries: c3 = 1, c4 = 1, so OF = 0. CF = 1, but that only matters for unsigned (12 + 7 = 19 > 15). The signs differ, so signed overflow is impossible anyway.

Using the adder-subtractor, compute 6 − 2. Show b_in, cin and the result.

K = 1, so b_in = 0010 ⊕ 1111 = 1101 and cin = 1.

0110 + 1101 + 1 = 1 0100, so s = 0100 = 4 and cout = 1 (no borrow).

Compute −8 − 1 on the adder-subtractor. What does OF show?

a = 1000, b = 0001 becomes b_in = 1110, and cin = 1. 1000 + 1110 + 1 = 1 0111, so s = 0111 = +7.

Bit trace: bit 0: 0 + 0 + 1 = 1 (c1 = 0). Bit 1: 0 + 1 + 0 = 1 (c2 = 0). Bit 2: 0 + 1 + 0 = 1 (c3 = 0). Bit 3: 1 + 1 + 0 = 10 (c4 = 1).

So OF = 0 ⊕ 1 = 1. The true answer −9 is below −8, so this is overflow ✓.

Why does XOR work as a "controllable inverter"?

b ⊕ 0 = b (it passes through) and b ⊕ 1 = b' (it flips). The control input K chooses which one happens.

An 8-bit signed counter holds 127 and adds 1. What does it hold, and which flag is set?

01111111 + 1 = 10000000 = −128. The carry into the MSB is 1 and the carry out is 0, so OF = 1 and CF = 0.
