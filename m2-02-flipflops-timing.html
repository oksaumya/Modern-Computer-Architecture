Flip-flops & timing: storing a bit at exactly the right moment

A flip-flop stores one bit, like a latch, but it only looks at its input at one instant: the clock edge. Between edges it ignores its input completely. That makes every register in a CPU update together, in step with the clock.

Think of it like this: a photo camera. A latch is a live video feed: whatever moves in front of it shows up. A flip-flop is a photo: it captures one instant when the shutter clicks (the clock edge) and shows that picture until the next click. The subject must hold still just before and just after the click, or the photo blurs.

Key terms

Clock (CLK)
A signal that goes 0, 1, 0, 1 forever at a fixed rate. It tells every flip-flop when to act.
Period (T) & frequency (f)
T is the time for one full 0-1 cycle. f = 1/T is how many cycles per second (Hz).
Rising edge
The instant the clock goes from 0 to 1. An edge is a moment, not a duration.
Level-triggered
Active for the whole time a signal is at a level (latches).
Edge-triggered
Acts only at the edge (flip-flops). Drawn with a small triangle ▷ on the clock pin.
Q⁺ (next state)
The value Q will have just after the next clock edge.
Setup / hold time
How long D must stay steady before / after the edge.
Metastability
An in-between, undecided output caused by D changing too close to the edge.

1. The clock

The clock is the drummer the whole orchestra follows. Flip-flops sample their inputs on each rising edge.

f = 1 / TA 3 GHz CPU: T = 1 / 3,000,000,000 s ≈ 0.33 ns, so 3 billion edges every second. A 3.5 GHz clock: T ≈ 0.29 ns. (1 ns = one billionth of a second.)

2. Level vs edge triggering

Level-triggered (latch)

Active the whole time the clock/enable is high. Transparent. Fewer gates. Risky: data can slip through while it is open.

Edge-triggered (flip-flop)

Samples at one instant (0→1). More gates (about 2× a latch). The safe choice for registers and pipelines.

Rule of thumb

If a clock edge triggers it, it's a flip-flop. If a level does, it's a latch.

3. The D flip-flop

On each rising edge, Q takes the value D has at that moment, then holds it until the next rising edge. Glitches on D between edges are ignored.

Q⁺ = D (at the rising edge)

How it's built: master-slave

Put two D latches in a row. The first (master) is open while CLK = 0. The second (slave) is open while CLK = 1. They are never open at the same time, like a two-door airlock for one bit. At the rising edge the master closes (freezing D) and the slave opens (showing that frozen value). So Q changes only at the edge.

Two things to notice in this testbench
  • A simulation race at t = 5. d changes to 1 at exactly the moment clk rises. The simulator may store the old 0 or the new 1, so q after the first edge is not guaranteed. In real hardware this is a setup violation. Safer: change d only when the clock is low (e.g. at t = 2 or 7, not 5).
  • No reset. q is X (unknown) until the first edge. Real designs add a reset, shown below.
verilog · d_ff with resetcode → what it means

  • JK fixes SR's forbidden row: J = K = 1 now means "toggle".
  • T flip-flop: tie J and K together, or use a D flip-flop with D = T ⊕ Q (an XOR in front).
  • Modern chips and every FPGA use D flip-flops almost exclusively. You may reason in T; the synthesis tool builds it from a D and an XOR.

Divide-by-2

A T flip-flop with T = 1 flips on every rising edge, so its output completes one cycle every two clock cycles. That halves the frequency. Chain n of them and you divide by 2ⁿ. Counting and dividing are the same operation (see Counters).

f_out = f_in / 2ⁿA watch crystal at 32,768 Hz = 2¹⁵ Hz. After 15 stages: 32,768 / 32,768 = 1 Hz, one tick per second.

The synchronous version is the one shown earlier: only posedge clk in the list, with if (rst) inside.

Why reset at all?

A flip-flop powers up holding a random value. Without a reset, "a counter might start at 173". It may look fine in simulation (which shows X) and then hang on real hardware.

6. Timing: setup, hold and clock-to-Q

t_setup
How long D must be stable before the edge.
t_hold
How long D must stay stable after the edge.
t_cq (clock-to-Q)
Delay from the edge until Q shows the new value.
  • Setup violation: D changes too late (inside the green part).
  • Hold violation: D changes too soon after the edge (inside the copper part).

Metastability

Either violation can leave the flip-flop metastable: its output hovers between 0 and 1 for an unpredictable time before falling to one side.

  • Most common when an input comes from an unrelated clock: a button press, another chip.
  • It cannot be eliminated, because such an input can always change near an edge.
  • It can be made extremely rare with a synchronizer: 2–3 flip-flops in a row. Each gives the signal one more clock cycle to settle. Designers aim for an MTBF (mean time between failures) of thousands of years.
  • It is a physical fact, not a "bug" in your code.

How fast can the clock go?

Between two flip-flops sits some combinational logic. In one clock period, the signal must leave the first flip-flop, pass through the logic, and arrive before the second flip-flop's setup window. The slowest such path is the critical path, and it sets the speed limit.

T ≥ t_cq + t_logic + t_setup   →   f_max = 1 / T_minStatic timing analysis (STA) tools such as PrimeTime check this for every path. Overclocking shrinks the margin until a path fails.

Worked examples

  1. Class homework. Path delay (t_cq + logic) = 0.28 ns, setup = 0.05 ns.
    T ≥ 0.28 + 0.05 = 0.33 ns.
    f_max = 1 / 0.33 ns = 1 / 0.33 × 10⁹ Hz ≈ 3.03 GHz.
  2. All three given. t_cq = 0.05 ns, t_logic = 0.20 ns, t_setup = 0.05 ns.
    T ≥ 0.05 + 0.20 + 0.05 = 0.30 ns, so f_max = 1 / 0.30 ns ≈ 3.33 GHz.
  3. What if you clock it at 3.5 GHz? T = 1 / 3.5 GHz ≈ 0.286 ns, which is less than 0.30 ns. The signal arrives late: a setup violation. The chip may compute wrong values.

Common mistakes & exam traps

Slips that cost marks
  • Mixing up latches (level) and flip-flops (edge).
  • Allowing S = R = 1 in an SR flip-flop.
  • Ignoring a latch's transparency window.
  • Forgetting hold time: it is measured after the edge.
  • Calling metastability a "bug". It is physics and can only be made rare.
  • Clocking with zero timing margin.
  • Declaring q as a wire. Anything set inside always must be a reg.
  • Using = instead of <= inside always @(posedge clk).
  • Forgetting begin/end when an always block has more than one line.

Practice

Latch vs flip-flop in one sentence.

A latch is level-sensitive and transparent while enabled; a flip-flop is edge-triggered and samples its input only at the clock edge.

What is metastability, and why can't it be eliminated?

An undecided output (between 0 and 1) caused by D changing inside the setup/hold window. Inputs from unrelated clocks can always change near an edge, so it can't be removed, only made rare with a 2–3 flip-flop synchronizer.

A JK flip-flop has Q = 1. J = 1, K = 1. What is Q after the edge? Check with the formula.

11 means toggle, so Q⁺ = 0. Formula: Q⁺ = JQ' + K'Q = 1·0 + 0·1 = 0 ✓

A T flip-flop starts at Q = 0 with T = 1. What is Q after 1, 2, 3 edges?

It toggles every edge: 1, 0, 1. Its output frequency is half the clock's.

t_cq = 60 ps, t_logic = 340 ps, t_setup = 100 ps. Find T_min and f_max.

T_min = 60 + 340 + 100 = 500 ps = 0.5 ns. f_max = 1 / 0.5 ns = 2 GHz.

How many T flip-flops divide 1 MHz down to about 1 Hz?

We need 2ⁿ ≈ 1,000,000. 2²⁰ = 1,048,576, so 20 stages give about 0.95 Hz.

Why is an asynchronous reset risky when it is released?

If rst goes low very close to a clock edge, the flip-flop sees a change inside its setup/hold window and can go metastable. A synchronous reset only acts on the edge, so it has no such risk.
