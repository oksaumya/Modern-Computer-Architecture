The register file: two reads, one write

A register file is a small bank of registers inside the CPU. You pick a register by its number (its address). In one clock cycle it can read two registers and write one.

Think of it like this: a row of numbered lockers. Two friends can each look into a locker at any moment, just by reading its number. But you can only put something into a locker when the bell rings (the clock edge), and only if you have the key (write enable).

Key terms

Register
A row of flip-flops that stores one binary word (for example 32 bits). See Registers.
Address
The number of a register. 32 registers need 5-bit addresses, because 2⁵ = 32.
Port
One "doorway" into the register file: an address input plus a data line. It has 2 read ports and 1 write port.
Write enable (WE / RegWrite)
A 1-bit control signal. 1 means "store the data at the next clock edge". 0 means "change nothing".
Combinational
Output follows the inputs after a tiny gate delay. No clock is needed.
Synchronous
Changes happen only at the clock edge.
One-hot
A group of wires where exactly one wire is 1. A decoder gives a one-hot output.

1. Why a CPU needs one

Modules 1–2 gave us flip-flops, registers and counters. Now look at one instruction:

add R1, R2, R3   →   R1 ← R2 + R3In the same clock cycle the CPU must READ R2 and R3, and WRITE the answer into R1.

So we need a block that holds many registers, lets us pick any two to read, and lets us pick one to write. That block is the register file. It is "a tiny, ultra-fast memory that lives inside the CPU".

  • MIPS and RISC-V: 32 registers × 32 bits each = 1,024 flip-flops.
  • 2 read ports + 1 write port per cycle. That matches an R-type instruction add rd, rs1, rs2: read rs1 and rs2, write rd.
  • Its two outputs feed the ALU (arithmetic logic unit), which you meet in Module 4.

3. The write port: decoder + AND gates

A decoder turns the write address into a one-hot signal: exactly one output wire is 1. Each output is ANDed with the global WE. The result is that register's own load enable (WE₀, WE₁, …). The drawing shows the 4-register lab version; MIPS uses a 5:32 decoder and 32 AND gates.

The one-line summary

"The decoder picks WHERE; WE picks WHETHER." Example: WADDR = 10 and WE = 1 → only WE2 = 1, so R2 stores WDATA. If WE = 0, all four enables are 0 and nothing changes.

4. The read ports: two MUXes

Every register's output goes into two multiplexers (MUXes). A MUX is a selector switch: its select input (the read address) chooses which input reaches the output. Two MUXes give two independent reads at the same time. MIPS uses two 32:1 MUXes, each 32 bits wide.

5. Reads are instant, writes wait for the clock

The class calls this "the single most important fact about a register file".

READ = combinational

  • No clock involved.
  • Change the read address → data appears after a small gate delay.
  • Both read ports work at the same time.

WRITE = synchronous

  • Address, data and WE are set up before the edge.
  • The register changes only at the rising clock edge.
  • This prevents races and half-written values.
  • The new value is readable after the edge (in the next cycle).
Why this matters

In one cycle of add R1, R1, R2, the CPU reads the old R1 all cycle long, the adder computes old R1 + R2, and the answer is stored at the end-of-cycle edge. Reading and writing the same register in one cycle is safe.

6. The zero register ($zero / x0)

In MIPS, register 0 is called $zero. In RISC-V it is x0 (registers are x0–x31). It is hardwired to 0:

  • Reading it always gives 0.
  • Writing to it is ignored.

Why? The constant 0 is used all the time (for example "copy R2 into R1" is just R1 = R2 + 0). The hardware version is shown after the lab code below.

Where the register file sits among storage:

  1. Register fileFastest, tiny, inside the CPU
  2. L1 cacheSRAM, very fast
  3. L2 cacheSRAM, bigger
  4. RAMDRAM, big, slower

The testbench (what it checks)

A testbench is a pretend circuit board that feeds inputs to your design and checks the outputs. It is only for simulation. The clock below has rising edges at t = 5, 15, 25, 35 ns. Inputs are changed at times between edges, so there are no races.

  1. Write 0xDEADBEEF to r1, then 0x12345678 to r2.
  2. Read r1 and r2 on both ports at the same time.
  3. Try a write with we = 0 and show it is ignored.
  4. Start a write to r1 and show the read port still gives the OLD value until the clock edge.

Common mistakes & exam traps

Slips that cost marks
  • Clocking the read port (putting the reads inside always @(posedge clk)). Reads then arrive one cycle late. Reads must be combinational (assign).
  • Forgetting write enable. Without if (we), the register file overwrites a register on every clock edge.
  • Bus contention: if reads are built with tri-state drivers on a shared bus, never enable two drivers at once. Two outputs fight and the value is garbage.
  • Wrong address width: address bits = log₂(number of registers). 32 → 5, 8 → 3, 4 → 2.
  • Using = instead of <= in the clocked block.
  • Changing testbench inputs exactly on a clock edge (t = 5, 15…) creates a simulation race. Change them between edges.
  • "Writing to $zero changes it" is false: it always reads 0.

Practice

How many address bits does a register file with 32 registers need? With 16?

log₂ 32 = 5 bits. log₂ 16 = 4 bits.

Why does a register file have two read ports but only one write port?

An R-type instruction such as add rd, rs1, rs2 reads two registers (rs1, rs2) and writes one (rd), all in one cycle.

WADDR = 3, WE = 0. Which register changes at the next clock edge?

None. The decoder picks R3 (WHERE), but WE = 0 (WHETHER), so every AND gate outputs 0.

R1 holds 5. In one cycle, WE = 1, WADDR = 1, WDATA = 9 and RADDR1 = 1. What does RDATA1 show before and after the clock edge?

Before the edge: 5 (the old value, because writes wait for the clock). After the edge: 9.

Homework: design an 8 × 16 register file. What sizes are the decoder, MUXes and storage?

8 registers → address = log₂ 8 = 3 bits.

  • Write port: a 3→8 decoder and 8 AND gates (each with WE).
  • Read ports: two 8:1 MUXes, each 16 bits wide.
  • Storage: 8 × 16 = 128 flip-flops. In Verilog: reg [15:0] r [0:7];
What happens if you read MIPS $zero after writing 42 to it?

You read 0. Register 0 is hardwired to zero; writes to it are ignored.

Your testbench shows rdata1 changing one full cycle after you change raddr1. What is wrong?

The read was written inside always @(posedge clk), so it became clocked. Use assign rdata1 = r[raddr1]; so reads are combinational.
