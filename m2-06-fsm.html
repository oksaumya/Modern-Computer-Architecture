Finite state machines: Moore vs Mealy

A finite state machine (FSM) is a circuit that is always in exactly one of a fixed list of situations, called states. On each clock edge it looks at its inputs and decides which state to move to next.

Think of it like this: a board game. Your token sits on exactly one square (the state). Each turn you roll the dice (the input), and the rules say which square you move to (the transition). Some squares say "collect a prize" (the output).

Key terms

State
What the machine "remembers" about the past, e.g. "I have seen 1, 0 so far".
Transition
A move from one state to another, chosen by the current state and the input.
Output
The signal the FSM produces, e.g. "sequence found" or "light is red".
State diagram
A drawing: circles are states, arrows are transitions labelled with their conditions.
State table
The same information as the diagram, written as a table: current state + input → next state + output.
State encoding
Giving each state a binary number so it can be stored in flip-flops.
Reset state
The state the machine starts in (S0) when reset is 1.

1. What an FSM is

Every FSM has three ingredients:

  1. States: a finite list. The machine is in exactly one at a time.
  2. Transitions: rules that use the current state + inputs to pick the next state.
  3. Outputs: signals the machine produces.

FSMs are everywhere: traffic lights, vending machines, elevators, washing machines, game AI (patrol → chase → attack), TCP network connections, USB handshakes and regex search engines. Even the CPU's own Fetch → Decode → Execute → Writeback loop is an FSM.

2. Moore vs Mealy

There are two styles. The only difference is what the output depends on.

"Moore = output in the circle, Mealy = output on the arrow." Both styles can solve the same problems.

3. Anatomy of any FSM

Every FSM is built from three blocks: next-state logic (combinational gates), a state register (flip-flops), and output logic (combinational gates).

4. Example: a traffic light (Moore)

The light goes GREEN → YELLOW → RED → GREEN. It moves on only when a timer says "expired". The output (Go / Slow / Stop) depends only on the colour, so this is a Moore machine.

Big picture: how a CPU uses FSMs

A CPU has a control unit (an FSM) and a datapath (registers, ALU, MUXes). Control sends control signals to the datapath; the datapath sends status flags (like "result is zero") back.

6. Worked design: a "1011" sequence detector

Goal: one input bit x arrives on each clock edge. Output y = 1 when the last four bits were 1011. Overlapping is allowed: in 1011011 the pattern is found twice, because the last 1 of the first match starts the next one.

Idea: each state remembers "how much of 1011 have I matched so far?"

StateMeaning
S0nothing matched yet
S1matched 1
S2matched 10
S3matched 101
S4 (Moore only)matched 1011 → output 1

The rule for a wrong bit: don't just go back to S0. Look at the bits you have so far and find the longest ending that is still a start of 1011. Example: in S3 (101) a 0 arrives → 1010. Its ending 10 is a start of 1011, so go to S2.

Mealy version: 4 states

Currentx = 0: next / yx = 1: next / y
S0S0 / 0S1 / 0
S1S2 / 0S1 / 0
S2S0 / 0S3 / 0
S3S2 / 0S1 / 1
  • S1 + 1 → S1: 11 ends in 1, which is still a start.
  • S2 + 0 → S0: 100 has no useful ending (neither 0 nor 00 starts 1011).
  • S3 + 1 → S1, output 1: found 1011! Its last 1 can begin the next match.

Encoding: 4 states need ⌈log₂ 4⌉ = 2 flip-flops, e.g. S0 = 00, S1 = 01, S2 = 10, S3 = 11.

Moore version: 5 states

In Moore, the output must live inside a state, so we need an extra state S4 meaning "just matched 1011, output 1".

CurrentOutput ynext if x = 0next if x = 1
S00S0S1
S10S2S1
S20S0S3
S30S2S4
S41S2S1

S4 + 0 → S2 because 10110 ends in 10. S4 + 1 → S1 because 10111 ends in 1. 5 states need ⌈log₂ 5⌉ = 3 flip-flops, one more than Mealy.

Trace: input "101011" through the Mealy detector

Start: reset puts the machine in S0. Inputs will arrive in this order: 1, 0, 1, 0, 1, 1.

Bit 1 = 1: in S0, input 1 → output 0, go to S1 (matched 1).

Bit 2 = 0: in S1, input 0 → output 0, go to S2 (matched 10).

Bit 3 = 1: in S2, input 1 → output 0, go to S3 (matched 101).

Bit 4 = 0: in S3, input 0 → output 0. 1010 ends in 10, so go to S2, not S0.

Bit 5 = 1: in S2, input 1 → output 0, go to S3 (matched 101 again).

Bit 6 = 1: in S3, input 1 → output 1. Found 1011! Go to S1, because the last 1 can start a new match.

State path: S0 → S1 → S2 → S3 → S2 → S3 → S1. Output: 000001. The Moore machine takes the path S0 → S1 → S2 → S3 → S2 → S3 → S4; its 1 appears only once it is in S4, one clock cycle later than the Mealy output.

Common mistakes & exam traps

Slips that cost marks
  • Resetting to S0 after a match is wrong for overlapping detection. After 1011 the trailing 1 can start a new match, so go to S1.
  • Mixing notations: Moore writes the output in the circle (S1/1); Mealy writes in/out on the arrow. Don't mix them in one diagram.
  • Miscounting states: Moore usually needs one more state than Mealy (5 vs 4 for 1011).
  • Wrong flip-flop count: N states need ⌈log₂ N⌉ flip-flops. 5 states → 3, not 2.
  • Forgetting the reset state. Without reset, the machine may power up in a random state.
  • Unused codes (like 11 in the traffic light) should route back to reset, so the machine can't get stuck.
  • Missing default or default values in always @(*) creates accidental latches.

Practice

Moore or Mealy: the output changes in the same cycle the input changes. Which one is it?

Mealy, because its output depends on the input directly. A Moore output only changes when the state changes (one cycle later).

How many flip-flops for an FSM with 12 states?

⌈log₂ 12⌉ = ⌈3.58⌉ = 4 flip-flops (3 bits only give 8 codes).
