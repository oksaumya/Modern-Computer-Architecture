Von Neumann vs Harvard architecture

A computer has a CPU, memory, I/O and wires (buses) that connect them. There are two classic ways to connect them. Von Neumann keeps program and data in one memory on one bus. Harvard gives the program and the data their own memories and their own buses.

Think of it like this: a kitchen. In a von Neumann kitchen, the recipe book and the ingredients sit on one shelf, and the cook uses one door to reach it. The cook has to take turns: fetch the recipe, then fetch the flour. In a Harvard kitchen, recipes are on one shelf and ingredients on another, each with its own door. The cook can grab both at once.

Key terms

CPU
Central Processing Unit. The part that computes: control unit + ALU + registers.
Memory
The part that stores things. Each byte sits at a numbered place called an address.
I/O
Input/Output. How the computer talks to the world: keyboard, screen, disk, network.
Bus
A bundle of shared wires that connects the parts. It carries an address, data and control signals.
Instruction
One small command for the CPU, e.g. "add these two registers". In MIPS it is a 32-bit number.
Stored-program concept
The program is kept in memory as numbers, just like data. To change the program, you just change the memory.
Bottleneck
The narrowest point that slows everything down, like the neck of a bottle.
Cache
A small, very fast memory (SRAM) next to the CPU that keeps copies of recently used bytes.
Microcontroller
A whole tiny computer on one chip (CPU + memory + I/O), e.g. the AVR chip on an Arduino.
DSP
Digital Signal Processor. A chip built to process audio, radio or sensor signals very fast.

1. The parts, and the big question

Every computer has the same four parts: CPU (compute), MEMORY (store), I/O (talk to the world) and BUS (connect). The class notes (L09) then ask: how do they connect, and how many buses? Two classic blueprints answer that question: von Neumann and Harvard.

2. The stored-program concept

The earliest computers (e.g. ENIAC, 1945) were programmed by re-plugging cables. Changing the program took days. John von Neumann's 1945 report described a better idea:

Programs ARE data

An instruction is just a number. So store the program in memory, next to the data. The CPU reads the next instruction from memory, does it, and moves on. To run a different program, load different numbers into memory.

Example: the MIPS instruction add $t0, $s1, $s2 is stored in memory as the number 0x02324020. To memory it looks exactly like any other 32-bit value. (See MIPS instruction formats for how that number is built.)

This is von Neumann's superpower. Because programs are data, other programs can create, load or change them:

  • Compilers write out programs as data.
  • OS loaders copy a program from disk into memory, then run it.
  • JIT compilers (Java, JavaScript) generate machine code while the program runs.
  • Self-modifying code changes its own instructions.

It is also the root of whole classes of security attacks (see section 7).

How the CPU runs a stored program

  1. FetchRead the instruction at address PC from memory.
  2. DecodeWork out what it means (which operation, which registers).
  3. ExecuteDo it, e.g. add in the ALU, or read/write data in memory.
  4. NextPC ← PC + 4, then repeat forever.

PC means Program Counter: a register that holds the address of the next instruction. Module 4 builds this cycle in hardware (single-cycle datapath).

3. Von Neumann architecture

One memory holds both the program and the data. One bus connects that memory to the CPU.

The von Neumann bottleneck

Every instruction and every piece of data must travel over the same single bus. The CPU fetches an instruction, then the data, then the next instruction: one at a time. The bus is the neck of the bottle.

It gets worse because the CPU is much faster than main memory. Main memory is DRAM, which takes about 50–100 ns to answer. SRAM answers in a few ns (see SRAM vs DRAM). The CPU spends a lot of time waiting. Module 5 calls this the memory wall.

Good

  • Simple: one memory, one bus.
  • Flexible: any memory byte can be code or data.
  • Programs can load and create programs.

Bad

  • Bottleneck: code and data take turns on one bus.
  • A bug or attack can make the CPU run data as code.

4. Harvard architecture

The program and the data get separate memories and separate buses. The name comes from the Harvard Mark I (1944), which read its program from punched paper tape and kept data in other storage.

  • Where it is used: microcontrollers and DSPs. Example: the AVR ATmega328P on an Arduino Uno keeps the program in 32 KB of Flash and the data in 2 KB of SRAM, on separate buses.
  • Good: no bottleneck between code and data. The CPU can never accidentally run data as code. The two memories can even use different technologies and sizes (Flash for code, SRAM for data).
  • Bad: the split is fixed. Unused program memory cannot be used for data. Loading a new program while running is hard.
You will meet Harvard again in Module 4

The textbook single-cycle MIPS datapath draws a separate instruction memory and data memory. That is a Harvard-style model: it lets one clock cycle fetch the instruction and read/write data at the same time.

5. Modified Harvard: what modern CPUs really do

Laptops, phones and servers mix both ideas:

  • Close to the CPU core (Harvard-style): the level-1 cache is split in two. L1i holds instructions and L1d holds data. Each has its own path to the core, so the core can fetch and read data at the same time. A typical size is 32–48 KB each, per core.
  • Further away (von Neumann-style): the L2/L3 caches and the main memory (DRAM) hold code and data together, in one address space. So the OS can still load programs as data.

7. Security: when data becomes code

In a von Neumann memory, the CPU cannot tell code from data. It runs whatever the PC points to. Attackers use this in a code-injection attack:

  1. InjectThe attacker sends input that contains machine-code bytes.
  2. OverflowA bug copies too much input, e.g. past the end of an array on the stack.
  3. HijackThe extra bytes overwrite a saved return address so it points at the injected bytes.
  4. RunWhen the function returns, the CPU jumps into the attacker's "data" and runs it as code.
The defence: the NX bit

NX means No-eXecute (Intel calls it XD, Windows calls the feature DEP). Every page of memory gets a flag. The OS marks the stack and the heap as writable but not executable, and the code as executable but not writable (a rule called W^X, "write XOR execute"). If the PC jumps into an NX page, the CPU raises a fault and the OS stops the program. This brings a bit of Harvard's safety to a von Neumann memory.

Attackers adapted with return-oriented programming (ROP), which reuses code that is already executable. So defences like address randomisation (ASLR) were added as well. Module 6 covers other hardware-level attacks (Spectre & Meltdown).

Common mistakes & exam traps

Slips that cost marks
  • The von Neumann bottleneck is about the single shared bus (and slow memory). It is not about having "only one CPU".
  • Harvard does not mean "no stored program". Harvard machines still store the program in memory, just a separate one.
  • Modern PCs are not pure Harvard. Only the L1 cache is split; main memory is shared.
  • Arduino (AVR) is the standard Harvard example. A desktop PC is the standard von Neumann (modified Harvard) example.
  • The NX bit does not stop the buffer overflow itself. It stops the injected bytes from running.

Practice

State the stored-program concept in one sentence.

Instructions are encoded as numbers and kept in memory alongside data, so the CPU fetches and runs them from memory, and a new program can be loaded just by changing memory.

What is the von Neumann bottleneck, and why does it slow the CPU?

Instructions and data share one bus to one memory, so they must be moved one at a time. The CPU is also much faster than DRAM (50–100 ns per access), so it waits on that single path.

Give two advantages and one disadvantage of the Harvard architecture.

Advantages: instruction fetch and data access can happen at the same time; data can never be run as code; each memory can use a different technology (Flash / SRAM). Disadvantage: the code/data split is fixed, so spare program memory cannot hold data.

Is an Arduino Uno von Neumann or Harvard? Why?

Harvard. Its AVR chip keeps the program in Flash and the data in SRAM, with separate buses and separate address spaces.

Why do we call modern x86/ARM CPUs "modified Harvard"?

Their L1 cache is split into L1i (instructions) and L1d (data), which is Harvard-style. But L2/L3 and main memory hold code and data together, which is von Neumann-style.

How does a code-injection attack use the stored-program concept, and what does the NX bit do?

The attacker's input (data) contains machine code. A bug redirects the PC to that input, and because memory does not separate code from data, the CPU runs it. The NX bit marks data pages (stack, heap) as non-executable, so the CPU faults instead of running the injected bytes.

Name four things made possible by "programs are data".

Compilers, OS program loaders, JIT compilers, and self-modifying code.
