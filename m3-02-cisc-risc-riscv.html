CISC vs RISC, and RISC-V's modular design

There are two ways to design a CPU's instruction set. CISC offers many powerful instructions of different lengths. RISC offers a small set of simple instructions, all the same length, that are easy to run fast. RISC-V is a free RISC design: a small base plus optional add-on "extensions".

Think of it like this: a CISC kitchen has a machine for every dish: press one button for "make pizza". A RISC kitchen has a few simple tools (knife, pan, oven) and a fast cook who chains simple steps. The RISC cook needs more steps, but each step is quick and predictable, so several cooks can work in an assembly line. RISC-V is like a basic kitchen kit where you add only the extra modules you need (a pizza oven, a mixer).

Key terms

ISA
Instruction Set Architecture: the list of instructions a CPU understands and how they are encoded. It is the contract between software and hardware.
CISC
Complex Instruction Set Computer. Example: Intel/AMD x86.
RISC
Reduced Instruction Set Computer. Examples: MIPS, ARM, RISC-V.
Load/store
Only load (read memory) and store (write memory) instructions touch memory. All maths happens on registers.
Microcode
A tiny hidden program inside a CISC CPU that carries out one complex instruction as many small steps.
Micro-op (µop)
A simple internal step. Modern x86 chips turn each instruction into µops.
Pipelining
Running instructions like an assembly line: several instructions are in different stages at once (Module 4).
CPI
Cycles Per Instruction: the average number of clock cycles one instruction takes.
Royalty-free
Anyone can build and sell chips using it without paying a licence fee.
Extension
An optional add-on group of instructions in RISC-V, named by a letter (M, A, F, D, C, V…).

1. CISC: powerful, variable-length instructions

In the 1970s memory was tiny and expensive. Designers wanted programs to be short, so each instruction did a lot of work. That is the CISC idea. x86 is the main CISC family today.

  • Variable length: an x86 instruction is anywhere from 1 to 15 bytes long. The CPU must decode the first bytes just to find where the instruction ends.
  • Complex, memory-to-memory instructions: one instruction can read memory, compute, and write memory back, e.g. add dword [ebx], 5. rep movsb copies a whole block of memory.
  • Microcode: complex instructions are run by an internal micro-program.
  • Fewer instructions per program (dense code), but each one can take many clock cycles (high CPI).
  • Few general-purpose registers (8 in 32-bit x86, 16 in x86-64).

2. RISC: simple, fixed-length instructions

In the 1980s, researchers (Patterson at Berkeley, Hennessy at Stanford) found that programs mostly use simple instructions. So they made those simple ones very fast.

  • Fixed length: every MIPS instruction is exactly 32 bits (4 bytes). The next instruction is always at PC + 4.
  • Load/store: only lw/sw touch memory. add works only on registers.
  • Simple instructions with only a few formats (MIPS has 3: R, I, J), so decoding is quick. Control can be plain hard-wired logic, not microcode.
  • Easy to pipeline: every instruction takes about the same steps, so they flow smoothly through an assembly line.
  • More registers: 32 in MIPS and RISC-V, so fewer slow memory trips.

3. Same task in x86 and MIPS

Task: a number x is stored in memory. Add 5 to it. The address of x is already in a register (ebx on x86, $s0 on MIPS). In MIPS, $s0 and $t0 are two of the 32 registers: $s registers hold our variables and $t registers hold temporary scratch values (full list on the next page).

x86 (CISC): 1 instruction

x863 bytes
add dword [ebx], 5Read memory at ebx, add 5, write the result back. All in one instruction.

MIPS (RISC): 3 instructions

mips12 bytes
lw $t0, 0($s0)Load: copy x from memory into register $t0.
addi $t0, $t0, 5Add 5, in the register.
sw $t0, 0($s0)Store: write the result back to memory.

The class example from L01 is the same story. Python's A[i] = B[i] + C[i] becomes lw · lw · add · sw in MIPS: load both values, add in registers, store the result.

4. The iron law ties it together

CPU time = Instruction count × CPI × Cycle timeHow many instructions × how many clock cycles each takes (on average) × how long one clock cycle lasts
  • CISC makes the instruction count small, but CPI is high and decoding is slow.
  • RISC accepts a bigger instruction count, but gets a low CPI (pipelining) and a short cycle time (simple decoding).

Worked example (made-up numbers)

  1. CISC machine: 1.0 million instructions, CPI = 3, cycle = 1 ns.
    Time = 1.0×10⁶ × 3 × 1 ns = 3×10⁶ ns = 3.0 ms.
  2. RISC machine: the same program needs 1.5 million instructions, CPI = 1.2, cycle = 0.8 ns.
    Time = 1.5×10⁶ × 1.2 × 0.8 ns = 1.44×10⁶ ns = 1.44 ms.
  3. Result: 3.0 / 1.44 ≈ 2.08× faster for RISC, even with 50% more instructions. More in Performance: CPI, IPC & Amdahl's Law.

5. Today: the two ideas have merged

Modern x86 chips (Intel Core, AMD Ryzen) keep the x86 instruction set for old software. But inside, a decoder turns each x86 instruction into simple RISC-like micro-ops. A fast RISC-style core then runs those µops with pipelining.

7. RISC-V: an open, modular ISA

RISC-V (say "risk five") started at UC Berkeley in 2010. It is open and royalty-free: anyone can design a RISC-V chip without asking permission or paying a fee. (x86 is made only by Intel and AMD; ARM designs require a paid licence.)

It looks a lot like MIPS: 32 registers (x0–x31), x0 hardwired to 0 (just like $zero), fixed 32-bit instructions, load/store.

The modular extension model

Instead of one huge fixed instruction set, RISC-V has a small base that every chip must have, plus optional extensions. A tiny sensor chip takes only what it needs. A laptop chip takes much more.

NameWhat it addsPlain meaning
RV32I / RV64IBase integer set (about 40 instructions)Add, subtract, logic, shifts, load/store, branches, jumps. 32-bit or 64-bit registers. Always required.
MMultiply / dividemul, div, rem in hardware.
AAtomicInstructions for safe sharing between threads (see atomics & mutexes).
F / DFloat / doubleSingle- and double-precision decimal-point maths.
CCompressed16-bit short forms of common instructions. Code gets about 25–30% smaller.
VVectorSIMD: one instruction works on many numbers at once (see SIMD).
G"General" = IMAFD + Zicsr + ZifenceiA shorthand for the usual general-purpose set. Zicsr = control/status registers; Zifencei = an instruction-fetch sync instruction.

Reading a RISC-V name: RV64GC

  1. RVRISC-V
  2. 6464-bit registers and addresses (base RV64I)
  3. GI + M + A + F + D (+ Zicsr, Zifencei)
  4. Cplus compressed 16-bit instructions

So RV64GC = RV64IMAFDC (+Zicsr, Zifencei). It is the usual target for Linux-capable RISC-V chips. A small microcontroller might be RV32IMC: 32-bit, multiply, compressed, and nothing else.

Common mistakes & exam traps

Slips that cost marks
  • RISC does not mean "fewer instructions per program". It means simpler instructions, so programs usually need more of them.
  • x86 length is 1 to 15 bytes, not "up to 16".
  • "Load/store" means only load/store instructions touch memory. add $t0, 0($s0) is not legal MIPS.
  • Don't say "x86 is pure CISC inside". Modern x86 translates to RISC-like µops.
  • G is not a single extension. It is shorthand for IMAFD (+Zicsr, Zifencei). C is not part of G, which is why names say "GC".
  • RISC-V is an open specification. Being royalty-free does not mean every chip design is free or open-source.

Practice

Give four features that make an ISA "RISC".

Fixed-length instructions; load/store architecture; few simple instructions and formats; many general-purpose registers (and hence easy pipelining and hard-wired control).

Why is a fixed instruction length good for pipelining?

The CPU always knows the next instruction starts at PC + 4, and every field sits in the same bit position. So fetch and decode are quick and take the same time for every instruction, which lets them move through pipeline stages evenly.

Program P: CISC needs 2 M instructions, CPI 4, cycle 1.2 ns. RISC needs 3 M instructions, CPI 1.5, cycle 1 ns. Which is faster, and by how much?

CISC: 2×10⁶ × 4 × 1.2 ns = 9.6 ms. RISC: 3×10⁶ × 1.5 × 1 ns = 4.5 ms. RISC is faster, by 9.6 / 4.5 ≈ 2.13×.

Write the MIPS for x86 add dword [ebx], 5 if the address is in $s0.

lw $t0, 0($s0) · addi $t0, $t0, 5 · sw $t0, 0($s0). Three instructions, because MIPS is load/store.

Expand the name RV64GC letter by letter.

RISC-V, 64-bit base integer set (I), M (multiply/divide), A (atomic), F (float), D (double), plus Zicsr and Zifencei (all from G), and C (compressed).

Why is a modular ISA useful?

A small chip (sensor, microcontroller) can implement only the base plus a few extensions, which saves area and power. A big chip adds more extensions. All of them still run the same base software.

How does modern x86 get RISC-style speed while staying CISC?

Its decoder translates each x86 instruction into simple RISC-like micro-ops, which a pipelined, out-of-order core then runs.
