CISC vs RISC, and RISC-V's modular design

L9 gave us the organisation — how CPU, memory and buses connect. The missing piece is the language: what set of commands does the hardware actually accept? That is the ISA. There are two philosophies for designing one. CISC packs power into each instruction. RISC keeps every instruction simple. RISC-V is a free, modular RISC design.

Think of it like this: a CISC kitchen has a machine for every dish: press one button for "make pizza". A RISC kitchen has a few simple tools (knife, pan, oven) and a fast cook who chains simple steps. The RISC cook needs more steps, but each step is quick and predictable, so several cooks can work in an assembly line. RISC-V is like a basic kitchen kit where you add only the extra modules you need (a pizza oven, a mixer).
The lecture's one-line thesis

"The trade never disappears — it just moves. CISC asks more of the chip; RISC asks more of the compiler." And the big reveal at the end: the RISC-vs-CISC war ended in a truce. Modern CPUs borrow from both.

Key terms

ISA
Instruction Set Architecture: the list of instructions a CPU understands and how they are encoded. It is the contract between software and hardware.
CISC
Complex Instruction Set Computer. Example: Intel/AMD x86.
RISC
Reduced Instruction Set Computer. Examples: MIPS, ARM, RISC-V.
Load/store
Only load (read memory) and store (write memory) instructions touch memory. All maths happens on registers.
Microcode
A tiny hidden program inside a CISC CPU that carries out one complex instruction as many small steps.
Micro-op (µop)
A simple internal step. Modern x86 chips turn each instruction into µops.
Pipelining
Running instructions like an assembly line: several instructions are in different stages at once (Module 4).
CPI
Cycles Per Instruction: the average number of clock cycles one instruction takes.
Royalty-free
Anyone can build and sell chips using it without paying a licence fee.
Extension
An optional add-on group of instructions in RISC-V, named by a letter (M, A, F, D, C, V…).
Code density
How much work a program does per byte of machine code. Denser code = a smaller program file.
Microarchitecture
How an ISA is actually built in silicon: the pipeline, caches and predictors. Two chips can share one ISA and have completely different microarchitectures.
Domain-specific ISA
An instruction set designed for one job (graphics, neural networks) instead of for general-purpose programs.

1. The ISA: the hardware/software contract

Before comparing the two philosophies, be clear what an ISA is. The lecture draws it as a sandwich: the ISA is the agreed interface in the middle, and the boundary the whole industry builds around.

2. CISC: powerful, variable-length instructions

The class's one-sentence philosophy: one instruction can do a whole task — even memory-to-memory arithmetic in a single line. Born when memory was scarce and expensive, so fewer, denser instructions saved precious space.

The philosophy

Instructions are variable-length: simple ones are short, complex ones are long. One CISC instruction can replace several RISC ones:

add [mem1], [mem2]The lecture's example: read two memory locations, add them, write the answer back — one instruction.

Character (the slide's list)

  • Hundreds of instructions
  • Variable length (1–15 bytes on x86)
  • Instructions can touch memory directly
  • Complex hardware decoder
  • Fewer lines of assembly
  • e.g. x86, VAX, 68000

Two more consequences the slides lean on later: complex instructions are run by an internal micro-program (microcode), and each one can take many clock cycles (high CPI). x86 also has few general-purpose registers — 8 in 32-bit x86, 16 in x86-64.

3. RISC: simple, fixed-length instructions

In the 1980s, researchers (Patterson at Berkeley, Hennessy at Stanford) found that programs mostly use simple instructions. So they made those simple ones very fast. The class's philosophy line: each instruction does ONE simple thing, in one cycle where possible, and only load and store touch memory.

The philosophy

All instructions are the same fixed length — easy to fetch, decode and pipeline. The same work as the CISC line above:

lw r1,m1 · lw r2,m2
add r1,r1,r2 · sw r1,m1Four simple steps instead of one complex one. Load both values into registers, add in registers, store the answer.

Character (the slide's list)

  • Few, simple instructions
  • Fixed length (e.g. 32 bits)
  • Only load/store touch memory
  • Simple, fast hardware decoder
  • More instructions per task
  • e.g. MIPS, ARM, RISC-V, SPARC

Two more: only a few instruction formats (MIPS has 3 — R, I, J), so control can be plain hard-wired logic instead of microcode; and 32 general-purpose registers in MIPS and RISC-V, so fewer slow memory trips. The next instruction is always at PC + 4.

Inside the 32 bits: fields, not just length

The class slide goes one level deeper. It is not only that RISC instructions are all the same length — their fields always sit in the same bit positions, so the decoder can pull out the register numbers before it even knows which instruction it has. (Field names here are the RISC-V ones the lecture uses: rd = destination register, rs1/rs2 = source registers, funct = "which exact operation". MIPS calls them rd, rs, rt, funct; same idea. Full detail on the next page.)

4. Activity 1 — one task, two styles

This is the class's own worked exercise. Task: compute C = A + B, then D = C × 2, where A, B, C and D all live in memory. Count the instructions each way.

CISC style — about 5 instructions

x86code → what it means
mov ax, [A]Copy the value stored at address A into register ax. Square brackets mean "the contents of memory at".
add ax, [B]Add the value at address B straight onto ax. This instruction reads memory and does arithmetic — impossible in RISC.
mov [C], axWrite ax (now A + B) out to address C.
shl ax, 1"Shift left by 1" — doubles the number, so ax = C × 2. (Shifting left by 1 is multiply by 2.) ax still held C, so no reload is needed.
mov [D], axWrite the doubled value out to address D.

Richer operations · direct memory operands.

RISC style — about 6 instructions

risccode → what it means
lw r1, ALoad word: copy the value at address A into register r1.
lw r2, BSame for B into r2. Memory can only be reached this way.
add r3, r1, r2Register-only arithmetic: r3 = r1 + r2, i.e. C = A + B.
sw r3, CStore word: write r3 back out to address C.
add r4, r3, r3Doubling trick: adding a number to itself is × 2, so r4 = C × 2 = D. No multiply instruction needed.
sw r4, DWrite the answer out to address D.

Each simple & one cycle · load/store only.

What to actually notice

5 vs 6 is a tiny difference, and that is the point. CISC's instruction-count win is real but modest, while each CISC instruction is harder to decode and takes more cycles. Count the memory touches instead: both do four (read A, read B, write C, write D). The work is the same — only the packaging differs.

Slide correction

The slide writes lw r1, A, as if a label fits inside the instruction. In real MIPS or RISC-V a 32-bit address does not fit in a 32-bit instruction, so an assembler expands lw r1, A into two instructions (load the top half of the address, then lw r1, 0(reg)). It is a fine shorthand for counting instructions in a comparison — just don't write it in an exam answer that asks for real machine instructions. Use the lw $t0, 0($s0) form below instead.

5. The same story, one line shorter

Task: a number x is stored in memory. Add 5 to it. The address of x is already in a register (ebx on x86, $s0 on MIPS). In MIPS, $s0 and $t0 are two of the 32 registers: $s registers hold our variables and $t registers hold temporary scratch values (full list on the next page). Keep this one in mind — it comes back when we open up a modern x86 chip.

x86 (CISC): 1 instruction

x863 bytes
add dword [ebx], 5Read memory at ebx, add 5, write the result back. All in one instruction.

MIPS (RISC): 3 instructions

mips12 bytes
lw $t0, 0($s0)Load: copy x from memory into register $t0.
addi $t0, $t0, 5Add 5, in the register.
sw $t0, 0($s0)Store: write the result back to memory.

The class example from L01 is the same story. Python's A[i] = B[i] + C[i] becomes lw · lw · add · sw in MIPS: load both values, add in registers, store the result.

6. The decoder tells the story

This is the slide the lecture builds everything else on. The two philosophies need the same total amount of cleverness — they just put it in different places.

CISC decoder

complexity in HARDWARE

  • Must handle variable-length instructions.
  • Often uses microcode — a mini-program per instruction.
  • Large, power-hungry, hard to pipeline.
  • But: shorter programs, denser code.

RISC decoder

complexity in the COMPILER

  • Fixed length → decode is almost trivial.
  • One instruction = one simple action.
  • Small, fast, easy to pipeline & replicate.
  • But: the compiler works harder to sequence more instructions.
Say it in the exam like this

"The trade never disappears — it just moves. CISC asks more of the chip; RISC asks more of the compiler." That single sentence answers half the CISC/RISC essay questions.

7. Each side's edge: density vs pipelining

Code density — CISC's edge

CISC programs are often smaller in bytes, because one instruction does more work. Smaller code means fewer bytes to fetch and less pressure on the L1 instruction cache. In memory-constrained or cache-sensitive settings, density is a real, measurable advantage.

Pipelining — RISC's edge

Uniform instructions flow through a pipeline like clockwork. The lecture gives four reasons, each tied to a concrete instruction property — worth memorising, because homework question 2 asks for exactly three of them.

PropertyWhy the pipeline likes it
Fixed lengthEasy fetch: the CPU always knows where the next instruction is (PC + 4) — no decode needed first.
Uniform formatSimple decode: every instruction decodes the same way, in one stage, at one speed.
One cycle eachSmooth flow: simple ops rarely stall the pipeline, so stages stay full and throughput stays high.
Load/store onlyPredictable memory: only two instructions touch memory, so hazards are easier to detect and handle.

The trade-off in one view

Every RISC strength has a matching CISC strength. Because both lists are real, the industry never picked a winner — it learned to combine them.

CISC strengths

  • Denser code (smaller programs)
  • Fewer instructions per task
  • Less instruction-fetch bandwidth
  • Rich, expressive operations

RISC strengths

  • Simple, fast, cheap decoder
  • Easy, efficient pipelining
  • Higher clock speeds possible
  • Simpler to design & verify

8. The iron law ties it together

CPU time = Instruction count × CPI × Cycle timeHow many instructions × how many clock cycles each takes (on average) × how long one clock cycle lasts
  • CISC makes the instruction count small, but CPI is high and decoding is slow.
  • RISC accepts a bigger instruction count, but gets a low CPI (pipelining) and a short cycle time (simple decoding).

Worked example (made-up numbers)

  1. CISC machine: 1.0 million instructions, CPI = 3, cycle = 1 ns.
    Time = 1.0×10⁶ × 3 × 1 ns = 3×10⁶ ns = 3.0 ms.
  2. RISC machine: the same program needs 1.5 million instructions, CPI = 1.2, cycle = 0.8 ns.
    Time = 1.5×10⁶ × 1.2 × 0.8 ns = 1.44×10⁶ ns = 1.44 ms.
  3. Result: 3.0 / 1.44 ≈ 2.08× faster for RISC, even with 50% more instructions. More in Performance: CPI, IPC & Amdahl's Law.

9. History: two lineages, two empires

The lecture sketches a family tree. Note the dates — this split defined 40 years of chips.

1990s–2000s: two empires

ARM — RISC wins mobile

  • Simple = low power = long battery life.
  • Licensable design → everyone builds ARM chips.
  • Billions of phones, tablets, embedded devices.
  • Now in Apple Silicon laptops too.

x86 — CISC holds the desktop

  • Backward compatibility: decades of software.
  • Intel & AMD poured R&D into raw speed.
  • The whole PC & server ecosystem locked in.
  • Still dominant in desktops & data centres.
The lesson the lecturer wants you to write down

"Best ISA rarely decides the winner — ecosystems, power budgets and compatibility do."

10. Today: the two ideas have merged

Modern x86 chips (Intel Core, AMD Ryzen) keep the x86 instruction set for old software. But inside, a decoder turns each x86 instruction into simple RISC-like micro-ops. A fast RISC-style core then runs those µops with pipelining — and renames them, exactly like a RISC machine. The CISC part is, in the lecture's words, "just a compatibility skin".

The boundary has blurred — both directions

It is not only CISC that moved. The class lists four ways the labels stopped meaning much:

What happened
CISC went RISC insidex86 decodes to RISC-like µops, then pipelines and reorders them. The CISC is just a compatibility skin.
RISC added complexityModern ARM and RISC-V have hundreds of instructions, SIMD and vector extensions — not so "reduced" any more.
Compressed instructionsARM Thumb and RISC-V "C" add 16-bit encodings for density — a very CISC-like concern.
It's about implementation nowWhat matters today is the microarchitecture — caches, pipelines, predictors — more than the ISA label.
So who won? Both — and neither.

The modern consensus: a RISC-like execution core is the way to go for performance, so keep a clean, pipelineable core and put whatever instruction "skin" the market needs on the front. x86: CISC skin for compatibility, RISC core inside. ARM: RISC through and through, the efficiency king. RISC-V: clean RISC, open to all, modular extensions.

12. RISC-V: an open, modular ISA

RISC-V (say "risk five") started at UC Berkeley in 2010, created by the same research lineage that gave us RISC in the first place. It is open and royalty-free: anyone — students, startups, giants — can design a RISC-V chip without asking permission or paying a fee. (x86 is made only by Intel and AMD; ARM designs require a paid licence.) Adoption is exploding, from university teaching to microcontrollers to data-centre and AI chips.

It looks a lot like MIPS: 32 registers (x0–x31), x0 hardwired to 0 (just like $zero), fixed 32-bit instructions, load/store.

Slide correction

The L10 slide closes with "we'll use RISC-V assembly in the coming lectures". In this course it turned out to be MIPS — L11 (registers and instruction formats), L12 (C to MIPS) and Labs 11–13 are all MIPS, and MARS is the simulator. Nothing is lost: MIPS and RISC-V are the same RISC ideas with different register spellings ($t0 vs x5). Learn the ideas, and the notation swap is ten minutes' work.

The modular extension model textbook extra

The lecture says only "a small base ISA plus optional extensions (multiply, float, vector, atomic) — take only what you need". The letter-by-letter detail below is from the textbook, in case an exam asks you to read a name like RV64GC.

Instead of one huge fixed instruction set, RISC-V has a small base that every chip must have, plus optional extensions. A tiny sensor chip takes only what it needs. A laptop chip takes much more.

NameWhat it addsPlain meaning
RV32I / RV64IBase integer set (about 40 instructions)Add, subtract, logic, shifts, load/store, branches, jumps. 32-bit or 64-bit registers. Always required.
MMultiply / dividemul, div, rem in hardware.
AAtomicInstructions for safe sharing between threads (see atomics & mutexes).
F / DFloat / doubleSingle- and double-precision decimal-point maths.
CCompressed16-bit short forms of common instructions. Code gets about 25–30% smaller.
VVectorSIMD: one instruction works on many numbers at once (see SIMD).
G"General" = IMAFD + Zicsr + ZifenceiA shorthand for the usual general-purpose set. Zicsr = control/status registers; Zifencei = an instruction-fetch sync instruction.

Reading a RISC-V name: RV64GC

  1. RVRISC-V
  2. 6464-bit registers and addresses (base RV64I)
  3. GI + M + A + F + D (+ Zicsr, Zifencei)
  4. Cplus compressed 16-bit instructions

So RV64GC = RV64IMAFDC (+Zicsr, Zifencei). It is the usual target for Linux-capable RISC-V chips. A small microcontroller might be RV32IMC: 32-bit, multiply, compressed, and nothing else.

13. Beyond CPUs: domain-specific ISAs

The newest frontier: instruction sets built for one job, especially AI. The class flags this as the door into Module 6.

What it is
GPU ISAs (NVIDIA PTX)Thousands of simple cores with their own instruction set, built for massive parallelism. See SIMD, GPUs & TPUs.
TPU / AI acceleratorsGoogle's TPU has an ISA centred on matrix multiply — the core operation of neural networks.
Why specialise?A fixed workload lets you strip away generality and win huge efficiency — the exact opposite of general-purpose.

Key takeaways

  1. The ISA is the hardware/software contract — the instruction set both compilers and chips agree to.
  2. CISC uses rich, variable-length instructions (x86, VAX): dense code, complex decoder, harder to pipeline.
  3. RISC uses simple, fixed-length, load/store instructions (MIPS, ARM, RISC-V): easy to pipeline, simpler chips.
  4. The trade-off just moves complexity between hardware and compiler — neither philosophy escapes it.
  5. Modern x86 decodes CISC into RISC-like micro-ops; RISC-V opens the ISA to all — the two worlds have merged.

Common mistakes & exam traps

The six the lecturer called out
  • "RISC is always faster." Not inherently. RISC eases pipelining, but real speed depends on the whole microarchitecture.
  • "CISC is obsolete." x86 still dominates desktops and servers. It just runs RISC-like µops inside.
  • "RISC = fewer instructions run." RISC has fewer instruction types, but often runs more instructions per task.
  • Forgetting load/store. It is RISC's defining feature — only load and store touch memory.
  • "The ISA determines speed." The implementation (pipeline, caches, predictors) matters far more than the ISA label.
  • Mixing up length rules. RISC = fixed length. CISC = variable length. This is what drives decoder complexity.
Extra slips worth avoiding
  • x86 length is 1 to 15 bytes, not "up to 16".
  • add $t0, 0($s0) is not legal MIPS — that is the load/store rule in action.
  • G is not a single extension. It is shorthand for IMAFD (+Zicsr, Zifencei). C is not part of G, which is why names say "GC".
  • RISC-V is an open specification. Being royalty-free does not mean every chip design is free or open-source.

Practice

Homework 1 (class): write a 3-element vector add in (a) x86-style CISC and (b) RISC style. Count the instructions.

The job is C[i] = A[i] + B[i] for i = 0, 1, 2. Written straight out (no loop), so the instruction counts are honest. A0 means "the memory location holding element 0 of A".

(a) CISC — 9 instructions

mov ax, [A0]
add ax, [B0]
mov [C0], ax
mov ax, [A1]
add ax, [B1]
mov [C1], ax
mov ax, [A2]
add ax, [B2]
mov [C2], ax

3 per element. The add reads memory and computes in one instruction.

(b) RISC — 12 instructions

lw  r1, A0
lw  r2, B0
add r3, r1, r2
sw  r3, C0
lw  r1, A1
lw  r2, B1
add r3, r1, r2
sw  r3, C1
lw  r1, A2
lw  r2, B2
add r3, r1, r2
sw  r3, C2

4 per element: load, load, add, store.

Count: 9 vs 12 — CISC wins on instruction count by 25%, exactly the pattern the lecture predicts. But both versions perform the same 9 memory accesses (6 reads, 3 writes) and the same 3 additions. The work is identical; only the packaging differs. And each RISC instruction is a single predictable pipeline step, while add ax, [B0] is really a load plus an add hiding in one opcode.

If you wrote it as a loop instead: both shrink to roughly 4–6 instructions in the loop body plus 3–4 for the counter and branch, and the gap nearly vanishes — another reminder not to read too much into raw instruction counts.

Homework 2 (class): list 3 reasons RISC is friendlier to pipelining. Tie each to a concrete instruction property.
  1. Fixed length → easy fetch. The next instruction is always at PC + 4, so the fetch stage never has to decode anything first to know where to look.
  2. Uniform format → simple decode. The register fields sit in the same bit positions in every instruction, so one decode stage at one speed handles them all. No microcode, no multi-cycle decode.
  3. Load/store only → predictable memory. Exactly one pipeline stage touches memory, and only two instruction types use it, so data hazards and memory stalls are easy to detect and forward around.

A fair fourth, if you want it: one simple action per instruction means roughly equal work per stage, so no single instruction clogs the pipeline.

Exit ticket 1: name the two hallmarks of RISC (hint: instruction length + memory access).

Fixed instruction length (every instruction the same width, e.g. 32 bits) and load/store architecture (only lw and sw touch memory; everything else works on registers).

Exit ticket 2: what are micro-ops, and why does x86 use them?

Micro-ops (µops) are simple, RISC-like internal steps. The x86 front-end decoder splits each complex x86 instruction into several of them — add [mem], 5 becomes load · add · store.

Why: so Intel and AMD can keep the x86 instruction set for backward compatibility (decades of software must still run) while the back end is a clean, pipelined, out-of-order RISC-style core that renames and reorders those µops. CISC skin outside, RISC engine inside.

Exit ticket 3: why can Apple use ARM (RISC) for laptops while x86 still thrives on the desktop?

Apple could switch because it controls its own whole software stack: it recompiled macOS and its apps for ARM and shipped Rosetta 2 to translate old x86 binaries, so the compatibility problem was solvable in one company. ARM's performance-per-watt advantage then pays off directly in battery life and in fanless designs.

x86 still thrives because the rest of the PC and server world cannot do that: decades of binary-only Windows software, an entire ecosystem of drivers and tooling, and Intel/AMD's enormous investment in making those same instructions run fast.

The point of the question: this is the lecture's "best ISA rarely decides the winner" lesson. Ecosystems, power budgets and compatibility decided both outcomes — not the ISA.

Mini debate prep (class): one strong argument for "RISC won" and one for "CISC won".

RISC won: every high-performance chip on earth, x86 included, now executes a RISC-like instruction stream internally. The execution core the industry settled on is RISC's. Add that ARM ships in billions of devices and Apple put it in laptops.

CISC won: the x86 interface is still what desktops and data centres run, 45 years on; the market never abandoned it. And RISC ISAs grew hundreds of instructions, SIMD, vectors and compressed 16-bit encodings — they became what they set out to replace.

The debrief answer: neither. The war ended in a truce — a RISC core with whatever instruction skin the market needs on the front.

Give four features that make an ISA "RISC".

Fixed-length instructions; load/store architecture; few simple instructions and formats; many general-purpose registers (and hence easy pipelining and hard-wired control).

Why is a fixed instruction length good for pipelining?

The CPU always knows the next instruction starts at PC + 4, and every field sits in the same bit position. So fetch and decode are quick and take the same time for every instruction, which lets them move through pipeline stages evenly.

Program P: CISC needs 2 M instructions, CPI 4, cycle 1.2 ns. RISC needs 3 M instructions, CPI 1.5, cycle 1 ns. Which is faster, and by how much?

CISC: 2×10⁶ × 4 × 1.2 ns = 9.6 ms. RISC: 3×10⁶ × 1.5 × 1 ns = 4.5 ms. RISC is faster, by 9.6 / 4.5 ≈ 2.13×.

Write the MIPS for x86 add dword [ebx], 5 if the address is in $s0.

lw $t0, 0($s0) · addi $t0, $t0, 5 · sw $t0, 0($s0). Three instructions, because MIPS is load/store.

Expand the name RV64GC letter by letter.

RISC-V, 64-bit base integer set (I), M (multiply/divide), A (atomic), F (float), D (double), plus Zicsr and Zifencei (all from G), and C (compressed).

Why is a modular ISA useful?

A small chip (sensor, microcontroller) can implement only the base plus a few extensions, which saves area and power. A big chip adds more extensions. All of them still run the same base software.

How does modern x86 get RISC-style speed while staying CISC?

Its decoder translates each x86 instruction into simple RISC-like micro-ops, which a pipelined, out-of-order core then runs.
