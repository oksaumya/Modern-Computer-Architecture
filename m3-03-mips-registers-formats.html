MIPS32: registers and instruction formats (R, I, J)

MIPS32 has 32 registers, and every instruction is exactly 32 bits. Those 32 bits are cut into fields in one of only three layouts: R-type (register maths), I-type (a constant, memory, or a branch) and J-type (jump). Learn the three layouts and you can turn any instruction into hex, and back.

Think of it like this: a fixed-size postal form with boxes. Box 1 always says what kind of form (the opcode). The rest of the boxes depend on that kind: a "transfer" form has from, to, amount boxes; an "address change" form has one big box. The clerk (the CPU) reads box 1 first, then knows how to read the rest.

Key terms

Register
A tiny, very fast storage slot inside the CPU. MIPS has 32 of them, each 32 bits wide.
Word
A 32-bit value (4 bytes) in MIPS.
Byte-addressed
Every byte of memory has its own address. So one word covers 4 addresses, and the next word is 4 further on.
Opcode (op)
The top 6 bits. They say which instruction (or which format) this is.
funct
The bottom 6 bits of an R-type. They pick the exact operation (add, sub, and…).
rs, rt, rd
5-bit register numbers (0–31). rs = first source, rt = second source (or target in I-type), rd = destination.
shamt
Shift amount: how many places to shift (for sll/srl). 0 otherwise.
Immediate
A constant number stored inside the instruction itself (16 bits in I-type).
Sign extension
Widening a number by copying its top (sign) bit to the left, so −1 (FFFF) stays −1 (FFFFFFFF).
PC
Program Counter: holds the address of the current instruction. Normally PC ← PC + 4.

1. The 32 registers

Each register has a number (0–31, used inside the machine code) and a name (used when you write code). The name tells you its job, by agreement between programmers (the "calling convention"). You write $t0, but the machine code stores 8.

Special registers (not among the 32):

  • PC: the program counter.
  • HI and LO: hold the results of mult and div. mult puts the upper 32 bits of the 64-bit product in HI and the lower 32 in LO. div puts the remainder in HI and the quotient in LO.
Link to Module 2

These 32 registers are the register file you built: 32 × 32-bit registers, 2 read ports (for rs and rt) and 1 write port (for rd or rt). Reads are instant (combinational); writes happen on the clock edge. The $zero register is wired to 0.

Memorise the numbers with ranges

0 zero · 1 at · 2–3 v · 4–7 a · 8–15 t · 16–23 s · 24–25 t · 26–27 k · 28 gp · 29 sp · 30 fp · 31 ra. Fast check: $t0 = 8, $s0 = 16, $ra = 31.

2. Memory: bytes, words, and "×4"

Every instruction is 32 bits, and memory is byte-addressed. So one word takes 4 addresses, and words sit 4 bytes apart. That is why the PC moves by 4, and why array element A[8] is at offset 8 × 4 = 32.

In MARS: the program (.text) starts at address 0x00400000, data (.data) starts at 0x10010000, and $sp starts at 0x7FFFEFFC.

3. The three instruction formats

All three formats put the opcode in the top 6 bits, and put rs and rt in the same place. That regularity makes the decoder simple and fast.

FormatUsed forWritten asExamples
RMaths/logic on registers, shifts, jrop rd, rs, rtadd, sub, and, or, slt, sll, jr
IConstants, memory, branchesop rt, rs, imm · op rt, imm(rs) · op rs, rt, labeladdi, lw, sw, beq, bne, slti, lui
JFar jumpsop labelj, jal

R-type: op(6) rs(5) rt(5) rd(5) shamt(5) funct(6)

op is 0 for every R-type. The funct field chooses the operation. The result goes into rd.

The opcode alone picks the instruction. rt is usually the destination (for addi, lw, slti…). For sw, rt is the value to store. For branches, rs and rt are the two things compared.

Sign-extend or zero-extend?

The 16-bit immediate must be widened to 32 bits. Most instructions (addi, lw, sw, beq, slti) sign-extend it, so the range is −32768 to +32767. The logic ones (andi, ori) zero-extend it (fill with 0s), range 0 to 65535. It is the same idea as lb (sign-extends a byte) vs lbu (zero-extends it) from class.

Constants bigger than 16 bits need two instructions: lui loads the upper 16 bits, then ori fills in the lower 16. Example: lui $t0, 0x1001 then ori $t0, $t0, 0x0000 makes $t0 = 0x10010000. MARS's la (load address) pseudo-instruction does exactly this.

J-type: op(6) address(26)

j (op 0x02) and jal (op 0x03) store a 26-bit address. The CPU builds the 32-bit target like this:

Target = { PC+4 [31:28] , address , 00 }Take the top 4 bits of PC+4, then the 26-bit field, then two 0 bits (every instruction address is a multiple of 4). { } means "join the bits together".

So j can only reach addresses in the same 256 MB block as PC+4 (same top 4 bits). To jump anywhere, use jr with a full 32-bit register.

4. Worked encodings

Encoding 1: add $t0, $s1, $s2 (R-type)

  1. Map the operands. Written add rd, rs, rt, so rd = $t0 = 8, rs = $s1 = 17, rt = $s2 = 18.
  2. Fill the fields. op = 0, rs = 17, rt = 18, rd = 8, shamt = 0, funct = 32 (0x20).
  3. Write each field in binary, at its width. 000000 10001 10010 01000 00000 100000
  4. Regroup into 4s. 0000 0010 0011 0010 0100 0000 0010 0000
  5. Each group is one hex digit: 0x02324020.

Encoding 2: lw $t0, 32($s3) (I-type)

  1. Map. Written lw rt, imm(rs): rt = $t0 = 8 (destination), rs = $s3 = 19 (base), imm = 32.
  2. Fields. op = 35 (0x23), rs = 19, rt = 8, imm = 32.
  3. Binary. 100011 10011 01000 0000000000100000
  4. Groups of 4. 1000 1110 0110 1000 0000 0000 0010 0000
  5. Hex: 0x8E680020.

Encoding 3: addi $t0, $t0, -1 (negative immediate)

  1. Fields. op = 8, rs = 8, rt = 8, imm = −1.
  2. −1 in 16-bit two's complement is 1111 1111 1111 1111 = 0xFFFF.
  3. Binary. 001000 01000 01000 1111111111111111 → 0010 0001 0000 1000 1111 1111 1111 1111
  4. Hex: 0x2108FFFF. At run time the CPU sign-extends FFFF to FFFFFFFF (−1).

Encoding 4: sll $t1, $s1, 2 (shift)

Written sll rd, rt, shamt. So rs = 0, rt = $s1 = 17, rd = $t1 = 9, shamt = 2, funct = 0.
000000 00000 10001 01001 00010 000000 → 0x00114880. Watch out: the shifted register goes in rt, not rs.

5. Branch offsets (beq / bne)

A branch does not store the full target address. It stores how many instructions to jump, counted from PC + 4 (the instruction after the branch). The count can be negative (jump backwards).

offset = (Target − (PC + 4)) ÷ 4   ⇔   Target = PC + 4 + offset × 4PC = address of the branch itself. The offset is a signed 16-bit number of instructions.
AddressCodeMachine codeNote
0x00400000loop: beq $t0, $zero, exit0x11000002(0x0040000C − 0x00400004) ÷ 4 = 2
0x00400004addi $t0, $t0, -10x2108FFFFskipped 1st
0x00400008j loop0x08100000skipped 2nd; address field 0x0100000
0x0040000Cexit: …branch target

beq decoded: op 4 = 000100, rs = $t0 = 8 = 01000, rt = $zero = 00000, offset = 2 → 0001 0001 0000 0000 0000 0000 0000 0010 = 0x11000002.

Backward example: a bne $s3, $s4, loop at 0x0040002C with loop at 0x00400000: offset = (0x00400000 − 0x00400030) ÷ 4 = −48 ÷ 4 = −12 = 0xFFF4. Machine code 0x1674FFF4.

Why count in instructions?

Targets are always multiples of 4, so storing "÷ 4" gives 4× the reach: ±32768 instructions (about ±128 KB) instead of ±32 KB.

6. Decoding: hex back to an instruction

  1. Hex → binaryWrite 4 bits per hex digit.
  2. Read opTop 6 bits. 0 means R-type; 2 or 3 means J-type; anything else is I-type.
  3. Split fieldsUse that format's layout.
  4. Look upfunct (R) or op (I/J); register numbers → names.
  5. Write itIn the written order (R: rd, rs, rt).

Example: decode 0x01098022

  1. 0000 0001 0000 1001 1000 0000 0010 0010
  2. op = 000000 → R-type. Split: 000000 | 01000 | 01001 | 10000 | 00000 | 100010
  3. rs = 8 ($t0), rt = 9 ($t1), rd = 16 ($s0), shamt = 0, funct = 34 = 0x22 → sub
  4. Answer: sub $s0, $t0, $t1

Common mistakes & exam traps

Slips that cost marks
  • Field order ≠ written order. You write add rd, rs, rt, but the bits are ordered rs rt rd.
  • In lw/addi, the destination is rt, not rd (I-type has no rd).
  • In sll, the source register goes in rt and rs = 0. In jr, the register goes in rs.
  • Branch offsets are counted from PC + 4, and in instructions, not bytes.
  • Negative immediates: write the 16-bit two's complement (−1 = FFFF, −8 = FFF8). Don't write 32 bits into a 16-bit field.
  • Using decimal where hex is expected: funct for add is 32 decimal = 0x20.
  • A J-type target keeps the top 4 bits of PC + 4 and adds two 0s at the bottom.
  • Register numbers: $t0 is 8 (not 0), $s0 is 16, $sp is 29, $ra is 31.

Practice

Encode sw $t0, 48($s3) in hex.

I-type: op = 43 (0x2B), rs = 19 ($s3), rt = 8 ($t0), imm = 48.
101011 10011 01000 0000000000110000 → 1010 1110 0110 1000 0000 0000 0011 0000 = 0xAE680030.

op = 8, rs = rt = 29 (11101), imm = −8 = 0xFFF8.
001000 11101 11101 1111111111111000 → 0x23BDFFF8.

Encode slt $t1, $t0, $s1 in hex.

R-type: rs = 8, rt = 17, rd = 9, shamt = 0, funct = 42 (0x2A).
000000 01000 10001 01001 00000 101010 → 0000 0001 0001 0001 0100 1000 0010 1010 = 0x0111482A.

Decode 0x1674FFF4. If it sits at address 0x0040002C, where does it jump?

000101 10011 10100 1111111111110100: op 5 = bne, rs = 19 ($s3), rt = 20 ($s4), offset = −12.
bne $s3, $s4, …. Target = 0x0040002C + 4 + (−12 × 4) = 0x00400030 − 0x30 = 0x00400000.

A jal func has the address field 0x0100012 and sits at 0x0040001C. What is the target, and what goes into $ra?

Target = {0000, 0x0100012, 00} = 0x0100012 × 4 = 0x00400048. $ra = PC + 4 = 0x00400020. (The factorial program on the functions page has exactly these numbers in MARS.)

Why do andi/ori zero-extend but addi sign-extends?

Logic operations treat the constant as a bit pattern (a mask), so the upper bits should be 0. addi does arithmetic, so a negative constant must stay negative, which needs sign extension.

How many bits hold a register number, and why?

5 bits, because 2⁵ = 32 registers.

What 32-bit value does lui $t0, 0x1001 put in $t0?

0x10010000: the immediate goes into the upper 16 bits and the lower 16 bits are 0. (That is the start of MARS's data segment.)
