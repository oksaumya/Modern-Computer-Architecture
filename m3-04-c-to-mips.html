C to MIPS: arithmetic, arrays, if-else and loops

A compiler turns each line of a high-level language (like C) into a few simple MIPS instructions. There are only a handful of patterns to learn: maths → register ops, array element → shift, add, load, if → branch on the opposite condition, loop → branch at the top, jump back at the bottom.

Think of it like this: a recipe says "if the dough is sticky, add flour; otherwise, knead". A very literal helper can only do "go to step N" and "if X, go to step N". So you rewrite the recipe: "Step 1: if the dough is not sticky, go to step 3. Step 2: add flour, go to step 4. Step 3: knead. Step 4: …". That rewrite is exactly what translating C into MIPS is.

Key terms

Variable
A named box that holds a value, e.g. i. In MIPS we keep it in a register.
Label
A name followed by a colon, like Loop:. It marks an address that branches and jumps can go to.
Branch
A conditional go-to: beq (go if equal) or bne (go if not equal).
Jump
An unconditional go-to: j Label always goes.
Fall through
When a branch is not taken, the CPU simply runs the next line.
Base address
The memory address of an array's first element, A[0].
Offset
How many bytes past the base address to look. For A[i] it is 4 × i.
Syscall
A request to the system (MARS) to do I/O, e.g. print a number. The request number goes in $v0.

0. C in 5 minutes (no coding knowledge needed)

C is a programming language. You don't need to write C. You only need to read these few pieces, so you can translate them.

Registers we will use

By convention, C variables go in the saved registers $s0–$s7, and scratch results go in the temporaries $t0–$t9. $zero always holds 0. Full table: MIPS registers & formats.

1. Arithmetic

C: f = (g + h) - (i + j); → "add g and h; add i and j; subtract the second from the first; store the result in f."
Variables f, g, h, i, j are in $s0, $s1, $s2, $s3, $s4.

mips · arithmeticcode → what it means
add $t0, $s1, $s2$t0 = g + h. MIPS adds only two things at a time, so keep the part-result in a temporary.
add $t1, $s3, $s4$t1 = i + j
sub $s0, $t0, $t1f = $t0 − $t1. The first register after the name is always the destination.

Check with g = 10, h = 7, i = 4, j = 2: (10 + 7) − (4 + 2) = 11. MARS prints 11.

Adding a constant uses addi: f = g + 5; → addi $s0, $s1, 5. There is no subi; use a negative constant: addi $s0, $s1, -5.

2. Arrays

Constant index: A[8]

Each int is 4 bytes, so A[8] is 8 × 4 = 32 bytes after the start. The base address of A is in $s3.

C: g = h + A[8]; → "take element 8 of A, add h, store in g". (g in $s1, h in $s2.)

mips · g = h + A[8]code → what it means
lw $t0, 32($s3)Load word: $t0 = memory[$s3 + 32] = A[8]. Maths can't use memory directly, so load it first.
add $s1, $s2, $t0g = h + A[8]

C: A[12] = h + A[8]; → "work out h + A[8] and store it into element 12".

mips · A[12] = h + A[8]code → what it means
lw $t0, 32($s3)$t0 = A[8]
add $t0, $s2, $t0$t0 = h + A[8]
sw $t0, 48($s3)Store word: memory[$s3 + 48] = $t0. 12 × 4 = 48, so this is A[12].

Variable index: A[i]

Now the offset is 4 × i, which is only known at run time. Compute the address in three steps. Here i is in $s1 and the base of A is in $s6.

mips · $t0 = A[i]code → what it means
sll $t1, $s1, 2Shift left by 2 = multiply by 4. $t1 = 4 × i (the offset in bytes).
add $t1, $t1, $s6$t1 = base + 4 × i = the address of A[i].
lw $t0, 0($t1)$t0 = memory[that address] = A[i].
Why shift instead of multiply?

Shifting a binary number left by 1 doubles it; by 2 multiplies by 4. For example, 3 = 0011 → 1100 = 12. A shift is just wiring, so it is much cheaper than a multiplier.

Common array bug

Writing lw $t0, $s1($s6) is illegal: the offset must be a constant. And forgetting the sll reads byte i instead of element i.

3. if / else

C: if (i == j) f = g + h; else f = g - h; → "If i equals j, set f to g + h. Otherwise, set f to g − h." (f..j in $s0..$s4.)

mips · if / elsecode → what it means
bne $s3, $s4, ElseIf i ≠ j, the "then" part must be skipped: go to Else. (Test the opposite of i == j.)
add $s0, $s1, $s2Then-part: f = g + h. We only get here when i == j.
j ExitSkip the else-part. Without this, both parts would run.
Else: sub $s0, $s1, $s2Else-part: f = g − h.
Exit: # …next statementBoth paths meet here. # starts a comment in MIPS.
Rule: branch on the opposite condition

The code under the if sits right after the branch, so we want to fall through when the condition is true, and branch away when it is false. So == becomes bne, and != becomes beq. An if with no else needs no j: branch straight to Exit.

4. Less-than and friends: slt

MIPS has only two real branches (beq, bne). For <, >, ≤, ≥ we first use slt ("set on less than"):

slt $t0, a, b  →  $t0 = 1 if a < b, else 0slti $t0, a, 10 does the same with a constant. Then test $t0 against $zero with beq/bne.
To jump to L when…MIPSWhy
a < bslt $t0, a, b
bne $t0, $zero, L		$t0 is 1 exactly when a < b
a >= bslt $t0, a, b
beq $t0, $zero, L		"not less than" = "greater or equal"
a > bslt $t0, b, a
bne $t0, $zero, L		a > b is the same as b < a (swap)
a <= bslt $t0, b, a
beq $t0, $zero, L		"not (b < a)"

Example: if (g < h) f = h; else f = g; ("f becomes the bigger of g and h"). We must skip the then-part when g ≥ h:

mips · if (g < h)code → what it means
slt $t0, $s1, $s2$t0 = 1 if g < h
beq $t0, $zero, ElseIf $t0 is 0 (g ≥ h, the opposite), go to Else.
add $s0, $s2, $zerof = h (adding 0 just copies)
j Exit
Else: add $s0, $s1, $zerof = g
Exit:

MARS also accepts pseudo-instructions blt, bge, bgt, ble. They are not real MIPS instructions: the assembler expands each into slt + beq/bne using $at. For example, blt $t0, $t1, L becomes slt $at, $t0, $t1 + bne $at, $zero, L.

5. while loop

C: while (save[i] == k) i += 1; → "As long as element i of the array save equals k, add 1 to i." It finds the first element that is not k.
i is in $s3, k in $s5, and the base of save in $s6.

mips · while (save[i] == k) i += 1;code → what it means
Loop: sll $t1, $s3, 2$t1 = 4 × i
add $t1, $t1, $s6$t1 = address of save[i]
lw $t0, 0($t1)$t0 = save[i]
bne $t0, $s5, ExitOpposite of ==: if save[i] ≠ k, leave the loop.
addi $s3, $s3, 1Loop body: i = i + 1
j LoopGo back and test again.
Exit:Continue with the rest of the program.

Trace: save = {7, 7, 7, 3, 7}, k = 7, i starts at 0

Round 1: i = 0 → $t1 = 0 + base → save[0] = 7. Is 7 ≠ 7? No, so don't branch. i becomes 1. j Loop.

Round 2: i = 1 → $t1 = base + 4 → save[1] = 7. Equal, so i becomes 2. j Loop.

Round 3: i = 2 → $t1 = base + 8 → save[2] = 7. Equal, so i becomes 3. j Loop.

Round 4: i = 3 → $t1 = base + 12 → save[3] = 3. Is 3 ≠ 7? Yes, so bne jumps to Exit.

Done: $s3 = 3, the index of the first element that is not 7. The loop body ran 3 times; the test ran 4 times. (Tested in MARS.)

6. for loop

C: for (i = 0; i < n; i++) sum = sum + A[i];
Plain English: "Start i at 0. While i is less than n: add element i of A to sum, then add 1 to i." So it adds up the first n elements.

A for loop is just a while loop with its three parts spread out:

for

for (init; test; step) body;

same thing as while

init;
while (test) { body; step; }

  1. initli $t0, 0 (i = 0), before the label
  2. Loop: testslt + beq … done (leave when i ≥ n)
  3. bodysll · add · lw · add
  4. stepaddi $t0, $t0, 1
  5. backj Loop

The full, runnable version is the array-sum program below.

7. Lab 3A: complete MARS programs

A MARS program has two parts. .data holds your values (arrays, text). .text holds the instructions. Output and input use syscall: put the service number in $v0, put the argument in $a0, then write syscall.

$v0ServiceArgument / result
1print intthe int in $a0
4print stringaddress of the text in $a0
5read intthe typed number comes back in $v0
10exitstop the program

A few MARS pseudo-instructions make programs easier to write: li $t0, 5 (load immediate: $t0 = 5), la $a0, msg (load the address of label msg), move $a0, $s2 (copy $s2 into $a0).

Program 1: array sum

C idea: sum = 0; for (i = 0; i < n; i++) sum = sum + arr[i]; print sum;

  1. Setupbase, n, sum = 0, i = 0
  2. Testi < n? If not, go to done
  3. Bodysum += arr[i]
  4. Stepi++ and jump back
  5. doneprint "Sum = " and sum, exit
mips · array_sum.asmcode → what it means
.dataStart of the data section.
arr: .word 5, 12, -3, 8, 20An array of five 32-bit ints. arr labels the address of arr[0].
n: .word 5The number of elements.
msg: .asciiz "Sum = "Text ending with a 0 byte (that is what the z means).
.textStart of the code section.
.globl mainMake the label main visible as the start point.
main: la $s0, arr$s0 = base address of arr
lw $s1, n$s1 = n = 5 (load the word stored at label n)
li $s2, 0sum = 0
li $t0, 0i = 0
loop: slt $t1, $t0, $s1$t1 = 1 if i < n
beq $t1, $zero, doneIf not (i ≥ n), leave the loop.
sll $t2, $t0, 2$t2 = 4 × i
add $t2, $t2, $s0$t2 = address of arr[i]
lw $t3, 0($t2)$t3 = arr[i]
add $s2, $s2, $t3sum = sum + arr[i]
addi $t0, $t0, 1i = i + 1
j loopBack to the test.
done: li $v0, 4Service 4 = print string
la $a0, msg…the text at msg
syscallPrints Sum =
li $v0, 1Service 1 = print int
move $a0, $s2…the value of sum
syscallPrints 42
li $v0, 10Service 10 = exit
syscallProgram ends.

Output: Sum = 42 (5 + 12 − 3 + 8 + 20 = 42).

Program 2: find the maximum

C idea: max = arr[0]; for (i = 1; i < n; i++) { if (max < arr[i]) max = arr[i]; } print max;
Plain English: "Guess that the first element is the biggest. Look at every other element; if it is bigger than the current guess, it becomes the new guess."

  1. Setupmax = arr[0], i = 1
  2. Testi < n? If not, go to done
  3. Load$t3 = arr[i]
  4. Comparemax < arr[i]? If not, go to skip
  5. Updatemax = arr[i]
  6. skipi++ and jump back
  7. doneprint max, exit
mips · find_max.asmcode → what it means
.data
arr: .word 5, 12, -3, 27, 20, 9Six values; the biggest (27) is in the middle.
n: .word 6
msg: .asciiz "Max = "
.text
.globl main
main: la $s0, arr$s0 = base address
lw $s1, n$s1 = n
lw $s2, 0($s0)max = arr[0]
li $t0, 1i = 1 (arr[0] is already counted)
loop: slt $t1, $t0, $s1i < n ?
beq $t1, $zero, doneNo → finished.
sll $t2, $t0, 2$t2 = 4 × i
add $t2, $t2, $s0$t2 = address of arr[i]
lw $t3, 0($t2)$t3 = arr[i]
slt $t4, $s2, $t3$t4 = 1 if max < arr[i]
beq $t4, $zero, skipNot bigger → don't update (opposite condition).

Output: Max = 27. slt compares signed numbers, so −3 is correctly treated as smaller.

Want the user to type the numbers?

Use service 5: li $v0, 5 then syscall. The typed int arrives in $v0; copy it with move $s1, $v0 before the next syscall overwrites $v0.

8. MARS how-to

  1. EditFile → New, type the program, save as .asm
  2. Assemble (F3)Converts to machine code. Errors show in the Messages pane.
  3. Run (F5)Runs to the end. Output appears in Run I/O.
  4. Step (F7)Runs one instruction. The next one is highlighted. (F8 steps back; F12 resets.)
  5. WatchRegisters pane and Data Segment pane
  • Registers pane (right side): all 32 registers plus PC, HI and LO. The one that just changed is highlighted. Watch $t0 (i) and $s2 (sum) climb as you step.
  • Text Segment (Execute tab, top): each instruction's address, machine code (hex), the real ("Basic") instruction, and your source line.
  • Data Segment (Execute tab, bottom): memory from 0x10010000. Your arr values appear there, 4 bytes each. Untick "Hexadecimal Values" to see them in decimal.
  • Set a breakpoint by ticking the "Bkpt" box next to a line; F5 then stops there.

Common mistakes & exam traps

Slips that cost marks
  • Branching on the same condition as the C code. Use the opposite, so the "then" code can fall through.
  • Forgetting j Exit after the then-part, so the else-part runs too.
  • Array index without ×4: A[8] is 32($s3), not 8($s3).
  • Mixing up lw and sw: lw reads memory into a register; sw writes a register into memory. Both write the register first.
  • Forgetting the loop's j Loop, or putting the i++ before the body in a for loop.
  • Using = vs == wrongly when reading C: = stores, == compares.
  • Loading into $v0 for a syscall and then losing a value you still needed there.
  • blt/bgt/li/la/move are pseudo-instructions. In an exam asking for "real MIPS instructions", expand them.

What does blt $t0, $t1, L become in real instructions?
