C to MIPS: conditionals, loops and arrays

A compiler turns each line of a high-level language (like C) into a few simple MIPS instructions. L12 calls it the translation mindset: variables become registers, structure becomes labels and branches, and conditions become compare + branch. One trick runs through everything — branch AWAY on the opposite condition.

Think of it like this: a recipe says "if the dough is sticky, add flour; otherwise, knead". A very literal helper can only do "go to step N" and "if X, go to step N". So you rewrite the recipe: "Step 1: if the dough is not sticky, go to step 3. Step 2: add flour, go to step 4. Step 3: knead. Step 4: …". That rewrite is exactly what translating C into MIPS is.

Key terms

Variable
A named box that holds a value, e.g. i. In MIPS we keep it in a register.
Label
A name followed by a colon, like loop:. It marks an address that branches and jumps can go to.
Branch
A conditional go-to: beq (go if equal) or bne (go if not equal).
Jump
An unconditional go-to: j Label always goes.
Fall through
When a branch is not taken, the CPU simply runs the next line.
Base address
The memory address of an array's first element, arr[0]. la puts it in a register.
Offset
How many bytes past the base address to look. For arr[i] it is 4 × i.
Stride
How far apart consecutive elements are. 4 bytes for a word array, 1 byte for a byte array.
Accumulator
The one register the loop builds up: a sum, a count, a product, a running best.
Identity
The value an accumulator must start at: 0 for a sum, 1 for a product, arr[0] for a maximum.
Sentinel
A special input value (usually 0) that means "stop reading".
Pseudo-instruction
Something the assembler accepts but the hardware does not have, e.g. blt, li, move. MARS expands each into real instructions.
HI / LO
Two extra registers that mult and div write. mflo and mfhi copy them into a normal register.
Syscall
A request to the system (MARS) to do I/O, e.g. print a number. The request number goes in $v0.

Registers we will use

The lectures put variables in temporaries $t0–$t9 (L12 uses $t0=a, $t1=b, $t2=c). Lab 12 goes further and fixes a register plan that every array program on this page follows:

RegisterRoleWhy
$t0base, then the walking pointerla once; addi $t0, $t0, 4 per pass
$t1n, the element countthe loop bound; from lw n or syscall 5
$t2accumulator / count / maxthe one value the loop produces
$t3i, the countercompared with $t1 at the top
$t4the loaded elementlw $t4, 0($t0)
$t5scratch addresssecond pointer, or sll/add result
$v0, $a0syscall onlyoverwritten by every syscall setup

Naming the roles first (base, n, accumulator, i) makes every array program the same program. Textbook examples often use the saved registers $s0–$s7 instead; both are fine, and the full table is on MIPS registers & formats.

1. The translation mindset

L12, slide 4. High-level code is structured; assembly is flat. Translation means flattening structure into labels and branches.

  1. Variables → registersEach active C variable lives in a register ($t/$s). The compiler assigns them.
  2. Structure → labels + branchesif, else, loop bodies become labelled blocks; control flow becomes jumps between them.
  3. Conditions → compare + branchA test like a > b becomes "set a flag, then branch on it" — usually slt then bne.
  4. Reverse the conditionif (cond) do X → "if NOT cond, skip X". You branch AWAY on the opposite test.
Keep "reverse the condition" in mind

It is the trick behind almost every if and loop translation on this page. The code you want to run sits right after the branch, so you want to fall through when the condition holds, and branch away when it fails.

2. The branch toolkit

MIPS keeps it minimal: two branches and one set-less-than. Everything else is built from these.

InstructionWhat it doesReal?
beq $a, $b, LBranch to L if $a == $b (branch if equal).real
bne $a, $b, LBranch to L if $a != $b (branch if not equal).real
slt $d, $a, $bSet $d = 1 if $a < $b, else 0 (set-less-than). It does not branch.real
j LUnconditional jump to label L.real
b LBranch always. The assembler writes beq $zero, $zero, L.pseudo
There is no "branch if less-than" instruction

You build it: slt to set a flag, then bne (or beq) against $zero.

Every comparison, written out (Lab 13, slide 7)

This table is the one to memorise. The left column is the condition you want to branch on; the middle column is what MARS actually assembles.

Branch if…Real instructionsPseudo name
a == bbeq a, b, L1 instruction
a != bbne a, b, L1 instruction
a < bslt $at, a, b ; bne $at, $zero, Lblt
a >= bslt $at, a, b ; beq $at, $zero, Lbge
a > bslt $at, b, a ; bne $at, $zero, Lbgt
a <= bslt $at, b, a ; beq $at, $zero, Lble
a < 5slti $at, a, 5 ; bne $at, $zero, Limmediate form
a == 0beq a, $zero, L$zero is free

Two shapes cover everything. Equality: beq/bne compare two registers directly. Order: slt writes 1 or 0 into a register; beq/bne then test that register against $zero.

The polarity decides the branchbne $at, $zero, L jumps when the condition holds. beq $at, $zero, L jumps when it fails. Loops branch out on the failing test.
Two things to notice about $at
  • bge costs two real instructions. Count them when you count cycles, and expand them when an exam asks for "real MIPS instructions". MARS's Text Segment pane shows you exactly the expansion.
  • $at is the assembler's own scratch register. Every pseudo-branch clobbers it. So do not keep your own value in $at — use $t8/$t9 if you need another temporary.

slt treats bit 31 as a sign; sltu treats it as a big magnitude bit. Use sltu for addresses and lengths, slt for int values. The pseudo-branches blt/bge/bgt/ble are all signed.

What a branch looks like in bits

A branch stores a relative offset, not an address. Lab 12 and Lab 13 use the same Sheet-K formula:

BTA = PC + 4 + signext(imm) × 4The 16-bit field counts instructions, measured from the instruction after the branch.

Forward (Lab 12)

0x00400020: beq $t0, $t1, skip
skip is at 0x0040002C.
0x0040002C − 0x00400024 = 8 bytes = imm 2.
Encoding: 0x11090002.

Backward (Lab 13)

0x00400030: bne $t0, $t5, loop
loop is at 0x00400020.
0x00400020 − 0x00400034 = −20 bytes = imm −5 = 0xFFFB.
Encoding: 0x150DFFFB.

Same 16-bit field, +2 one way and −5 the other. It is sign-extended, then multiplied by 4. Every loop's closing branch is a negative number. Reach: 16-bit signed × 4 ≈ ±128 KiB for branches; j keeps 26 bits, a 256 MiB region.

3. Arithmetic (recap)

Textbook support Not re-taught in L12, but you need it for everything below.

C: f = (g + h) - (i + j); → "add g and h; add i and j; subtract the second from the first; store the result in f."
Here f, g, h, i, j are in $s0, $s1, $s2, $s3, $s4.

mips · arithmeticcode → what it means
add $t0, $s1, $s2$t0 = g + h. MIPS adds only two things at a time, so keep the part-result in a temporary.
add $t1, $s3, $s4$t1 = i + j
sub $s0, $t0, $t1f = $t0 − $t1. The first register after the name is always the destination.

Check with g = 10, h = 7, i = 4, j = 2: (10 + 7) − (4 + 2) = 11. MARS prints 11.

Adding a constant uses addi: f = g + 5; → addi $s0, $s1, 5. There is no subi; use a negative constant: addi $s0, $s1, -5.

4. if and if / else

A one-sided if (L12, slide 7)

C: if (a == b) { c = a + b; } → "If a equals b, set c to a + b. Then carry on either way."
L12's register assumption: $t0 = a, $t1 = b, $t2 = c.

mips · if (a == b) c = a + b;code → what it means
bne $t0, $t1, SkipC says "if EQUAL, do the body". MIPS says "if NOT equal, skip the body". Reversed condition, same result.
add $t2, $t0, $t1The body. We only reach it by falling through, i.e. when a == b.
Skip: # continue…Both paths meet here. # starts a comment in MIPS.

Verified: a = b = 7 → c = 14. a = 7, b = 3 → c unchanged.

Two-sided: if / else (L12, slide 8)

C: if (a == b) { c = 1; } else { c = 0; } → "If a equals b, set c to 1; otherwise set c to 0."

mips · if / elsecode → what it means
bne $t0, $t1, ElseOpposite of ==: if a ≠ b, go to the else-block.
li $t2, 1Then-block: c = 1. (li = load immediate, "put this constant in the register".)
j DoneEssential. Without it the then-block falls straight through into the else-block and both run.
Else: li $t2, 0Else-block: c = 0.
Done:The two paths merge. Everything after this runs either way.

Verified: a = b = 4 → 1. a = 4, b = 5 → 0.

5. Ordering: the slt idiom

For <, >, <=, >= there is no direct branch — you set a flag with slt, then branch on it.

C: if (a < b) { /* body */ }

mips · if (a < b)code → what it means
slt $t3, $t0, $t1$t3 = 1 if a < b, else 0. This is only a flag; nothing has branched yet.
beq $t3, $zero, SkipIf the flag is 0 (meaning a ≥ b, the opposite), skip the body.
# body (runs when a < b)$t3 = 1 means a < b, so beq … $zero is false and we fall into the body.
Skip:Continue.

Worked: max of two (L12, slide 10)

C: if (a > b) c = a; else c = b; → "c becomes the bigger of a and b."

mips · max of two ($t0=a, $t1=b, $t2=c)code → what it means
slt $t3, $t1, $t0Operands flipped on purpose. a > b is the same question as b < a, and slt only knows "<". $t3 = 1 when a > b.
beq $t3, $zero, ElseFlag 0 → a is not bigger → take the else path.
move $t2, $t0c = a. (move is a pseudo-instruction; the assembler writes add $t2, $t0, $zero.)
j DoneSkip the else-block.
Else: move $t2, $t1c = b.
Done:Merge point.

Verified: (12, 5) → 12 · (5, 12) → 12 · (7, 7) → 7 · (−4, −9) → −4. slt compares signed numbers, so −4 is correctly bigger than −9.

Flip the operands to turn > into <

Only one ordering instruction exists. a > b ⇔ b < a; a <= b ⇔ not (b < a). Between flipping the operands and flipping beq↔bne, you can express all four orderings.

6. else-if chains, && and ||

&& and ||: two tests, one target

OperatorShape
A && Bbranch to skip if A fails; branch to skip if B fails; else fall into the block

mips · if (x >= 10 && x <= 20) count++;code → what it means
slti $t8, $t0, 10$t8 = 1 if x < 10 — that is the failure of the first test.
bne $t8, $zero, skipFirst test failed → the whole && is false, so skip.

li $t9, 100

skip:

Verified: the && version counts for x = 10, 15, 20 and not for 9 or 21. The || version fires for −1 and 101, not for 0 or 100.

Short-circuit for free

If A already decides the answer, B is never evaluated — the branch jumped past it. That is why C can safely write if (p != 0 && p->x > 3): when p is 0 the second half never runs.

Lab 13 also notes the compiler's trick: a range test 10 ≤ x ≤ 20 becomes a single unsigned compare of x − 10 < 11 (sltiu), because a negative x − 10 reads as a huge unsigned number and fails too.

Slide note: use $t8, not $at

The Lab 13 slide writes slti $at, $t0, 10 and then uses bgt. That works here, but bgt is a pseudo-instruction that itself overwrites $at. Keeping your own values out of $at avoids a whole class of mystery bugs, so the version above uses $t8.

7. Loops

A loop is a conditional with a branch back to the top: label → test → body → update → jump back.

The while loop (L12, slide 13)

C: while (i < n) { sum += i; i++; } → "While i is less than n: add i onto sum, then add 1 to i."
Registers: $t0 = i, $t1 = n, $s0 = sum.

Slide correction

L12 slide 13 writes the exit test as blt $t1, $t0, End. That reads "branch out when n < i", so the loop keeps going while i <= n — one pass too many. With i = 0 and n = 5 it computes 0+1+2+3+4+5 = 15 instead of the C answer 10. (Tested.)

The exit test must fire when the loop condition i < n fails, i.e. when i >= n. Write bge $t0, $t1, End, which is exactly the slt + beq the slide's own caption describes. The corrected version is below; everything else on the slide is right.

mips · while (i < n) { sum += i; i++; } — correctedcode → what it means
Loop: bge $t0, $t1, EndExit test, branching on the opposite of i < n. Expands to slt $at,$t0,$t1 + beq $at,$zero,End.
add $s0, $s0, $t0Body: sum += i.
addi $t0, $t0, 1Update: i++.
j LoopGo back and test again.
End:Continue with the rest of the program.

Verified: i = 0, n = 5 → sum = 10. The test runs n+1 = 6 times; the body runs 5 times.

The for loop (L12, slide 14)

C: for (i = 0; i < 10; i++) { sum += i; } → "Start i at 0. While i is less than 10: add i onto sum, then add 1 to i."

for

for (init; test; step) body;

same thing as while

init;
while (test) { body; step; }

mips · for (i = 0; i < 10; i++) sum += i;code → what it means
li $t0, 0init — before the label, so it runs once.
Loop: slti $t2, $t0, 10test — $t2 = 1 if i < 10. slti compares against a constant, so 10 needs no register.
beq $t2, $zero, EndFlag 0 (i ≥ 10) → leave the loop.
add $s0, $s0, $t0body — sum += i.
addi $t0, $t0, 1step — i++, placed just before the jump back.
j Loop
End:

Verified: prints 45 (0+1+…+9). Map the four for-parts: init before the label, condition at the top, body in the middle, increment before the jump-back.

A do-while runs the body at least once

So it is wrong for n = 0. Only use the bottom-tested shape when you know the loop runs at least one pass. Verified: all three shapes sum 1..5 to 15.

The counted-loop skeleton (Lab 12, slide 14)

This is the shape for the rest of the page. Learn it so you can write it from memory.

mips · counted-loop skeletoncode → what it means
# INIT i = 0, ptr = base, accumulator = identityEverything that must happen once, before the label.
loop: bge $t3, $t1, doneTEST: i ≥ n? Yes → leave. Branches on the opposite of "i < n".
# BODY work on *ptrLoad the element, use it.
addi $t0, $t0, 4UPDATE the pointer: one word forward = 4 bytes.
addi $t3, $t3, 1UPDATE the counter: one element forward = 1.
j loopJUMP BACK to the test.
done:Print, exit — the loop must fall through to here.
Four places loop bugs live
  1. init — accumulator or counter not zeroed (or a product not started at 1).
  2. test — bge is right; bgt or ble is off by one.
  3. update — the pointer strides by 4, not 1. The counter strides by 1.
  4. exit — done: must fall through to the print.

continue and break: labels, nothing more

C: count the multiples of 3 in 1..20 — "for each i, if i is not a multiple of 3, continue to the next i; otherwise count it."

mips · count multiples of 3 in 1..20code → what it means

Verified: $t2 = 6.

Where the update sits decides whether continue works

The pointer/counter update must sit after the next: label. Put it before, and continue skips the update — an infinite loop. A parity test is the same idea without div: andi $t4, $t3, 1.

Writing into an array, and the bound nobody checks

Arrays are where programs fail: there is no hardware bound check

lw $t2, 20($t0) on a 5-element array reads arr[5], one past the end. It succeeds. MIPS raises no exception; you get whatever word follows arr in .data. An sw there silently corrupts another variable.

Only alignment is checked. lw $t2, 2($t0) raises an address error, because 2 is not a multiple of 4. Reading past the end does not.

The loop bound is the only guard, and it is three things: the value of n, the test (bge, not ble), and the size you gave .space.

Array bug number one

lw $t4, 0($t3) uses the index as an address. For i = 3 that is address 3: not a multiple of 4, so MARS raises an address error. The hardware does no scaling — MIPS has no "base + index×4" addressing mode (x86 and Arm do). You must write the sll yourself.

Also illegal: lw $t0, $t3($t0). The offset must be a constant, never a register.

Why walking in order is fast

One 64-byte cache line holds 16 ints on Intel and AMD cores.

The signed 32-bit maximum is 231 − 1 = 2,147,483,647. 12! fits; 13! does not.

mips · the general signed overflow check after multcode → what it means
mult $t1, $t2The full 64-bit product lands in HI:LO.
mfhi $t5$t5 = the top 32 bits.
mflo $t1$t1 = the bottom 32 bits — the candidate answer.
sra $t6, $t1, 31Arithmetic shift right by 31 copies the sign bit into all 32 bits: 0 for a positive LO, −1 (all ones) for a negative one.
bne $t5, $t6, ovfIf HI is not that sign extension, the product did not fit in 32 bits.

Verified: 100000 × 100000 is flagged; (−3) × (−4) and 1000 × (−1000) are not.

For factorial, HI != 0 is enough

No factorial lands between 231 and 232 (12! < 231, 13! > 232), so a simple bne $t3, $zero, ovf after mfhi $t3 catches it.

mul rd, rs, rt discards HI

The three-operand mul is convenient but it cannot detect overflow — the top half is thrown away. Use mult + mfhi whenever the result might be large.

12. Bug hunt

Both labs run the same drill: find the bug, state the symptom, fix it in one line. The debugging order used all semester: (1) read the symptom, (2) write the trace table, (3) find the first row that differs from what you expect, (4) fix that line only.

Lab 12: five broken array snippets

S1 — first element right, then crash. loop: lw $t4,0($t0) / add $t2,$t2,$t4 / addi $t0,$t0,1 / addi $t3,$t3,1

Stride 1, not 4. The second lw reads B+1, which is not a multiple of 4 → address error.

Fix: addi $t0, $t0, 4

S2 — sums n+1 elements. The loop closes with ble $t3, $t1, loop.

ble keeps looping while i ≤ n, so it runs passes 0…n — one element too many, reading arr[n], which is past the end.

Fix: use blt at the bottom, or move the test to the top as bge $t3,$t1,done.

S3 — prints 0 for arr = {-5, -2, -9}, but −2 is wanted. It starts with li $t2, 0 # max.

The max starts at 0, which is bigger than every element of an all-negative array, so nothing ever beats it.

Fix: lw $t2, 0($t0) first — start at arr[0].

S4 — the sum comes out as arr[0] × n. The loop body is lw / add / addi $t3,$t3,1 / j loop.

The pointer is never advanced: every pass loads arr[0]. The counter moves, the data does not.

Fix: add addi $t0, $t0, 4.

S5 — address error. # arr[i], i in $t3 then lw $t4, 0($t3).

The index is being used as an address: i = 3 means address 3, which is misaligned.

Fix: sll by 2, add the base, then lw.

Lab 13: five broken branch and loop snippets

S1 — the loop body never runs. li $t0,0 / li $t1,10 / loop: ble $t0,$t1,done

The exit test is inverted. i <= n is already true at i = 0, so the loop exits on the first test. The exit branch must fire when the loop condition fails.

Fix: bge $t0, $t1, done.

S2 — the sum is only the first term. loop: bge $t0,$t2,done / add / addi / done: …

No j loop: after one pass control simply falls through into done:.

Fix: add j loop before done:.

S3 — an even number prints "Odd". andi $t1,$t0,1 / bne $t1,$zero,even_l

Branch polarity. bne fires when bit 0 is 1 — that is odd — but it jumps to the even label.

Fix: beq $t1, $zero, even_l.

S4 — 5! prints 1. loop: bgt $t2,$t0,done / mult $t1,$t2 / addi $t2,$t2,1 / j loop

mult without mflo. The product sits in LO; the register $t1 is never updated, so it stays 1.

Fix: mflo $t1 after the mult.

S5 — 5! prints 0. li $t1, 0 # result / li $t2, 2 # i / … / mult $t1,$t2 / mflo $t1

The product is initialised to 0 — the identity of +, not of ×. Every product is then 0.

Fix: li $t1, 1.

13. MARS how-to

A MARS program has two parts. .data holds your values (arrays, text). .text holds the instructions. Output and input use syscall: put the service number in $v0, put the argument in $a0, then write syscall.

$v0ServiceArgument / result
1print intthe int in $a0
4print stringaddress of the text in $a0
5read intthe typed number comes back in $v0
10exitstop the program
11print charthe character code in $a0

A few MARS pseudo-instructions make programs easier to write: li $t0, 5 (load immediate), la $a0, msg (load the address of label msg), move $a0, $t2 (copy), b L (branch always), and the comparison branches blt / bgt / ble / bge.

  1. EditFile → New, type the program, save as .asm
  2. Assemble (F3)Converts to machine code. Errors show in the Messages pane.
  3. Run (F5)Runs to the end. Output appears in Run I/O.
  4. Step (F7)Runs one instruction. The next one is highlighted. (F8 steps back; F12 resets.)
  5. WatchRegisters pane and Data Segment pane
  • Registers pane (right side): all 32 registers plus PC, HI and LO. The one that just changed is highlighted. Watch $t3 (i) and $t2 (sum) climb as you step.
  • Text Segment (Execute tab, top): each instruction's address, machine code (hex), the real ("Basic") instruction, and your source line. This is where you see bge expand into slt + beq.
  • Data Segment (Execute tab, bottom): memory from 0x10010000. Your arr values appear there, 4 bytes each. Untick "Hexadecimal Values" to see them in decimal.
  • Set a breakpoint by ticking the "Bkpt" box next to a line; F5 then stops there.

Common mistakes & exam traps

From L12 slide 30 and both bug hunts
  • Not reversing the condition. if (cond) body → branch AWAY on !cond. Branching on cond itself inverts your logic.
  • Forgetting j Done after the then-block, so the else-block runs too.
  • Wrong array scaling. arr[i] is at base + i×4. Forgetting the ×4 (sll by 2) reads the wrong memory; using the index as the address raises an alignment error.
  • Using blt/bgt when the question says "real MIPS". Base MIPS has no blt. Expand to slt + beq/bne with $zero, and count it as two instructions.
  • Inverted exit test. ble where bge belongs runs one extra pass (or none at all). This is the single most common loop bug — and it is the bug on L12 slide 13.
  • Missing j loop, so the loop runs exactly once.
  • Stride 1 instead of 4, or a pointer that is never advanced.
  • Wrong accumulator identity. Sum must start at 0, product at 1, max at arr[0].
  • mult without mflo — the register never changes. And mul rd,rs,rt cannot detect overflow.
  • Losing $v0. Copy a value out of $v0 immediately after syscall 5; the next syscall setup overwrites it.
  • Keeping your own value in $at. Every pseudo-branch clobbers it.
  • Reading C punctuation wrongly: = stores, == compares.
  • (Lab 14 / next page) Forgetting to save $ra, unbalanced $sp, clobbering an $s register without saving it.

Key takeaways (L12, slide 31)

  1. 01if/else translates to compare-and-branch: use beq/bne, and branch AWAY on the reversed condition.
  2. 02Ordering (< > ≤ ≥) uses the slt idiom — set a flag, then branch on it with beq/bne + $zero.
  3. 03Loops are a label, a condition test at the top, a body, and a j back — while and for share this skeleton.
  4. 04Arrays are base + 4i: sll, add, lw. Nothing checks the bound but your loop test.
  5. 05Every accumulator has an identity, and every mult that might be large needs a HI check.

Practice

Translate if (a == b) { c = a + b; } with $t0=a, $t1=b, $t2=c.

bne $t0, $t1, Skip
add $t2, $t0, $t1
Skip:

Branch on the opposite of ==. No j is needed because there is no else-block.

Translate if (a == b) c = 1; else c = 0;. Show your labels. (L12 homework 1)

bne $t0, $t1, Else
li $t2, 1
j Done
Else: li $t2, 0
Done:

The j Done is what stops the then-block falling into the else-block.

Translate int sum(int n) { int s = 0; for (i = 1; i <= n; i++) s += i; return s; } as a loop. (L12 homework 2)

With n in $t0, s in $t1, i in $t2. The bound is inclusive, so exit on i > n:

li $t1, 0
li $t2, 1
loop: bgt $t2, $t0, done
add $t1, $t1, $t2
addi $t2, $t2, 1
j loop
done:

For n = 10 this gives 55. Compare with "Sum 0 to 9", where the bound is exclusive and the test is bge $t0, $t2, done.

What does bge $t3, $t1, done become in real instructions, and how many cycles does it cost?

slt $at, $t3, $t1 then beq $at, $zero, done. Two real instructions — MARS's Text Segment pane shows exactly this. Count both when you count cycles.

Base = 0x1000. What is the address of arr[5]? And from 0x10010000, arr[6]? (Lab 12 cold call / exit ticket)

arr[5] = 0x1000 + 5×4 = 0x1000 + 20 = 0x1014.
arr[6] = 0x10010000 + 24 = 0x10010018.

Why does the loop add 4 to the pointer, not 1? And why does the pointer end at base + 4n?

Memory is byte-addressable and a word is 4 bytes, so consecutive elements are 4 bytes apart. After n passes the pointer has advanced 4n bytes, landing one past the last element — which is why -4($t0) is the last element and why base + 4n makes a natural end-pointer bound.

lw $t4, 0($t3) with $t3 = 3: what happens?

It tries to read address 3, which is not a multiple of 4 → MARS raises an address error. The index was used as an address; it needed sll $t5,$t3,2 then add $t5,$t5,$t0 first.

Which of the index, pointer and end-pointer copy loops is fastest, and why?

The end-pointer loop: 5 instructions per element versus 8 and 9. It has no counter (the pointer is the counter) and closes with a single real bne instead of a two-instruction bge plus a j. At 93.75 MHz with CPI 1 and 1000 elements: 53.3 µs vs 85.3 and 96.0.

Why must a running maximum start at arr[0] and not 0?

Because 0 beats every element of an all-negative array. On {−5, −2, −9} a max that starts at 0 prints 0; starting at arr[0] correctly prints −2. (0x80000000, the smallest 32-bit int, also works.)

How many ints fit in .space 400? What breaks if n = 150? What if n = 0?

400 bytes ÷ 4 = 100 words. n = 150 writes 200 bytes past the end of the buffer, silently corrupting whatever follows it in .data. n = 0 makes lw $a0, -4($t0) read arr[-1] — the word before the array.

A 64-byte cache line holds how many ints, and what is the hit rate of a cold sequential scan?

64 ÷ 4 = 16 ints. The first access misses and loads the whole line; the next 15 hit. So 1 miss per 16 = 93.75% hits.

Write x >= 10 && x <= 20 in MIPS. (Lab 13 cold call 6)

slti $t8, $t0, 10 (1 if the first test fails)
bne $t8, $zero, skip
li $t9, 20
bgt $t0, $t9, skip (second test fails)
addi $t2, $t2, 1
skip:

Both tests branch to the same skip label; the body is reached only by falling through both.

Which loop shape has the least overhead, and why?

Count-down to zero: 2 instructions of overhead per pass. The bottom test removes the j, and comparing against $zero removes the slt, leaving one real bne. Caveat: like any bottom-tested loop it runs the body at least once, so it is wrong for n = 0.

slt vs sltu on −1 and 1 — what does each give?

slt is signed: −1 < 1 → 1.
sltu is unsigned: 0xFFFFFFFF = 4,294,967,295, which is not less than 1 → 0.
Use sltu for addresses and lengths, slt for int values.

Why does andi $t1, $t0, 1 correctly detect that −3 is odd?

andi keeps only bit 0, and two's complement does not change the low bits of odd numbers: −3 is 0xFFFFFFFD, whose bit 0 is 1. So $t1 = 1 → odd. (Note andi zero-extends its immediate, so the upper bits are masked away cleanly.)

A backward branch whose target is 5 instructions up: what is the immediate?

−5, stored as 0xFFFB. BTA = PC + 4 + signext(imm)×4, so going back 20 bytes from the instruction after the branch needs imm×4 = −20. Example encoding: bne $t0, $t5, loop → 0x150DFFFB.

After mult, where is the product? And what does beq $v0, $zero, done do after syscall 5?

The full 64-bit product is in HI:LO — mflo gets the low 32 bits, mfhi the high 32. No general register is touched.

beq $v0, $zero, done is the sentinel test: the number just typed arrived in $v0, so this leaves the loop when the user types 0.

12! vs 13! in a signed 32-bit word — and why does HI != 0 catch 13!?

12! = 479,001,600 = 0x1C8CFC00, comfortably under 2³¹−1 = 2,147,483,647, so HI = 0.
13! = 6,227,020,800 needs 33 bits: HI = 1, LO = 0x7328CC00 = 1,932,053,504 — a plausible-looking wrong answer.

No factorial lands between 2³¹ and 2³², so for factorial a plain HI != 0 is a complete test. The general signed rule is HI == (LO >> 31 arithmetic), i.e. HI must equal LO's sign extension.

Why is 0! = 1 with no special case in the loop?

Because result is initialised to the multiplicative identity 1 and the counter starts at 2. With n = 0 (or 1) the test bgt $t2, $t0, done is true on the very first check, the body never runs, and 1 is printed. The empty product is 1 by definition.

Where must the update sit for continue to work?

After the next: label that continue jumps to. Put the addi before it and continue skips the update — an infinite loop.

Rewrite for (i = 0; i < n; i++) arr[i] = 0; in MIPS, pointer style.

la $t0, arr
li $t3, 0
loop: bge $t3, $t1, done
sw $zero, 0($t0) (store 0 — $zero is always 0, so no li is needed)
addi $t0, $t0, 4
addi $t3, $t3, 1
j loop
done:

What is wrong with L12 slide 13's while loop, and what should it say?

It writes blt $t1, $t0, End, i.e. "leave when n < i". The loop then continues while i <= n — one pass too many. For i = 0, n = 5 it gives 15 instead of 10.

It should be bge $t0, $t1, End ("leave when i ≥ n") = slt $at, $t0, $t1 + beq $at, $zero, End, which is what the slide's own caption describes.
