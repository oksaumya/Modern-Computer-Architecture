Functions, the stack and recursion in MIPS

To call a function, MIPS uses jal (jump and remember where you came from) and returns with jr $ra. Arguments travel in $a0–$a3 and the answer comes back in $v0. Anything that must survive the call is saved on the stack, an area of memory that grows downward.

The class deck Factorial and Fibonacci in MIPS solves both of its programs the other way — with a plain loop that counts down to zero, no jal and no stack at all — and leaves recursion as the closing challenge. Sections 8–12 are that material, and section 11 measures what each route costs.

Think of it like this: you are reading a book and look up a word in the dictionary. You put a bookmark in the book first ($ra). If the dictionary entry sends you to an encyclopedia, you need a second bookmark, so you stack the first one on a pile of sticky notes (the stack). When you finish each lookup, you take the top note off the pile and go back to that place.

Key terms

Function (procedure)
A named, reusable piece of code. It takes inputs (arguments) and gives back a result.
Caller / callee
The caller is the code that makes the call. The callee is the function being called.
Return address
Where to continue after the function ends: the instruction after the call. Kept in $ra (register 31).
Stack
A region of memory used like a pile: the last thing put on is the first taken off (LIFO).
Stack pointer $sp
Register 29. Holds the address of the top item on the stack.
Push / pop
Push = put a value on the stack. Pop = take the top value off.
Stack frame
The block of stack space one function call uses: saved $ra, saved registers, local variables.
Leaf function
A function that calls no other function.
Recursion
A function that calls itself, on a smaller problem, until it reaches a simple "base case".
Calling convention
The agreed rules for which registers carry what and who must save them.

1. A C function, in plain words

C:

c · leaf_examplecode → what it means
int leaf_example(int g, int h, int i, int j)Define a function named leaf_example. It takes four whole numbers (g, h, i, j) and will give back a whole number (the first int).
{The function's body starts.
int f;A local variable f that exists only inside this function.
f = (g + h) - (i + j);Compute the value and store it in f.
return f;Hand f back to the caller and end the function.
}The body ends.

Somewhere else, a caller writes e.g. x = leaf_example(10, 7, 4, 2); meaning "run the function with these four values and store the answer (11) in x".

2. The six steps of a call

  1. 1 · ArgsCaller puts arguments in $a0–$a3
  2. 2 · Calljal func: $ra = PC + 4, jump
  3. 3 · SaveCallee makes a stack frame, saves what it will change
  4. 4 · WorkCallee does its job
  5. 5 · ResultPut the answer in $v0 (and $v1); restore, pop
  6. 6 · Returnjr $ra

jal and jr

  • jal label (jump and link, J-type): saves PC + 4 into $ra, then jumps to label.
  • jr $ra (jump register, R-type): sets PC = the value in $ra. This returns to the line after the call.

Easy memory trick

$s = "saved": a function promises they look unchanged when it returns. $t = "temporary": any function may trash them.

4. The stack

In MIPS the stack starts at a high address (MARS: $sp = 0x7FFFEFFC) and grows DOWN toward lower addresses. $sp points at the top item (the lowest used address).

Push (save)

mips
addi $sp, $sp, -4Make room: move the top down 4 bytes.
sw $s0, 0($sp)Write the value into the new slot.

Pop (restore)

mips
lw $s0, 0($sp)Read the value back.
addi $sp, $sp, 4Release the slot.

To save several values, make room once (e.g. addi $sp, $sp, -8 for two words) and use offsets 0, 4, …

A stack frame (also called an activation record) holds, from top to bottom: the saved $ra (if the function calls others), saved $s registers it will change, and space for local variables or arrays. Some code also keeps $fp (frame pointer) pointing at the start of the frame, so locals have fixed offsets even if $sp moves.

5. Leaf example: leaf_example(g, h, i, j)

g, h, i, j arrive in $a0, $a1, $a2, $a3. The body uses $s0 for f, so the function must save and restore $s0 (callee-saved). The temporaries $t0, $t1 need no saving.

mips · leaf_examplecode → what it means
leaf_example:The function's label: jal leaf_example jumps here.
addi $sp, $sp, -4Push: make room for one word.
sw $s0, 0($sp)Save the caller's $s0, because we are about to change it.
add $t0, $a0, $a1$t0 = g + h
add $t1, $a2, $a3$t1 = i + j
sub $s0, $t0, $t1f = (g + h) − (i + j)
add $v0, $s0, $zeroreturn f: copy it into $v0.
lw $s0, 0($sp)Restore the caller's $s0.
addi $sp, $sp, 4Pop: give the word back.
jr $raReturn to the caller. $ra was not changed (no jal here), so it needs no saving.

Tested in MARS with g, h, i, j = 10, 7, 4, 2 and the caller's $s0 = 99: it returns 11, and $s0 is still 99 afterwards.

Textbook note

Patterson & Hennessy first show a version that pushes three words ($t1, $t0, $s0, with addi $sp, $sp, -12). It then points out that, by convention, $t registers need not be saved, so only $s0 is needed, as above. Both give the same answer.

6. Non-leaf functions must save $ra

If a function calls another function, its own jal overwrites $ra. Without saving it, its final jr $ra would jump to the wrong place (usually an endless loop). It also must save any argument or $t value it still needs after the inner call, because the callee may change them.

7. Recursive factorial — the class's closing challenge

The class deck ends on this: "write factorial as a function that calls itself with jal. One hint: the moment fact calls fact, jal overwrites $ra. Where could you keep a copy so the function still finds its way home?" The answer is the stack, and here is the whole program.

C:

c · factcode → what it means
int fact(int n) {A function fact that takes one whole number n and returns a whole number.
if (n < 1) return 1;Base case: if n is less than 1 (i.e. 0), the answer is 1. Stop here.
else return n * fact(n - 1);Recursive case: otherwise, work out fact(n − 1) by calling itself, then multiply by n (* means multiply).
}So fact(3) = 3 × fact(2) = 3 × 2 × fact(1) = 3 × 2 × 1 × fact(0) = 6.

fact is not a leaf: it calls itself. After the inner call it still needs n (to multiply) and its own return address. So each call saves both in an 8-byte frame.

Watch the frames pile up: fact(3)

Addresses are the real ones MARS uses. Each frame shows the saved $ra (at 4($sp)) and saved $a0 (at 0($sp)). Copper = newest frame; red = frame being popped.

Step 1 · main calls fact(3). main puts 3 in $a0; jal fact sets $ra = 0x00400020 (the line after the jal). fact subtracts 8 from $sp and saves $ra and $a0. 3 < 1 is false, so it sets $a0 = 2 and calls itself.

Step 2 · fact(2) starts. The jal inside fact overwrote $ra with 0x00400070 (the lw $a0 line after it). That is why the old $ra had to be saved first. fact(2) pushes its own frame and calls fact(1).

Step 3 · fact(1) starts. Another 8-byte frame: $ra = 0x00400070, $a0 = 1. 1 < 1 is false, so it calls fact(0).

Step 4 · fact(0): the base case. It pushes a frame, then 0 < 1 is true. So $v0 = 1, it pops its frame ($sp += 8) without restoring anything, and jr $ra returns to 0x00400070 inside fact(1). The stack is at its deepest: 4 frames = 32 bytes.

Step 5 · back in fact(1). It reloads $a0 = 1 and $ra = 0x00400070 from its frame and pops it. $v0 = $a0 × $v0 = 1 × 1 = 1. jr $ra returns into fact(2).

Step 6 · back in fact(2). Reload $a0 = 2, pop. $v0 = 2 × 1 = 2. Return into fact(3).

Step 7 · back in fact(3). Reload $a0 = 3 and $ra = 0x00400020, pop. $v0 = 3 × 2 = 6. jr $ra goes back to main.

Step 8 · back in main. $sp is back to 0x7FFFEFFC, exactly where it started, and $v0 = 6. main prints n! = 6. Every push was matched by a pop.

8. The class's other route: loops instead of recursion

The deck Factorial and Fibonacci in MIPS builds both programs with a loop and no function call at all: no jal, no $ra, no stack. Recursion is set at the very end as a challenge ("the moment fact calls fact, jal overwrites $ra — where could you keep a copy?"), which is exactly the program in section 7. So the two halves of this page are the two answers to the same question.

The class builds each program in the same five steps:

  1. 1 · Write it in Cso the logic is clear first
  2. 2 · Choose registersone register per variable
  3. 3 · Learn the new instructionsblez, mult, mflo, syscall 11
  4. 4 · Write the MIPSfill in the loop skeleton
  5. 5 · Trace it by handcheck every value, then run it

The loop skeleton: counting down

Both class programs count a counter down to zero. This is the shape:

mips · the skeletoncode → what it means
initSet the starting values. This runs once, and it must sit before the label.
loop: blez counter, doneFinished? If the counter is 0 or less, leave the loop.
bodyThe real work of one pass.
counter--Count down by one, so the loop eventually ends.
j loopJump back to the test and go round again.
done: …Carry on here when the counter has run out.
Why count DOWN?

Because MIPS can compare a register against zero in one instruction: blez. Counting up to n would need slt plus a branch — two instructions, and a second register holding n.

Watch the label

The init lines go before loop:. Put them after it and they run again on every pass, so the counter is reset and the loop never ends.

Three instructions the loops need

InstructionWhat it does
blez $t1, doneBranch if Less than or Equal to Zero. If $t1 ≤ 0, jump to done; otherwise carry on with the next line. It only ever compares with zero, so no slt is needed.
mult $t0, $t1Multiply two 32-bit numbers. The answer can be up to 64 bits, so it does not go in an ordinary register: it goes into two special registers, HI (top 32 bits) and LO (bottom 32 bits).
mflo $t0Move from LO: copy LO into $t0. For small answers HI is 0 and LO holds the whole result. (mfhi reads HI.)
addiu $t1, $t1, -1Add −1 to $t1: this is the "count down by one". The u means it never raises an overflow exception.
li $a0, 32 + li $v0, 11 + syscallSyscall 11 prints one character, given by its ASCII code. 32 is the code for a space.
$v0Syscall serviceUses

Keep nothing in $a0

Every print overwrites $a0. So a, b and the counter must live in $t registers, and you copy a value into $a0 only at the moment you print it.

9. Iterative factorial (the class program)

The idea. n! = n × (n − 1) × … × 2 × 1. The class's picture: in how many ways can 4 objects be held in 4 hands? The first hand has 4 choices, the second 3, the third 2, the last 1 — so 4 × 3 × 2 × 1 = 24. That is counting down, and the program does exactly the same starting from n.

Why start at result = 1?

Multiplying by 1 changes nothing, so 1 is the safe starting value. It also makes n = 0 come out right for free: the loop never runs and the answer stays 1, which is the correct 0! = 1.

C first (while means "keep repeating as long as the test is true"; counter-- means "make counter one smaller"):

c · iterative factorialcode → what it means
int result = 1;A whole-number box called result, starting at 1.
int counter = n;A second box, starting at the n we read.
while (counter > 0) {Repeat the block below as long as counter is still above zero.
result = result * counter;Multiply what we have so far by the counter (* means multiply).
counter--;Take one off the counter.
}End of the repeated block; go back and test again.
printf("%d", result);Print the result as a decimal number.

Then MIPS. Everything happens inside main: $t0 = result, $t1 = counter.

10. Iterative Fibonacci (the class assignment)

The task: read one integer n, then print F(0) up to F(n) with a single space between consecutive numbers. Use a loop — no recursion. No prompt, no labels: an automatic checker compares the output exactly.

input 5  →  output 0 1 1 2 3 5n = 5 prints six numbers: F(0), F(1) … F(5). Nothing else — no prompt, no labels.

The idea. Each number is the sum of the two before it, starting F(0) = 0, F(1) = 1.

n012345678
F(n)01123581321

You never need the whole list — only the last two numbers. Keep a window of two values and slide it along, printing each number as soon as you have it.

Older than Fibonacci: in Gujarat around 1150, the scholar Hemachandra wrote down this exact rule while counting the possible rhythms of a line of poetry (short and long syllables): the number of patterns of length n is the one before it plus the one before that.

Getting the spaces right

Six numbers need only five spaces, so the first number is special. Print F(0) on its own before the loop; then every pass prints "space, then number". No space can ever end up at the end.

C, registers, then the program

Why addu and not add?

addu is "add, unsigned" — the same addition, but with the overflow check switched off. The loop always computes one number ahead of what it prints, so with plain add the program would crash on a number it was never going to show you. See section 12.

The update-order trap

Start with a = 2 and b = 3. The next number should be 5.

Wrong

ordervalues after
a = ba = 3, b = 3 — the old a (2) is gone.
b = a + bb = 3 + 3 = 6. Wrong.

Right

ordervalues after
next = a + bnext = 5; a and b untouched.
a = ba = 3, b = 3.
b = nextb = 5. Correct.
Think of it like this: swapping the juice in two glasses needs a third, empty glass to hold one of them for a moment. In the program that third glass is $t2.

11. Iterative vs recursive: what it actually costs

Both factorial programs on this page give the same answers. They do not cost the same. The numbers below are measured, by running each listing one instruction at a time and counting; both versions were given identical input/output code (read an integer, print an integer, exit) so the comparison is fair.

iterative = 11 + 5n  ·  recursive = 17 + 12ninstructions executed start to finish, for the two factorial programs on this page
  • Instruction count. The loop body is 5 instructions (blez, mult, mflo, addiu, j). One recursive call costs 12: the same arithmetic plus 3 stack-pointer adjustments, 2 sw, 2 lw, a jal and a jr. So recursion runs roughly 2.4× more instructions for the same answer.
  • Memory. The loop uses zero bytes of stack, whatever n is. Recursion uses 8 × (n + 1) bytes, because every call keeps its own $ra and $a0 until the whole chain unwinds. For n = 1000 that is about 8 KB of stack for a program whose answer is one number.
  • Speed. On a simple machine where every instruction takes about the same time, 2.4× the instructions means about 2.4× the time. On a real pipelined CPU the gap is usually wider: the lws touch memory, and jal/jr are harder for the processor to predict than a loop that jumps to the same place every time.
  • What recursion buys. Code that reads like the mathematical definition, and a natural way to handle problems with branching structure (trees, searches, sorting) where there is no simple loop. For a plain countdown like factorial, it buys nothing.

Fibonacci makes the gap enormous

Factorial recursion is linear: n + 1 calls. But the naive recursion F(n) = F(n−1) + F(n−2) calls itself twice each time, and the same values are recomputed over and over. The number of calls is exactly 2·F(n+1) − 1:

12. When n gets big: overflow

Not needed for the assignment, but worth knowing what your program would actually do. A register holds 32 bits, so the largest positive value is 2,147,483,647 (2³¹ − 1).

Factorial

12!479,001,600fits
13!6,227,020,800too big

mult does keep the full answer, in HI:LO — but mflo takes only LO. So for n = 13 the program prints 1,932,053,504 (that is 6,227,020,800 − 4,294,967,296): wrong, with no warning at all.

To detect it: after mult, read HI with mfhi $t4. If $t4 is not 0, the answer did not fit.

Fibonacci

F(46)1,836,311,903fits
F(47)2,971,215,073too big

With addu (our code) the value wraps round silently: n = 47 ends by printing −1,323,752,223.

With plain add, MARS stops with an overflow exception already at n = 46 — even though every number it printed was correct — because the last pass computes F(47) one step ahead before the loop exits.

So which should you use?

addu, as the class does: the program must not crash on a number it is not even going to print. If you wanted a real overflow check you would test the value yourself before printing it, not rely on the exception.

Common mistakes & exam traps

Slips that cost marks
  • Not saving $ra in a function that calls another. Its jr $ra then returns to the wrong place.
  • Pushing with +. The stack grows down: push = addi $sp, $sp, -N; pop = +N.
  • Unbalanced stack: every -8 needs a matching +8 on every return path (including the base case).
  • Wrong offsets: after addi $sp,$sp,-8 the two slots are 0($sp) and 4($sp). Never use negative offsets from the new $sp.
  • Restoring $a0 before the jal instead of after it. The callee may have changed it.
  • Expecting $t registers to survive a call. They are caller-saved.
  • Using j instead of jal to call: $ra is never set.
  • jal saves PC + 4 (the next instruction), not PC.

How to check it in MARS
  1. Assemble (F3), then step through one instruction at a time rather than running it.
  2. Watch $t0, $t1 and $t3 in the Registers pane as you step.
  3. Compare each pass against the trace table above. The first row that disagrees is where the bug is.
  4. Test the smallest inputs first: n = 0 → 0, n = 1 → 0 1, n = 2 → 0 1 1, n = 5 → 0 1 1 2 3 5.

Practice

A jal func sits at address 0x00400100. What is in $ra after it runs?

0x00400104 (PC + 4).

A function changes $s1, $s2 and calls another function. Write its entry (push) and exit (pop) code.

Entry:
addi $sp, $sp, -12
sw $ra, 8($sp)
sw $s1, 4($sp)
sw $s2, 0($sp)
Exit:
lw $s2, 0($sp)
lw $s1, 4($sp)
lw $ra, 8($sp)
addi $sp, $sp, 12
jr $ra

For fact(4), how many frames are on the stack at the deepest point, and how many bytes do they use?

fact(4), fact(3), fact(2), fact(1), fact(0) = 5 frames × 8 = 40 bytes. $sp reaches 0x7FFFEFFC − 40 = 0x7FFFEFD4.

Why doesn't the base case of fact restore $a0 and $ra before popping?

In the base case, nothing changed them (no jal, no change to $a0), so the registers still hold the right values. It only needs to move $sp back.

Is leaf_example required to save $t0 and $t1? Why?

No. $t registers are caller-saved: a caller that needs them must save them itself. Only $s0 (callee-saved) must be saved.

Translate int add3(int a, int b, int c) { return a + b + c; } ("take three ints, give back their sum").

A leaf that changes no $s register needs no stack:
add3: add $v0, $a0, $a1
add $v0, $v0, $a2
jr $ra

What real instructions does la $a0, res become if res is at 0x1001000A?

lui $at, 0x1001 then ori $a0, $at, 0x000A. (MARS shows exactly this: 0x3c011001, 0x3424000a.)

In fact, what goes wrong if you swap the order and write lw $a0, 0($sp) before jal fact?

The $a0 you just set to n − 1 is replaced by n, so fact calls itself with the same n forever (well, until the stack overflows). And after the call, $a0 is no longer your n.

Why does the class count down to zero instead of up to n?

Because blez compares a register with zero in one instruction. Counting up would need the value of n kept in a second register plus slt and a branch — two instructions per pass instead of one, for no benefit.

In the iterative factorial, what happens if you write li $t0, 0 instead of li $t0, 1?

Every multiplication is 0 × something, so the answer is always 0. 1 is the identity for multiplication — it is the only safe starting value.

You move li $t1, 5 (the init) to just after the loop: label. What does the program do?

The counter is set back to 5 at the top of every pass, so blez never fires. The program loops forever. This is why the init must sit before the label.

For n = 7, how many numbers does the Fibonacci program print, and how many spaces?

8 numbers (F(0) … F(7) = 0 1 1 2 3 5 8 13) and 7 spaces — one per loop pass. F(0) is printed before the loop with no space, so there is never a space at the end.

Why does the Fibonacci loop need $t2 at all? Couldn't it just do a = b then b = a + b?

No. Once a = b has run, the old a is gone, so a + b is really b + b. Starting from a = 2, b = 3 you would get 6 instead of 5. $t2 is the third glass that holds the sum before anything is overwritten.

Your Fibonacci output is 1 1 2 3 5 8 for n = 5. What did you forget?

The move $a0, $t0 / li $v0, 1 / syscall that prints F(0) before the loop. Without it the output starts at F(1) and still has six numbers, so it is easy to miss.

The iterative factorial prints 1932053504 for n = 13. Is the program wrong?

The program is fine; 32 bits are not enough. 13! = 6,227,020,800 and mflo keeps only the bottom 32 bits: 6,227,020,800 − 4,294,967,296 = 1,932,053,504. Add mfhi $t4 after the mult and check whether $t4 is 0 if you want to detect it.

How many stack bytes does the iterative factorial use for n = 1000? And the recursive one?

Iterative: 0 bytes — it never touches $sp. Recursive: 8 × 1001 = 8,008 bytes, because every one of the 1001 calls keeps its own $ra and $a0 until the chain unwinds.

Class homework 1. Print the factorials 1! to n!, separated by spaces. (n = 5 → 1 2 6 24 120)

Keep the running product in $t0 and the multiplier in $t1, counting up this time; print a space only between numbers, by testing the counter again after each print.

Class homework 2. Print only the even Fibonacci numbers up to F(n). (n = 10 → 0 2 8 34)

Same sliding window, with two additions: andi $t4, $t0, 1 keeps only the lowest bit of a — that bit is 0 for an even number and 1 for an odd one. And because you cannot know in advance which number is printed last, the "space" trick is flipped: print the space before each number except the very first. $t5 remembers whether anything has been printed yet.

mips · even Fibonacci numbers up to F(n)code → what it means
main: li $v0, 5read n…

li $t0, 0a = F(0)

li $t5, 0flag: nothing printed yet

bne $t4, $zero, skipodd → do not print it
beq $t5, $zero, noSpfirst one printed? then no space in front

li $v0, 1

Checked by simulation: 0 → 0, 3 → 0 2, 10 → 0 2 8 34, 15 → 0 2 8 34 144 610. (Every third Fibonacci number is even — a nice pattern to notice.)

Roughly how many times slower is recursive factorial than the loop, and why exactly?

About 2.4× (17 + 12n instructions against 11 + 5n). The loop body is 5 instructions; one recursive call is 12, because on top of the same arithmetic it must move $sp three times, do two sw, two lw, a jal and a jr. None of that work contributes to the answer — it exists only to remember where to come back to.
