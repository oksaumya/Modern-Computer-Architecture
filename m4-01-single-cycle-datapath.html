Fetch-decode-execute & the single-cycle datapath

A CPU repeats one loop forever: fetch an instruction, decode it, execute it. The datapath is the set of parts the data flows through (PC, memories, register file, ALU, MUXes). The control unit sets the switches so each instruction takes the right route. In a single-cycle CPU, every instruction finishes inside one clock tick.

Think of it like this: a kitchen where every order must be finished within one fixed time slot. The slot has to be long enough for the slowest dish (a full meal), so a cup of tea also waits the full slot. That is the single-cycle CPU: simple, but it wastes time on quick instructions.

Key terms

PC (program counter)
A 32-bit register holding the address of the instruction being run now.
Datapath
The hardware that stores, moves and changes data: memories, registers, ALU, adders, MUXes and the wires between them.
Control signal
A 1-bit (or few-bit) wire from the control unit that sets a MUX or enables a write. Example: RegWrite = 1 means "save a result into a register".
MUX (multiplexer)
A switch: a select signal picks which one of its inputs goes to the output. See MUX.
ALU
Arithmetic Logic Unit. Adds, subtracts, ANDs, ORs and compares. It also outputs Zero = 1 when the result is 0.
Sign-extend
Stretch a 16-bit number to 32 bits by copying its top (sign) bit. −1 (FFFF) becomes FFFFFFFF, still −1.
Critical path
The slowest route through the circuit. It sets the shortest safe clock period.
Single-cycle
Design where each instruction starts and finishes in exactly one clock cycle. CPI = 1.
Register names used on this page

MIPS has 32 registers (see MIPS registers). Here: $t0–$t7 are temporaries (scratch space), $s0–$s7 are saved registers (long-lived variables), $zero is always 0.

1. The fetch-decode-execute cycle

Every instruction goes through the same five steps. The single-cycle CPU does all five inside one clock cycle. The pipeline later turns each step into its own stage.

  1. 1 · Fetch (IF)Read the instruction at address PC from instruction memory. Compute PC + 4.
  2. 2 · Decode (ID)Split the 32 bits into fields. Read the two registers named by rs and rt. Sign-extend the immediate.
  3. 3 · Execute (EX)The ALU does the maths: add/sub/and/or/slt, or works out a memory address, or compares for a branch.
  4. 4 · Memory (MEM)lw reads data memory. sw writes it. Others skip this step.
  5. 5 · Write back (WB)Save the result into a register (R-type, lw). Load the new PC.
Why PC + 4?

Every MIPS instruction is 32 bits = 4 bytes, and memory is byte-addressed. So the next instruction sits 4 addresses later.

3. The main control unit

The control unit reads the 6-bit opcode and sets every control signal. In a single-cycle CPU it is plain combinational logic (a truth table). "X" means don't care: the value doesn't matter because it is never used.

  • sw and beq have RegWrite = 0. They never save into a register, so RegDst and MemtoReg are "X".
  • ALUOp is a 2-bit hint: 00 = add (for addresses), 01 = subtract (for beq's compare), 10 = "look at the funct field".

How beq uses subtract

beq computes rs − rt. If they are equal, the answer is 0, so Zero = 1. Zero AND Branch drives PCSrc and the CPU jumps.

4. Following four instructions through the datapath

mips · four instruction typescode → what it means
add $t0, $s1, $s2R-type. $t0 = $s1 + $s2. Reads rs=$s1 and rt=$s2, ALU adds, result saved to rd=$t0. Skips data memory.
lw $t0, 8($s3)"Load word". Address = $s3 + 8. Read 4 bytes from memory there and save them into $t0. Uses every part.
sw $t0, 8($s3)"Store word". Address = $s3 + 8. Copy $t0 into memory there. No register is written.
beq $t0, $t1, 3"Branch if equal". If $t0 = $t1, jump to (PC + 4) + 3 × 4. Otherwise just go to PC + 4.

Worked example: trace lw $t0, 8($s3) (the longest path)

Fetch. PC → instruction memory → the 32-bit word for lw. At the same time, the adder computes PC + 4.

Decode. Control sees opcode 35 (lw) and sets RegDst = 0, ALUSrc = 1, MemtoReg = 1, RegWrite = 1, MemRead = 1, MemWrite = 0, Branch = 0, ALUOp = 00. The register file reads $s3 (rs). The immediate 8 is sign-extended to 32 bits.

Execute. ALUSrc = 1 picks the immediate. ALU computes $s3 + 8 = the memory address.

Memory. Data memory reads the word at that address.

Write back. MemtoReg = 1 picks the memory value. RegDst = 0 picks rt = $t0. On the clock edge the value is saved in $t0 and PC becomes PC + 4 (PCSrc = 0 because Branch = 0).

Path used: PC → Instruction memory → Register file → ALU → Data memory → MUX → Register file. Nothing else is this long.

Worked example: where does a beq go?

  1. beq $t0, $t1, 3 sits at address 0x00400010. So PC + 4 = 0x00400014.
  2. Immediate 3, sign-extended, shifted left 2 (× 4) = 12 = 0xC.
  3. Target = 0x00400014 + 0xC = 0x00400020. The offset counts instructions after PC + 4, not bytes.

5. Why single-cycle is slow: the critical path

Textbook (Patterson & Hennessy) sample delays. Parts not listed (MUXes, sign-extend, adders) are treated as having no delay.

Clock period ≥ longest path = 800 ps → max clock rate = 1 / 800 ps = 1.25 GHzEvery instruction takes 800 ps, even though the average needs far less. This waste is why real CPUs use pipelining.

Single-cycle: good

  • Simple to design and understand.
  • CPI = 1 exactly.
  • Control is just a truth table.

Single-cycle: bad

  • Clock is set by the slowest instruction.
  • Needs separate instruction and data memories and extra adders, since nothing can be reused within one cycle.
  • Only one instruction in the hardware at a time.

Common mistakes & exam traps

Slips that cost marks
  • RegDst for lw is 0, not 1. lw saves into rt. Only R-type uses rd.
  • sw writes memory, not a register. RegWrite = 0, MemWrite = 1.
  • ALUSrc = 1 for lw and sw (base + offset), 0 for beq (compare two registers).
  • Branch target uses PC + 4, not PC, and the offset is multiplied by 4.
  • The clock period is the longest instruction's delay, not the average.
  • Don't forget register-write setup time when adding up the lw path.
  • "X" (don't care) is not the same as 0. It means the value is irrelevant.

Practice

List the control signals for sw.

RegDst = X, ALUSrc = 1, MemtoReg = X, RegWrite = 0, MemRead = 0, MemWrite = 1, Branch = 0, ALUOp = 00.

Using the sample delays, what is the delay of an R-type instruction? Which parts does it skip?

200 + 100 + 200 + 100 = 600 ps. It skips data memory.

A single-cycle CPU (800 ps clock) runs 100 instructions. How long does it take?

CPI = 1, so 100 × 1 × 800 ps = 80,000 ps = 80 ns, whatever the mix of instructions.

If the data memory were made 100 ps faster, what would the new clock period be?

lw becomes 700 ps, sw 600 ps, R-type stays 600 ps. The longest is now lw at 700 ps.

beq $s0, $s1, -2 is at address 0x00400040. Where does it jump if taken?

PC + 4 = 0x00400044. Offset = −2 × 4 = −8. Target = 0x00400044 − 8 = 0x0040003C.

Why is RegDst "X" for beq but not for lw?

beq has RegWrite = 0, so no register is written and the chosen register number is ignored. lw does write, so it must pick rt (RegDst = 0).

RegWrite is stuck at 0. Which of add, lw, sw, beq still work?

sw and beq still work because they never write a register. add and lw fail because their results are never saved.
