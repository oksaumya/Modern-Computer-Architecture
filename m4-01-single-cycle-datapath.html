Module 4 · CPU Datapath & Pipelining From class notes · L13

Fetch, decode, execute & the single-cycle datapath

Lecture 13 is the payoff of the whole course so far. Modules 1–2 built the parts (gates, adders, MUXes, flip-flops, the register file, memory). Module 3 gave us the ISA (MIPS instructions and assembly). Today we wire the parts together so they actually execute an instruction: fetch it, decode it, execute it, touch memory, write back. In a single-cycle CPU all five steps finish inside one clock tick.

Think of it like this: a kitchen where every order must be finished within one fixed time slot. The slot has to be long enough for the slowest dish (a full meal), so a cup of tea also waits the full slot. That is the single-cycle CPU: simple, but it wastes time on quick instructions.
The lecture's own goal

From slide 3: "by the end, you can draw the single-cycle datapath from memory and trace any instruction through it." Treat the big diagram below as something to redraw by hand, not just read.

Key terms

PC (program counter)
A 32-bit register holding the address of the instruction being run now. Updated on every clock edge.
Datapath
The hardware that stores, moves and changes data: memories, registers, ALU, adders, MUXes and the wires between them.
Control signal
A 1-bit (or few-bit) wire from the control unit that flips a MUX or enables a write. Example: RegWrite = 1 means "save a result into a register".
MUX (multiplexer)
A switch: a select signal picks which one of its inputs goes to the output (from L3). See MUX.
ALU
Arithmetic Logic Unit. Add, subtract, AND, OR, set-less-than. It also outputs a Zero flag = 1 when the result is 0.
ALU control
A small second decoder. It takes ALUOp (2 bits, from the main control) plus the funct field and produces the 4-bit code that picks the ALU's operation.
Sign-extend
Stretch a 16-bit immediate to 32 bits by copying bit 15 (the sign bit) into bits 31–16. 0xFFFB stays −5; 0x0005 stays +5.
Write enable
The input that decides whether a clock edge actually stores anything. RegWrite is the register file's write enable; MemWrite is data memory's.
Critical path
The slowest route through the circuit. It sets the shortest safe clock period.
Single-cycle
Design where each instruction starts and finishes in exactly one clock cycle. CPI = 1.
Register names used on this page

MIPS has 32 registers (see MIPS registers). Here: $t0–$t7 are temporaries (scratch space), $s0–$s7 are saved registers (long-lived variables), $sp is the stack pointer, $zero is always 0. The lecture's running example is add $t0, $t1, $t2.

1. The instruction cycle — five steps

Every instruction the CPU runs passes through the same five steps. The lecture calls this sequence "the heartbeat of every CPU — it never stops while the machine is on". The single-cycle CPU does all five inside one clock cycle; the pipeline in L14 turns each step into its own stage.

  1. 1 · FETCHRead the instruction from memory — the PC points at it. In parallel, a dedicated adder computes PC + 4.
  2. 2 · DECODESplit the 32 bits into fields. Opcode + funct say what the operation is; rs/rt say which registers to read. The register file reads both at once.
  3. 3 · EXECUTEThe ALU does the real work: arithmetic/logic for R-type, base + offset for lw/sw, or a subtraction to compare for beq.
  4. 4 · MEMORYOnly lw and sw use this step. lw reads a word, sw writes one. Everything else skips it.
  5. 5 · WRITE-BACKA MUX picks what to store: the ALU result (for add) or the value loaded from memory (for lw). It goes into the destination register.

Then the PC — already incremented to PC + 4, or redirected by a taken branch — points at the next instruction, and the cycle restarts.

Why PC + 4?

Every MIPS instruction is 32 bits = 4 bytes, and memory is byte-addressed. So the next instruction sits 4 addresses later.

Not every instruction uses all five

An add skips MEMORY. An sw skips WRITE-BACK. A beq skips both. The sequence is always the same; the steps used are not.

How to read the diagram
  • Solid dark lines carry data — 32 bits wide unless a tick says otherwise (16, 32; the register-number wires are 5 bits).
  • Copper dashed lines are control signals. They flip MUXes and enable writes. Every one of them comes out of the Control oval, which only ever looks at the opcode, bits [31–26].
  • A dot means one wire splits and the same value goes to two places. No dot = the wires merely cross and are unrelated.
  • Green is the active path for lw — the one instruction that lights up every block. Grey/dark = present but unused this cycle.
  • Two adders on top: one for PC + 4, one for the branch target. They run every cycle, in parallel with everything else; the PCSrc MUX just decides which answer is kept.

The sign extender, in the lecture's own example

The I-type immediate is only 16 bits but the ALU is 32 bits wide. The sign extender copies bit 15 into all of bits 31–16, so the value is unchanged (from L11):

3. The main control unit

The control unit reads the 6-bit opcode (bits 31–26) and sets every MUX select and every write-enable. In a single-cycle CPU it is plain combinational logic — a truth table. The same hardware runs every instruction; only these control values change.

How beq uses subtract

beq computes rs − rt. If they are equal the answer is 0, so Zero = 1. Zero AND Branch drives PCSrc and the CPU jumps. That AND gate is the little D-shaped block on the right of the diagram.

4. Tracing instructions through the datapath

Four instruction types, one datapath, four different lit-up routes.

mips · the lecture's four instruction typescode → what it means
add $t0, $t1, $t2R-type. $t0 = $t1 + $t2. Reads rs=$t1 and rt=$t2, the ALU adds, the result is saved to rd=$t0. Skips data memory.
lw $t0, 8($sp)"Load word". Address = $sp + 8. Read 4 bytes from memory there and save them into $t0. Uses every block.
sw $t0, 8($sp)"Store word". Address = $sp + 8. Copy $t0 into memory there. No register is written.
beq $t0, $t1, 3"Branch if equal". If $t0 = $t1, jump to (PC + 4) + 3 × 4. Otherwise just go to PC + 4.

Worked example: trace lw $t0, 8($sp) (the longest path)

Fetch. PC → instruction memory → the 32-bit word for lw. At the same time the PC + 4 adder does its work.

Decode. Control sees opcode 35 (0x23, lw) and sets RegDst = 0, ALUSrc = 1, MemtoReg = 1, RegWrite = 1, MemRead = 1, MemWrite = 0, Branch = 0, ALUOp = 00. The register file reads $sp from bits [25–21]. The immediate 8 is sign-extended to 32 bits.

Execute. ALUSrc = 1 picks the sign-extended immediate. ALUOp = 00 tells the ALU control to emit 0010 (add). The ALU computes $sp + 8 = the memory address.

Memory. MemRead = 1, so data memory reads the word at that address onto its Read data port.

Write back. MemtoReg = 1 picks the memory value. RegDst = 0 picks rt = $t0 from bits [20–16]. On the clock edge RegWrite = 1 stores it, and PC becomes PC + 4 (PCSrc = 0, because Branch = 0).

Path used: PC → Instruction memory → Register file → ALU → Data memory → MemtoReg MUX → Register file. Nothing else is this long.

Worked example: where does a beq go?

  1. beq $t0, $t1, 3 sits at address 0x00400010. So PC + 4 = 0x00400014.
  2. Immediate 3, sign-extended, then shifted left 2 (× 4) = 12 = 0xC. That is the branch adder's second input.
  3. Target = 0x00400014 + 0xC = 0x00400020. The offset counts instructions after PC + 4, not bytes.
  4. The target is computed whether or not the branch is taken. Only PCSrc = Branch AND Zero decides whether the PC actually gets it.
Slide correction

Slide 17's caption says "write-back writes one (rd)". That is only true for R-type instructions. lw writes into rt, bits [20–16]. The slide's own drawing gets it right — its Write-register input is labelled "rt or rd (via RegDst)". Read the caption as: write-back writes one register, and RegDst chooses whether its number comes from the rt field or the rd field.

5. Why single-cycle is slow: the critical path

The clock must be slow enough for the slowest instruction, and that is lw. Its path puts every stage in series:

clock period ≥ PC + IMem + RegRead + ALU + DataMem + WriteBackEvery one of these delays happens one after another inside a single cycle, because nothing can be reused and nothing can be overlapped.

The lecture does not put numbers on those blocks, so here are the standard sample delays from the textbook (Patterson & Hennessy). Parts not listed — MUXes, the sign extender, the adders — are treated as free.

Clock period ≥ longest path = 800 ps → max clock rate = 1 / 800 ps = 1.25 GHzEvery instruction takes 800 ps, even though most need far less. "Every fast instruction is padded out to the slowest one's length. Enormous wasted time." — slide 30.
How much is wasted, exactly?

Slide 30 estimates that an add "finishes in maybe 60% of that time". With the textbook delays above it is 600 / 800 = 75% (and 500 / 700 ≈ 71% if you drop the register-write setup from both). The slide's 60% is a rough illustration, not a number to quote — the point it is making (the fast instruction still waits the full period) is exactly right.

Single-cycle: good

  • Simple to design and understand.
  • CPI = 1 exactly.
  • Control is just a truth table.

Single-cycle: bad

  • The clock is set by the slowest instruction.
  • Needs separate instruction and data memories, and two extra adders, since nothing can be reused within one cycle.
  • Only one instruction is in the hardware at a time — everything else sits idle.

This is why we pipeline

  1. The problemOne instruction per cycle, and the cycle is as long as the slowest instruction (lw). Most hardware sits idle most of the time.
  2. The ideaBreak the datapath into stages and overlap instructions — like an assembly line. That is pipelining.
  3. The payoffUp to about 5× throughput: while one instruction is in EXECUTE, the next is in DECODE and the next in FETCH.
  4. Coming next (L14)We slice this exact datapath into 5 pipeline stages. Pipelining does not replace the single-cycle datapath — it re-organises it. Same blocks, better timing.

Common mistakes & exam traps

The six the lecture calls out (slide 32)
  • "Every instruction uses all 5 steps." add skips MEMORY; sw skips write-back; beq skips both.
  • Confusing the two memories. Instruction memory (fetch) and data memory (lw/sw) are separate blocks here.
  • "The clock is set by add." It is set by lw — the longest path. The clock must fit the slowest instruction.
  • Forgetting the MUXes. They are what let one datapath serve all instructions. Not optional detail.
  • Mixing up PC+4 and the branch target. PC+4 is the default next address; the branch target is PC+4+(imm<<2), chosen only if taken.
  • "Single-cycle is efficient." It is simple, but it wastes time — fast instructions wait for the slowest. That is why we pipeline.
Slips that cost marks on the control table
  • RegDst for lw is 0, not 1. lw writes into rt. Only R-type uses rd.
  • sw writes memory, not a register. RegWrite = 0, MemWrite = 1.
  • ALUSrc = 1 for lw and sw (base + offset), 0 for beq (compare two registers).
  • "X" (don't care) is not the same as 0. It means the value is never looked at.
  • Don't forget the register-write setup time when adding up the lw path.
  • The Control unit only sees the opcode. The funct field goes to the ALU control, not to the main control.

Key takeaways

  1. Every instruction goes through fetch → decode → execute → memory → write-back (some steps are skipped).
  2. The single-cycle datapath wires together PC, instruction memory, register file, ALU, data memory and MUXes.
  3. R-type uses RegFile→ALU→RegFile; lw uses every block; sw skips write-back; beq uses the ALU to compare plus the branch logic.
  4. The MUXes (ALUSrc, MemtoReg, RegDst, PCSrc) reconfigure the one datapath to serve every instruction type.
  5. The clock period is set by the slowest instruction (lw) — so single-cycle wastes time, which motivates pipelining.

Practice

Class Q1. List which datapath blocks are active for sw $t0, 8($sp). Justify each.
  • PC + instruction memory — every instruction must be fetched. The PC+4 adder also runs.
  • Register file, read ports only — Read reg 1 = $sp (the base address), Read reg 2 = $t0 (the value to store). RegWrite = 0, so the write port does nothing.
  • Sign extender — the 16-bit offset 8 becomes 32 bits.
  • ALUSrc MUX = 1 — picks the extended immediate instead of Read data 2.
  • ALU — ALUOp = 00 → ALU control 0010 (add). It computes $sp + 8, the address.
  • Data memory, write port — MemWrite = 1, so on the clock edge $t0 is stored at that address. MemRead = 0.
  • Idle: the MemtoReg MUX, the register write port, the RegDst MUX (its output is a don't-care), and the branch adder's result (PCSrc = 0, so PC gets PC + 4).
Class Q2. Explain why the single-cycle clock is set by lw and not by add.

In a single-cycle design, one clock period has to contain the whole of any instruction, so it must be at least as long as the longest route through the hardware. lw is the only instruction that uses every block in series: PC → instruction memory → register read → ALU (address) → data memory → write-back. add skips the data-memory step entirely, so its route is shorter. But a clock set to add's length would cut lw off mid-flight and latch garbage. So the clock is set by lw, and add simply finishes early and waits.

With the textbook delays: lw = 800 ps, add = 600 ps, so add idles for 200 ps of every cycle it runs in.

Class Q3. Sketch the datapath changes needed to add addiu (add immediate unsigned).

No datapath changes at all — that is the point of the question. addiu $rt, $rs, imm is an I-type that needs: a register read (rs), a sign-extended immediate into the ALU, an add, and a write-back of the ALU result into rt. Every one of those wires already exists for lw and R-type.

The only change is one new row in the main control's truth table, for opcode 9:

InstructionRegDstALUSrcMemtoRegRegWriteMemReadMemWriteBranchALUOp
addiu010100000

Read it as: destination is rt (RegDst = 0, like lw), second ALU input is the immediate (ALUSrc = 1), write back the ALU result not memory (MemtoReg = 0, like R-type), do write a register (RegWrite = 1), don't touch memory, don't branch, and tell the ALU to add (ALUOp = 00).

Trap: the "u" in addiu means "does not trap on overflow" — it does not mean the immediate is zero-extended. addiu still sign-extends, so the existing sign extender is correct as-is. (andi/ori/xori are the ones that zero-extend; those would need a second extender and a new control signal.)

List the control signals for sw.

Using the sample delays, what is the delay of an R-type instruction? Which block does it skip?

200 + 100 + 200 + 100 = 600 ps. It skips data memory.

A single-cycle CPU (800 ps clock) runs 100 instructions. How long does it take?

CPI = 1, so 100 × 1 × 800 ps = 80,000 ps = 80 ns, whatever the mix of instructions.

If the data memory were made 100 ps faster, what would the new clock period be?

lw becomes 700 ps, sw becomes 600 ps, R-type stays 600 ps, beq stays 500 ps. The longest is now lw at 700 ps (1.43 GHz).

beq $s0, $s1, -2 is at address 0x00400040. Where does it jump if taken?

PC + 4 = 0x00400044. Offset = −2, sign-extended, shifted left 2 = −8. Target = 0x00400044 − 8 = 0x0040003C — two instructions backwards, i.e. the beq itself minus one. That is how a loop is written.

Why is RegDst "X" for beq but not for lw?

beq has RegWrite = 0, so no register is written and whatever number the RegDst MUX picks is ignored. lw does write, so it must pick rt (RegDst = 0).

RegWrite is stuck at 0. Which of add, lw, sw, beq still work?

sw and beq still work, because they never write a register. add and lw fail: the ALU and memory still do their work, but the answer is never saved.

The wire from the Zero output to the AND gate is cut (it reads 0 forever). What breaks?

PCSrc = Branch AND Zero becomes 0 for every instruction, so no branch is ever taken — the PC always gets PC + 4. Every loop runs straight through once and every if falls through. Nothing else changes: add, lw and sw are unaffected because they have Branch = 0 anyway.

Why does the datapath need two adders plus the ALU, instead of reusing the ALU three times?

Because all three additions must happen in the same clock cycle: PC + 4, the branch target (PC+4) + (imm<<2), and the instruction's own ALU work. One ALU can only do one operation at a time, and there is no second cycle to come back in. Hardware is duplicated to buy parallelism — the same reason instruction memory and data memory are separate blocks.
