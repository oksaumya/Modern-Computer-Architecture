The 5-stage pipeline: IF → ID → EX → MEM → WB

Pipelining cuts the single-cycle datapath into 5 stages with a register between each. Each clock cycle, every instruction moves one stage forward, so up to 5 instructions are in progress at once. Each instruction takes just as long (or a little longer), but many more finish per second.

Think of it like this: doing laundry. The washer, dryer, folding table and closet are the stages. You don't wait for load A to be put away before starting load B. As soon as A moves to the dryer, B goes into the washer. Each load still takes 2 hours, but 4 loads finish in 3.5 hours instead of 8.

Key terms

Stage
One step of the work (IF, ID, EX, MEM, WB). Each stage takes exactly one clock cycle.
Pipeline register
A bank of flip-flops between two stages (IF/ID, ID/EX, EX/MEM, MEM/WB). It holds one instruction's data so the next stage can use it in the next cycle.
Throughput
How many instructions finish per second. Pipelining improves this.
Latency
How long one instruction takes from start to finish. Pipelining does not improve this.
Stage time (clock period)
The slowest stage's delay plus the pipeline register's own overhead (setup + clock-to-Q delay).
Pipeline chart
A grid: rows are instructions, columns are clock cycles, and each cell shows which stage an instruction is in.

1. The laundry picture

4 loads (A–D), 4 tasks, 30 minutes per task.

2. The five stages and the pipeline registers

StageWhat happensHardware used
IF · Instruction FetchRead the instruction at PC. Compute PC + 4.PC, instruction memory, adder
ID · Instruction DecodeDecode the fields, read registers rs and rt, sign-extend the immediate, generate control signals.Register file (read), sign-extend, control unit
EX · ExecuteALU does the operation or computes an address. Branch target is computed.ALU, ALUSrc MUX, branch adder
MEM · Memory accesslw reads, sw writes data memory. Others just pass through.Data memory
WB · Write BackSave the result into the register file.MemtoReg MUX, register file (write)
Control travels with the instruction

The control unit decodes the opcode in ID, once. The signals are then stored in the pipeline registers in three groups: EX signals (RegDst, ALUSrc, ALUOp) are used in EX, M signals (MemRead, MemWrite, Branch) in MEM, and WB signals (RegWrite, MemtoReg) in WB. That way each stage uses the signals of the instruction it is working on.

  • Read a row to follow one instruction: it moves one stage right every cycle.
  • Read a column to see a snapshot of the whole CPU at that clock cycle.
  • Cycle 5 is the first "full" cycle: all 5 stages are busy. I1 is in WB, I2 in MEM, I3 in EX, I4 in ID and I5 in IF.
  • I1 finishes at the end of cycle 5. After that, one instruction finishes every cycle. Total = 5 + (5 − 1) = 9 cycles.

4. How much faster? The timing maths

Time for n instructions on a k-stage pipeline = (k + n − 1) × stage timeThe first instruction takes k cycles. Each of the other n − 1 instructions finishes 1 cycle later.
Stage time = slowest stage + pipeline-register overheadAll stages share one clock, so the slowest stage sets the pace.
Ideal speedup ≈ k (the number of stages)Only when stages are perfectly balanced, n is large, and there are no hazards.

Worked example (Patterson & Hennessy): 3 × lw

Delays: memory 200 ps, ALU 200 ps, register read or write 100 ps. The single-cycle clock is 800 ps (see single-cycle). In the pipeline, the slowest stages take 200 ps, so every stage gets 200 ps (the register stages are padded from 100 to 200 ps).

Instruction1234567
lw 1 (done at 1000 ps)IFIDEXMEMWB
lw 2 (done at 1200 ps)IFIDEXMEMWB
lw 3 (done at 1400 ps)IFIDEXMEMWB

Single-cycle: each instruction takes the full 800 ps. 3 × 800 = 2400 ps.

Pipelined, first instruction: 5 stages × 200 ps = 1000 ps. It finishes at 1000 ps (later than the single-cycle's 800 ps, so latency got worse).

Pipelined, the rest: the 2nd finishes at 1200 ps and the 3rd at 1400 ps, one stage time (200 ps) apart.

Check with the formula: (k + n − 1) × T = (5 + 3 − 1) × 200 = 7 × 200 = 1400 ps. ✓

Many instructions: for 1,000,000 instructions the gap between finishes is 800 ps vs 200 ps, so the speedup approaches 800 / 200 = 4×. It is not 5× because the stages are unbalanced (some only need 100 ps but get 200 ps).

Worked example: unbalanced stages plus register overhead

  1. Stage delays: IF 150, ID 100, EX 200, MEM 150, WB 100 ps. Pipeline register overhead: 20 ps.
  2. Single-cycle clock = 150 + 100 + 200 + 150 + 100 = 700 ps.
  3. Pipeline stage time = slowest stage + overhead = 200 + 20 = 220 ps.
  4. 100 instructions: single-cycle = 100 × 700 = 70,000 ps. Pipeline = (5 + 100 − 1) × 220 = 104 × 220 = 22,880 ps. Speedup = 70,000 / 22,880 ≈ 3.06×.
  5. Very long programs: speedup → 700 / 220 ≈ 3.18×, well below the ideal 5×.

What pipelining improves

  • Throughput: instructions finished per second.
  • Total time for a whole program.

What it does not improve

  • Latency of one instruction (it gets slightly worse, due to register overhead and padding).
  • Speedup is capped by the slowest stage and by hazards.

5. Why MIPS (RISC) is easy to pipeline

  • All instructions are 32 bits. IF always fetches 4 bytes, and PC + 4 is always right. (x86 instructions are 1 to 15 bytes, which is much harder.)
  • Few formats, fields in fixed places. rs and rt are always in the same bit positions, so ID can read the registers while it is still decoding.
  • Load/store only. Only lw/sw touch memory, so memory access fits neatly in the MEM stage. The ALU is free to compute the address in EX.
  • Memory is aligned (words at multiples of 4), so a data transfer needs only one memory access.

Common mistakes & exam traps

Slips that cost marks
  • "Pipelining makes each instruction faster." Wrong. It improves throughput, not latency.
  • Total cycles = k + n − 1, not k × n. 5 stages and 10 instructions take 14 cycles, not 50.
  • Stage time uses the slowest stage, plus register overhead if given.
  • Ideal speedup = number of stages only with balanced stages, no overhead, no hazards, and many instructions.
  • Pipeline registers are named after the two stages they sit between (IF/ID, ID/EX, EX/MEM, MEM/WB). There is no register after WB.
  • Numbering cycles from 1: instruction i (counting from 1) enters IF in cycle i and finishes WB in cycle i + 4.

Practice

A 5-stage pipeline with a 200 ps stage time runs 10 instructions. How long does it take (no hazards)? How long in an 800 ps single-cycle CPU?

Pipeline: (5 + 10 − 1) × 200 = 14 × 200 = 2800 ps. Single-cycle: 10 × 800 = 8000 ps.

In the 5-instruction chart above, which instruction is in EX during cycle 6?

Instruction i is in EX in cycle i + 2. So cycle 6 → I4 (sw).

Stage delays are 300, 150, 250, 300, 100 ps and register overhead is 25 ps. Find the pipeline clock period and the speedup for a very long program.

Single-cycle = 300 + 150 + 250 + 300 + 100 = 1100 ps. Pipeline = 300 + 25 = 325 ps. Speedup ≈ 1100 / 325 ≈ 3.38×.

What is the latency of one instruction in the 325 ps pipeline above?

5 × 325 = 1625 ps. That is slower than the 1100 ps single-cycle, which shows that pipelining trades latency for throughput.

Which pipeline register carries the value that sw will write to memory, when it is used?

The value is read from the register file in ID and stored in ID/EX. It is then copied into EX/MEM and used by data memory in the MEM stage.

Why does the pipelined CPU need separate instruction and data memories?

In the pipeline, IF (fetching an instruction) and MEM (reading/writing data) happen in the same clock cycle for different instructions. One shared memory would be needed twice at once, which is a structural hazard. Separate memories avoid it.

Laundry: 3 tasks of 40 minutes each, 5 loads. Sequential vs pipelined time?

Sequential: 5 × 3 × 40 = 600 min (10 h). Pipelined: (3 + 5 − 1) × 40 = 7 × 40 = 280 min.
