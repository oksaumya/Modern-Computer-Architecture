Hazards, forwarding & branch prediction

A hazard is anything that stops the next instruction from running in its planned clock cycle. There are three kinds: structural, data and control. The fixes are to forward a value early, stall (wait), or predict and fix mistakes afterwards.

Think of it like this: an assembly line where worker 2 needs a part that worker 1 is still finishing. Worker 1 can hand it over directly instead of sending it all the way round the belt (forwarding). If it isn't ready at all, worker 2 waits one tick (stall). At a fork in the belt, the line guesses which way to go. If the guess was wrong, the half-built items are thrown away (flush).

Key terms

Hazard
A situation where the next instruction can't safely run in the next clock cycle.
Stall / bubble
A deliberate do-nothing cycle (like a NOP) inserted so an instruction waits. Each stall adds 1 clock cycle.
Forwarding (bypassing)
Sending a result straight from a later pipeline register back to the ALU input, before it has been written to the register file.
Flush
Throwing away instructions that were fetched by mistake (turning them into bubbles).
Branch penalty
The number of cycles lost when a branch goes a way we didn't expect.
Branch predictor
Hardware that guesses "taken" or "not taken" before the branch is actually decided.
BTB (branch target buffer)
A small cache: branch address → its target address. Used in IF, so a predicted-taken branch can jump immediately.
Register numbers
Textbook examples write $2, $12, … meaning register number 2, number 12, and so on. $0 is $zero, always 0.

2. Data dependencies: RAW, WAW, WAR

Take two instructions, i first and j later. Hennessy & Patterson name each possible clash by what j does after i:

sub $t1,$t0,$s3		True (data) dependencyYes, the common hazard. Fix with forwarding or stalls.

"Read after read" (RAR) is never a hazard, because reading doesn't change anything. A simple 5-stage pipeline finishes instructions in order, so only RAW causes hazards here. Out-of-order CPUs (ILP & renaming) must also handle WAW and WAR.

3. Spotting a data hazard

mips · textbook example (P&H)code → what it means
sub $2, $1, $3$2 = $1 − $3. Writes $2, but only in WB (cycle 5).
and $12, $2, $5$12 = $2 AND $5. Reads $2 in cycle 3 (too early), hazard.
or $13, $6, $2$13 = $6 OR $2. Reads $2 in cycle 4 (too early), hazard.
add $14, $2, $2$14 = $2 + $2. Reads $2 in cycle 5, the same cycle it is written. OK: write happens in the first half, read in the second.
sw $15, 100($2)Store $15 at memory[$2 + 100]. Reads $2 in cycle 6. OK.
The quick rule

An instruction reads its registers in ID. The writer saves in WB, 3 cycles after its own ID. So if the reader comes 1 or 2 instructions after the writer, it reads too early: hazard. At 3 or more after, it's safe.

4. Forwarding

The new value of $2 already exists at the end of sub's EX stage, sitting in the EX/MEM register. A cycle later it is in the MEM/WB register. So we add a MUX in front of each ALU input that can pick the value from the register file (normal), from EX/MEM, or from MEM/WB.

Instruction123456789
sub $2,$1,$3IFIDEXMEMWB
and $12,$2,$5IFIDEXMEMWB
or $13,$6,$2IFIDEXMEMWB
add $14,$2,$2IFIDEXMEMWB
sw $15,100($2)IFIDEXMEMWB

Outlined cells are where a value is forwarded: sub's EX/MEM value goes to and's EX in cycle 4, and sub's MEM/WB value goes to or's EX in cycle 5. With forwarding, no stalls are needed, so the program takes 9 cycles.

Why "not EX hazard"? The double data hazard

add $1,$1,$2 · add $1,$1,$3 · add $1,$1,$4. When the third add is in EX, both earlier adds wrote $1. The correct value is the most recent one (in EX/MEM), so the EX/MEM check has priority.

5. The load-use hazard: forwarding is not enough

lw gets its value from data memory at the end of MEM. If the very next instruction needs that value at the start of its EX, that would be the same moment, and nothing can travel backwards in time. So we must stall one cycle and then forward from MEM/WB.

mips · load-use example (P&H)code → what it means
lw $2, 20($1)Load memory[$1 + 20] into $2. The value is ready only after MEM (cycle 4).
and $4, $2, $5Needs $2 in its EX. Right after the lw, so this is a load-use hazard: 1 stall, then forward from MEM/WB.
or $8, $2, $6After the stall, its ID lines up with lw's WB, so the split-cycle register file handles it.
add $9, $4, $2Needs $4 from and (2 back), forwarded from MEM/WB.
Instruction123456789

In cycle 4, and is held in ID and or is held in IF, while a bubble (all control signals 0) goes into EX. Total: 5 + 4 − 1 + 1 stall = 9 cycles.

Count stalls carefully

A stall delays every later instruction too. That can shrink the gap to the next dependency, or remove it. Recheck each pair after inserting stalls. Example: in the sub/and/or program without forwarding, and needs 2 stalls. After those stalls, or already reads $2 after it is written, so the total is 2 stalls, 11 cycles (vs 9 with forwarding).

Worked example (Lab 4A idea): reorder code to avoid stalls

Task: "a = b + e; c = b + f". In plain words: add the values b and e and store the answer in a; then add b and f and store the answer in c. The variables live in memory at offsets from $t0: b at 0, e at 4, f at 8, a at 12, c at 16.

7. Control hazards (branches)

The PC has to be updated every cycle, but beq only knows whether to jump after comparing its two registers. By then, the pipeline has already fetched the next instructions. If the branch is taken, those instructions are wrong and must be flushed.

mips · branch example (addresses on the left)code → what it means
40: beq $1, $3, 7If $1 = $3, jump to 44 + 7 × 4 = 72.
44: and $12, $2, $5Fetched next by default (PC + 4).
48: or $13, $6, $2
52: add $14, $2, $2
72: lw $4, 50($7)The branch target.

The branch is resolved at the end of cycle 4. The three instructions fetched in cycles 2, 3 and 4 are flushed, and the target is fetched in cycle 5.

Now only the one instruction fetched in cycle 2 is wrong. Moving the decision to ID needs an equality comparator and the target adder in ID. That can create new data hazards for the comparison.

The 2-bit saturating counter

An FSM with 4 states (see FSMs). A taken branch (T) moves the counter up (towards 11). A not-taken branch (N) moves it down (towards 00). It never goes past 11 or 00 (saturating). The top bit is the prediction.

Worked example: a loop that runs 10 times

The loop's branch at the bottom goes T nine times, then N once (the exit). Here is the loop's second visit, after the first visit has trained the predictor:

Iteration123–8910Misses (accuracy)

1-bit predictsN ✗TTTT ✗2 (80%)

2-bit predictsTTTTT ✗1 (90%)

The 1-bit predictor misses twice per visit: at the exit, and again on the first iteration of the next visit, because it remembered "N". The 2-bit counter only drops from ST to WT at the exit, so it still predicts T on re-entry: 1 miss per visit.

8. Effective CPI with hazards

Effective CPI = 1 + Σ (fraction × stall probability × stall cycles)Fraction = share of instructions of that kind. The ideal pipeline has CPI = 1. Each kind of stall adds its average cost per instruction.
  1. Branches only: 20% of instructions are branches, 20% of those are mispredicted, penalty 1 cycle. CPI = 1 + 0.2 × 0.2 × 1 = 1.04.
  2. Load-use + branches: 20% are lw and half of those need a stall (1 cycle). 15% are branches, 30% mispredicted, penalty 2. CPI = 1 + 0.2 × 0.5 × 1 + 0.15 × 0.3 × 2 = 1 + 0.10 + 0.09 = 1.19.
  3. Compared with single-cycle: 800 ps × 1 vs 200 ps × 1.19 = 238 ps per instruction, a speedup of 800 / 238 ≈ 3.36× (down from 4× without hazards).

9. Lab 4B: data-dependent branches on real hardware

The lab loop, in C-like form: if (data[i] >= 128) sum += data[i];. In plain words: look at item number i of the list data; if it is at least 128, add it to the running total sum. This is repeated for every i. Here it is in MIPS:

mips · sum of big valuescode → what it means
# $s0 = address of data, $s1 = n, $s2 = sum, $t0 = iWhich register holds what.
add $t0, $zero, $zeroi = 0.
loop: beq $t0, $s1, doneIf i = n, the loop is finished, so jump to done.
sll $t1, $t0, 2t1 = i × 4 (each item is 4 bytes).
add $t1, $t1, $s0t1 = address of data[i].
lw $t2, 0($t1)t2 = data[i].
slti $t3, $t2, 128t3 = 1 if data[i] < 128, else 0. (Uses t2 right after its lw: a load-use stall!)
bne $t3, $zero, skipThe data-dependent branch. If the value is small, skip the add.
add $s2, $s2, $t2sum = sum + data[i].
skip: addi $t0, $t0, 1i = i + 1.
j loopGo round again.
done:

Random data

The bne outcome is a coin flip, so even a 2-bit predictor is wrong about half the time. Each miss flushes the pipeline. Modern CPUs have 15–20 stage pipelines, so a miss costs many cycles.

Sorted data

The outcomes look like T T T … T N N N … N. The predictor is wrong only around the switch point, so the same loop runs much faster, even though it does exactly the same work.

The branchless fix

Replace the bne + add with arithmetic that gives the same result and has no branch to mispredict:

mips · branchless bodycode → what it means
slti $t3, $t2, 128t3 = 1 if small, 0 if big.
addi $t3, $t3, -1t3 = 0 if small, −1 if big. −1 is 0xFFFFFFFF (all 32 bits are 1).
and $t4, $t2, $t3"Mask": t4 = 0 if small, data[i] if big.
add $s2, $s2, $t4Always add. Adding 0 changes nothing.

Common mistakes & exam traps

Slips that cost marks
  • Load-use always needs 1 stall, even with forwarding. R-type → next instruction needs 0 stalls with forwarding.
  • ForwardA = 10 means EX/MEM (the newer value) and 01 means MEM/WB. They are easy to swap.
  • Forget the Rd ≠ 0 check and you'll forward a "result" into $zero, which must stay 0.
  • The instruction 3 after a writer needs no forwarding, because the register file writes in the first half of the cycle and reads in the second.
  • Hazard detection for load-use checks ID/EX.MemRead and compares ID/EX.Rt (lw's destination) with IF/ID.Rs and IF/ID.Rt.
  • A sw writes memory, not a register (RegWrite = 0), so no later instruction ever needs a register value forwarded from it.
  • WAW and WAR are not hazards in a simple in-order 5-stage pipeline.
  • 1-bit predictor: 2 misses per loop visit. 2-bit: 1.
  • Branch penalty depends on where the branch is decided: MEM → 3 flushed, ID → 1 flushed.

Practice

add $t0,$t1,$t2 then sub $t3,$t0,$t4. Name the dependency. How is it fixed, and what are ForwardA and ForwardB?

RAW on $t0. When sub is in EX, the add is in MEM, so $t0 is forwarded from EX/MEM. $t0 is sub's rs (first operand), so ForwardA = 10 and ForwardB = 00. No stall.

lw $t0,0($s0) then add $t1,$t0,$t0. How many stalls with forwarding? Without forwarding? Total cycles for these 2 instructions?

With forwarding: load-use, 1 stall, so 5 + 2 − 1 + 1 = 7 cycles. Without forwarding: the add must wait until lw's WB for its ID, 2 stalls, so 8 cycles.

Classify: (a) add $t0,$s1,$s2 / addi $t0,$s3,4; (b) add $t1,$t0,$s1 / sub $t0,$s2,$s3.

(a) Both write $t0: WAW (output dependency). (b) The first reads $t0 and the second writes it: WAR (anti-dependency). Neither is a hazard in a 5-stage in-order pipeline.

A 2-bit counter starts at Strongly Not taken (00). The branch goes T, T, N, T. Give each prediction and count the misses.

SNT → predict N, actual T ✗ → WNT → predict N, actual T ✗ → WT → predict T, actual N ✗ → WNT → predict N, actual T ✗ → WT.
4 misses out of 4. A bad starting state plus an irregular pattern defeats the predictor.

A branch alternates T, N, T, N, T, N. Compare a 1-bit predictor (starting at T) with a 2-bit one (starting at ST).

1-bit: T✓ N✗ T✗ N✗ T✗ N✗, so 5 misses. 2-bit: ST→T✓, ST→T✗, WT→T✓, ST→T✗, WT→T✓, ST→T✗, so 3 misses. The 2-bit counter bounces between ST and WT and always predicts T.

25% of instructions are branches, 10% mispredicted, 2-cycle penalty. Also 30% are lw, and 40% of those are followed by a use (1 stall). What is the effective CPI?

Branches: 0.25 × 0.10 × 2 = 0.05. Load-use: 0.30 × 0.40 × 1 = 0.12. CPI = 1 + 0.05 + 0.12 = 1.17.

20% of instructions are branches and 60% of them are taken. The CPU predicts not-taken. Find the CPI if the branch is decided in MEM (3-cycle penalty) vs in ID (1 cycle).

MEM: 1 + 0.2 × 0.6 × 3 = 1.36. ID: 1 + 0.2 × 0.6 × 1 = 1.12.

Why can't forwarding alone fix lw $2,20($1) followed by and $4,$2,$5?

The loaded value exists only at the end of lw's MEM stage, which is the same moment and needs it at the start of its EX. Forwarding can't send data backwards in time, so one bubble is inserted and the value is then forwarded from MEM/WB.
