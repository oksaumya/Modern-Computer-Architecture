Cache organization & lookup

A cache is a small table of recently used memory blocks. To find a block quickly, the CPU splits every address into three parts: tag | index | offset. The index says where to look, the tag says whether it is the right block, and the offset says which byte inside the block.

Think of it like this: a hotel with numbered rooms. Your room number (index) tells you which door to go to. The name on the booking (tag) proves the person inside is really you. The drawer number (offset) tells you where your socks are inside the room. A direct-mapped cache gives each guest exactly one possible room. A set-associative cache gives a few possible rooms on the same floor.

Key terms

Block (line)
The fixed-size chunk of memory copied into the cache as one unit. A cache slot that holds a block is also called a line.
Hit / miss
Hit: the block is already in the cache. Miss: it is not, so it must be fetched from main memory.
Hit rate / miss rate
Hits ÷ total accesses, and misses ÷ total accesses. They add up to 1.
Miss penalty
The extra time a miss costs: fetching the block from the slower level and placing it in the cache.
Valid bit
1 if the slot holds real data. At power-on every valid bit is 0, so garbage is never taken as a hit.
Set
A group of slots that one address is allowed to use. The index picks the set.
Way
One slot inside a set. "4-way" means 4 slots per set.
Associativity
How many ways each set has: 1 (direct-mapped) up to all slots (fully associative).

1. Three ways to organize a cache

The big design question: for a given address, which cache slots may hold its block?

OrganizationWhere can a block go?Sets × ways
Direct-mappedExactly one slotmany sets × 1 way
N-way set-associativeAny of N slots in one set(slots ÷ N) sets × N ways
Fully associativeAny slot at all1 set × all ways

2. Splitting the address: tag | index | offset

offset bits = log₂(block size in bytes)
index bits  = log₂(number of sets)
tag bits    = address bits − index bits − offset bits

log₂(x) asks "2 to what power gives x?" For example log₂(4096) = 12, because 212 = 4096. Number of sets = number of blocks ÷ ways.

  1. OffsetLow bits. Which byte inside the block.
  2. IndexMiddle bits. Which set to look in.
  3. TagHigh bits. Stored in the slot and compared to prove it is the right block.

Worked example 1: direct-mapped

  1. 32-bit address, 16 KB cache, 4-byte blocks, direct-mapped (1 way).
  2. Blocks = 16 KB ÷ 4 B = 16,384 ÷ 4 = 4,096 = 212. With 1 way, sets = 4,096.
  3. offset = log₂(4) = 2 bits; index = log₂(4096) = 12 bits.
  4. tag = 32 − 12 − 2 = 18 bits.

Worked example 2: same cache, 4-way set-associative

  1. Still 4,096 blocks, but now 4 per set: sets = 4,096 ÷ 4 = 1,024 = 210.
  2. offset = 2 bits (block size did not change); index = log₂(1024) = 10 bits.
  3. tag = 32 − 10 − 2 = 20 bits. Two bits moved from the index into the tag.
Rule of thumb

Doubling the associativity halves the number of sets: index −1 bit, tag +1 bit. A fully associative cache has 0 index bits: everything except the offset is tag.

Conflict (collision)Blocks fight over the same set while other slots are free.Higher associativity

In the trace above, all 5 misses are compulsory: each block was used for the first time.

6. The associativity trade-off

Low associativity (direct-mapped)

  • One comparator: simple, cheap, fast hit check.
  • More conflict misses.
  • No replacement choice needed.

High associativity (N-way, fully)

  • Fewer conflict misses.
  • N comparators + a MUX: more hardware, slower hit check, more power.
  • Needs a replacement policy (LRU, FIFO…).

Real CPUs pick the middle: L1 caches are often 8-way; fully associative is used only for tiny caches such as the TLB.

7. How many bits does a cache really need?

Each slot stores more than the data: it also stores the tag and the valid bit.

Total bits = number of slots × (valid + tag + data bits)Other status bits (such as a dirty bit) are added the same way.

Patterson & Hennessy example: direct-mapped, 16 KB of data, blocks of 4 words (1 word = 32 bits = 4 bytes), 32-bit addresses.

  1. 16 KB = 16,384 bytes = 4,096 words = 212 words.
  2. Blocks = 212 ÷ 4 = 210 = 1,024 blocks → index = 10 bits.
  3. Offset = 2 bits (which word) + 2 bits (which byte) = 4 bits → tag = 32 − 10 − 4 = 18 bits.
  4. Per slot: 1 (valid) + 18 (tag) + 4 × 32 (data) = 147 bits.
  5. Total = 1,024 × 147 = 150,528 bits ≈ 18.4 KB, about 1.15× the 16 KB of data alone.
Correction: 2¹⁰ blocks, not 2¹⁴

A draft of these notes said "214 blocks" for this example. 214 is the number of bytes (16 KB). With 4 bytes per word and 4 words per block, the cache has 214 ÷ 16 = 210 blocks.

Common mistakes & exam traps

Slips that cost marks
  • Index bits come from the number of sets, not the number of blocks (they are only equal when direct-mapped).
  • Offset bits come from the block size in bytes (if addresses count bytes). A "4-word block" is 16 bytes → 4 offset bits.
  • Forgetting the valid bit. Without it, junk left in the cache at power-on could look like a hit.
  • Fully associative has no index: tag = address bits − offset bits.
  • Direct-mapped caches need no replacement policy: there is only one place a block can go.
  • KB here means 1024 bytes (210). 16 KB = 16,384 bytes, not 16,000.

Practice

32-bit addresses, 64 KB cache, 16-byte blocks, direct-mapped. Find offset, index and tag bits.

Blocks = 65,536 ÷ 16 = 4,096 = 212. Offset = log₂16 = 4, index = 12, tag = 32 − 12 − 4 = 16.

Same cache, but 8-way set-associative?

Sets = 4,096 ÷ 8 = 512 = 29. Offset = 4, index = 9, tag = 32 − 9 − 4 = 19.

Same cache, fully associative?

1 set → index = 0. Offset = 4, tag = 32 − 4 = 28.

In Worked example 1 (tag 18 | index 12 | offset 2), split the address 0x00001234.

0x1234 = 0001 0010 0011 0100 (all higher bits are 0).

Offset = last 2 bits = 00 = 0. Index = the next 12 bits = 0100 1000 1101 = 0x48D. Tag = everything above = 0.

Add a 9th access, block 26, to the trace in Worked example 3. Hit or miss? Which C?

Miss. Set 010 now holds 18 (tag 10), but 26 has tag 11. This is a conflict miss: 26 was in the cache before and was pushed out only because 18 shares its set. An 8-slot fully associative cache would still hold 26, so there it would be a hit.

Worked example 1 stores 32 bits of data per block. How many bits does the whole cache need?

Per slot: 1 + 18 + 32 = 51 bits. Total = 4,096 × 51 = 208,896 bits ≈ 25.5 KB.

A fully associative cache is full and misses on a block it has seen before. What kind of miss is this?

Capacity. With full associativity there are no conflict misses. The block was pushed out only because there was no room.
