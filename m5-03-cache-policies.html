Replacement & write policies

A cache needs rules. A replacement policy decides which block to throw out when the set is full. A write policy decides when a change made in the cache is copied to main memory.

Think of it like this: your desk holds only three books. When a fourth arrives, one must go back to the shelf. You can return the one you haven't touched for longest (LRU) or the one that arrived first (FIFO). And if you write notes in a book, you can copy them into the library's master copy every time (write-through), or only when you return the book (write-back).

Key terms

Eviction / victim
Throwing a block out of the cache to make room. The block thrown out is the victim.
LRU
Least Recently Used: evict the block whose last use is oldest.
FIFO
First In, First Out: evict the block that entered the cache first, however often it has been used.
Optimal (Bélády)
Evict the block whose next use is furthest in the future. Needs knowledge of the future, so it is used only as a yardstick.
Dirty bit
A 1-bit flag per slot. 1 means "changed in the cache, not yet copied to memory".
Stale
Out of date. Main memory is stale when the newest value exists only in the cache.
DMA
Direct Memory Access: a device (disk, network card) that reads and writes main memory without going through the CPU.
Prefetch
Loading a block into the cache before it is asked for, based on a guess.

1. When is a replacement policy needed?

  • Direct-mapped: never. Each block has exactly one possible slot, so the old block in that slot must go. There is no choice to make.
  • Set-associative or fully associative: when a miss happens and every way in the set is full, something must choose the victim.

2. Worked example: LRU vs FIFO

A fully associative cache with 3 slots, starting empty. Access sequence: A B C A D B E A. A new block goes into the empty slot or into the victim's slot.

LRU

LRU: 7 misses, 1 hit. At step 4, using A moves it to the "newest" end, so at step 5 the least recent block is B, and B is evicted, even though it is needed next.

FIFO

FIFO: 6 misses, 2 hits. A hit does not change the FIFO queue. At step 5, A arrived first, so A goes, and B survives for step 6.

So is FIFO better than LRU?

Not in general. On this short sequence FIFO happened to win. On real programs, which have strong temporal locality, LRU usually has fewer misses. The practice section has a sequence where LRU wins 5 misses to 7. Always trace the sequence you are given.

3. LRU in hardware: 1 bit for a 2-way set

With 2 ways, "which one is least recent?" has only two answers, so one bit per set is enough. On every access, set the bit to point at the other way.

With more ways the cost grows. Exact LRU must remember a full ordering: N ways have N! possible orders, so it needs log₂(N!) bits per set (4-way: log₂24 ≈ 4.6 → 5 bits; 8-way: 16 bits). That is why big caches and virtual memory use cheaper LRU approximations (for example, a "recently used" bit that is cleared now and then).

4. Write policies: write-through vs write-back

When the CPU writes to a block that is in the cache, main memory now holds an old copy. When should memory be updated?

Why the stale copy matters

On a multicore chip, each core has its own cache. If core 0 uses write-back, core 1 or a DMA device reading main memory can see the old value. Module 6 covers how caches keep each other consistent: see cache coherence & MESI.

5. Write buffer and read policies

Write buffer
A small queue that holds blocks waiting to be written to memory. The CPU drops the write into the buffer and carries on, instead of waiting for DRAM.
Demand fetch
Load a block only when it is asked for and missed. Simple, but every first access is a miss.
Prefetch
Guess what is needed next (for example, block n+1 after block n) and load it early. Uses spatial locality. A wrong guess wastes work and may evict a useful block.

Common mistakes & exam traps

Slips that cost marks
  • FIFO ignores hits. A hit does not move a block in the FIFO queue. It does in LRU.
  • Direct-mapped caches have no replacement choice. Don't apply LRU to them.
  • Count the first few misses too (the cache starts empty). They are compulsory misses.
  • "LRU is always better than FIFO" is false. It depends on the sequence; trace it.
  • Write-back copies a block to memory only if its dirty bit is 1. A clean block is just dropped.
  • Write-through is always consistent but slow; write-back is fast but temporarily stale. Don't swap them.

Practice

3 slots, sequence A B C A B D A D B C. Count the misses for LRU and for FIFO.

LRU: A, B, C miss; A, B hit; D misses and evicts C (least recent); A, D, B hit; C misses and evicts A. 5 misses.

FIFO: A, B, C miss; A, B hit; D evicts A; A evicts B; D hits; B evicts C; C evicts D. 7 misses.

Here LRU wins, because A and B are used often but FIFO evicts them anyway.

2 slots, sequence A B A C B A. Count LRU and FIFO misses.

LRU: M, M, H, M (evict B), M (evict A), M (evict C) → 5 misses.

FIFO: M, M, H, M (evict A), H, M (evict B) → 4 misses.

Which replacement policy does a direct-mapped cache use?

None is needed. Each block can live in only one slot, so the block already there is always the victim.

How many bits per set does exact LRU need for a 4-way set?

4 ways can be ordered in 4! = 24 ways. log₂24 ≈ 4.58, so 5 bits.

A loop writes to the same cached block 1,000 times, then the block is evicted. How many main-memory writes happen under each write policy?

Write-through: 1,000 (one per write). Write-back: 1 (at eviction, because the dirty bit is 1).

A block is evicted and its dirty bit is 0. What happens?

Nothing is copied. The block was never changed, so memory already has the same data. The slot is simply reused.

Why can write-back cause wrong results when a network card uses DMA?

The card reads main memory directly. Under write-back, the newest data may still be only in the CPU cache, so the card sends stale data. The OS must flush (write back) such blocks first.
