Virtual memory, page tables & the TLB

Every program believes it has a huge, private memory that starts at address 0. These virtual addresses are translated, page by page, into physical addresses in real RAM. A page table stores the translations, and a small, fast cache called the TLB remembers the recent ones.

Think of it like this: a big library with a catalogue. You ask for "shelf 3, book 42" (virtual address). The catalogue (page table) says shelf 3 is really kept in room 7 (physical page), so you fetch "room 7, book 42". You keep a sticky note of the last few lookups (TLB) so you rarely open the catalogue. If the catalogue says "in the warehouse" (on disk), a librarian must fetch it first: that is a page fault.

Key terms

Virtual address (VA)
The address a program uses. Each program has its own virtual address space.
Physical address (PA)
The real location in RAM.
Page / frame
A fixed-size chunk (often 4 KB) of virtual memory is a page. The same-size chunk of RAM it lives in is a frame (physical page).
VPN / PPN
Virtual page number and physical page number: the "which page" part of each address.
Page table
A per-program table in RAM: entry number VPN holds that page's PPN and status bits. One entry is a PTE.
Page-table register
A CPU register holding the address of the current program's page table.
Page fault
The page is not in RAM (valid bit = 0). The OS must load it from disk.
TLB
Translation Lookaside Buffer: a small, fast cache of recent VPN → PPN translations.
MMU
Memory Management Unit: the CPU hardware that does the translation.

1. Why virtual memory?

BenefitWhat it means
Isolation (protection)Each program has its own page table, so it cannot even name another program's memory. A bug or attack in one cannot overwrite another.
Illusion of a large memoryPages not in use can wait on disk. A program can be bigger than the RAM.
RelocationA program can be loaded into any free frames. Its pages need not be next to each other, and it always sees the same virtual addresses.

This is also a safety net for the "programs are data" idea of von Neumann machines: page protection bits can mark code pages read-only and data pages non-executable. See von Neumann vs Harvard.

2. Splitting the address

VA = VPN | page offset   →   PA = PPN | page offsetOnly the page number is translated. The offset is copied unchanged. offset bits = log₂(page size): 4 KB = 2¹² bytes → 12 bits.

A 32-bit VA with 4 KB pages: offset = 12 bits, VPN = 32 − 12 = 20 bits.

Worked translation

  1. 16-bit VA, 4 KB pages → 12-bit offset, 4-bit VPN.
  2. VA = 0x3A7F = 0011 1010 0111 1111. Each hex digit is 4 bits, so the offset is the last 3 hex digits.
  3. VPN = 0x3, offset = 0xA7F.
  4. The page table says VPN 3 → PPN 0x7.
  5. PA = PPN followed by the offset = 0x7A7F.

3. The page table

Valid bit
1 = page is in RAM and PPN is usable. 0 = page is on disk (or not allocated).
Protection bits
Read / write / execute permissions. Breaking them causes a fault (e.g. writing to code).
Dirty bit
Set on a write. A dirty page must be saved to disk before its frame is reused.
Reference (use) bit
Set on any access; cleared now and then by the OS. Used to approximate LRU.

4. Page faults, and why VM is designed differently

On a page fault the CPU stops the program and jumps to the OS. The OS picks a victim frame (saving it to disk if dirty), reads the wanted page from disk, updates the page table, and restarts the instruction.

A disk read takes about 10 ms = 10,000,000 ns, around 100,000× slower than DRAM. Because a miss is so expensive, VM makes choices that caches cannot afford:

How much does a page fault cost?

EAT = (1 − p) × tmem + p × tfaultp = page-fault rate per access · EAT = effective access time

With tmem = 100 ns, tfault = 10 ms = 107 ns and p = 0.0001 (1 in 10,000): EAT = 100 + 0.0001 × (107 − 100) ≈ 1,100 ns. That is 11× slower than RAM alone, from just one fault in ten thousand accesses.

5. How big is a page table?

  1. 32-bit VA, 4 KB pages → VPN = 20 bits → 220 = 1,048,576 entries.
  2. Each PTE is 4 bytes → 220 × 4 = 222 bytes = 4 MB.
  3. That is per program. With 100 programs running, 400 MB of RAM would go to page tables.
  4. For 64-bit machines (48-bit VA, 8-byte PTEs) a flat table would need 236 × 8 = 512 GB. Impossible.

Fix: multi-level page tables

Split the VPN into pieces. The first piece indexes a small outer table; that entry points to an inner table; the second piece indexes it. Inner tables exist only for address ranges the program actually uses.

x86-64 uses 4 levels for a 48-bit VA: 9 + 9 + 9 + 9 + 12 bits. The price: one translation may need 4 extra memory reads. The TLB makes that rare.

6. The TLB: a cache for translations

Without help, every memory access would need two reads: one for the PTE, one for the data. The TLB is a small (tens to a few thousand entries), usually fully associative cache of recent VPN → PPN pairs, with their valid, dirty, reference and protection bits.

vpn = va >> 12Drop the 12 offset bits to get the page number (4 KB pages).
offset = va & 0xFFFKeep only the low 12 bits. 0xFFF is twelve 1-bits.
if vpn in tlb:TLB hit: fast path.
ppn = tlb[vpn]
else:TLB miss.
pte = page_table[vpn]Read the entry from RAM (the page-table walk).
if not pte.valid:Page not in RAM.
os_handle_page_fault(vpn)OS loads it from disk and fixes the table …
return retry()… then the instruction runs again from the start.
ppn = pte.ppn
tlb.add(vpn, ppn)Remember it (evicting an old TLB entry if full).
pa = (ppn << 12) | offsetShift the PPN up 12 places and glue the offset back on. | is bitwise OR.

Effective access time with a TLB

EAT = h × (tTLB + tmem) + (1 − h) × (tTLB + 2 × tmem)h = TLB hit rate. On a miss, one extra memory read fetches the PTE (single-level table, no page fault).
  1. tTLB = 20 ns, tmem = 100 ns, h = 98%.
  2. Hit: 20 + 100 = 120 ns. Miss: 20 + 100 + 100 = 220 ns.
  3. EAT = 0.98 × 120 + 0.02 × 220 = 117.6 + 4.4 = 122 ns.
  4. Without a TLB every access costs 2 × 100 = 200 ns. The TLB saves about 39%.

  2. TLBhit → PPN
  3. Page tableon TLB miss
  4. Page faultonly if PTE invalid
  5. Build PAPPN | offset

Common mistakes & exam traps

Slips that cost marks
  • The offset is never translated. Only the VPN changes.
  • Offset bits come from the page size, not the memory size. 4 KB → 12 bits, 8 KB → 13 bits.
  • A TLB miss is not a page fault. A TLB miss just means a page-table walk; a page fault means the page is on disk.
  • Page-table size = number of entries (2VPN bits) × PTE size. Don't use the physical memory size.
  • The page table is per process; the page-table register changes on every process switch.
  • VM uses write-back (dirty bit), never write-through, because disk writes are far too slow.
  • With hex, each digit is 4 bits: a 12-bit offset is exactly the last 3 hex digits.

Practice

32-bit VA 0x12345678, 4 KB pages. Find VPN and offset. If VPN maps to PPN 0xABC, what is the PA?

Offset = last 3 hex digits = 0x678. VPN = 0x12345. PA = PPN then offset = 0x00ABC678.

16-bit VA 0xBEEF, 4 KB pages, and the page table maps VPN 0xB → PPN 0x2. Find the PA.

VPN = 0xB, offset = 0xEEF. PA = 0x2EEF.

32-bit VA, 8 KB pages, 4-byte PTEs. How big is a flat page table?

8 KB = 213 → 13-bit offset → VPN = 19 bits. Size = 219 × 4 = 2,097,152 bytes = 2 MB.

48-bit VA, 4 KB pages, 8-byte PTEs. How big would a flat page table be?

VPN = 48 − 12 = 36 bits. 236 × 8 = 239 bytes = 512 GB. That is why multi-level tables are used.

TLB lookup 10 ns, memory access 80 ns, TLB hit rate 90%. Find the effective access time.

Hit: 10 + 80 = 90 ns. Miss: 10 + 80 + 80 = 170 ns. EAT = 0.9 × 90 + 0.1 × 170 = 81 + 17 = 98 ns.

RAM access 100 ns, page-fault service 10 ms. What fault rate p keeps EAT at or below 110 ns?

100 + p × (107 − 100) ≤ 110 → p ≤ 10 ÷ 9,999,900 ≈ 1 × 10−6: at most about one fault per million accesses.

Why does virtual memory use fully associative placement and write-back, when caches often don't?

A page fault costs milliseconds, about 100,000× a DRAM read. Anything that avoids even a few faults is worth it: letting a page go in any frame removes conflict faults, and the OS can afford smart (software) choices. Writing to disk on every write would be hopelessly slow, so pages are written back only when evicted, and only if dirty.

A TLB miss happens, and the PTE is valid. Is this a page fault?

No. The hardware (or OS) reads the PTE from the page table, loads it into the TLB and continues. It costs an extra memory read or two, not a disk read.
