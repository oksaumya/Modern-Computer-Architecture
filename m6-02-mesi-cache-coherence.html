Cache coherence & the MESI protocol

In a multicore chip, each core has its own cache. Two cores can hold copies of the same memory block. If one core changes its copy, the other copy is now wrong. MESI is a set of four labels (states) and rules that keep all the copies in agreement.

Think of it like this: two students each photocopy the same page of class notes. If one student edits their copy, the other student's copy is out of date. The rule: before you edit, shout "throw your copy away!" If you are the only one with a copy, you can edit quietly.

Key terms

Cache line (block)
The unit a cache stores, e.g. 64 bytes of memory. MESI keeps one state per line. See cache organization.
Stale copy
A cached copy that no longer matches the latest value.
Dirty
The cached copy has been changed and main memory has not been updated yet.
Clean
The cached copy is the same as the copy in main memory.
Write back
Copying a dirty line from the cache to main memory.
Broadcast / invalidate
A message sent to every other core: "your copy of this line is no longer valid".
Bus traffic
Messages between cores. They cost time, so good protocols avoid them.
Cache coherence
Keeping all the cached copies of the same data in agreement.

1. The problem: stale copies

Cache coherence

A hardware mechanism. It makes sure every cached copy of a block matches the latest written value, or is marked invalid.

Memory consistency

A promise to programs about what value a read returns when several processors share memory. The usual promise: "a read sees the most recent write". Coherence protocols like MESI are how the hardware keeps that promise.

4. Worked example: two cores, one block X

Click through. Memory starts with X = 5, and neither cache holds X yet.

Step 0, start. Core A: I · Core B: I · Memory X = 5.

Step 1, A reads X. A has a miss and asks on the bus. Nobody else has a copy, so A loads X = 5 and marks it E.

A: E (5) · B: I · Memory 5. Bus: 1 read request.

Step 2, A writes X = 7. A holds X in E, so it knows it is the only owner. It changes the value silently: E → M. No bus message is needed.

A: M (7, dirty) · B: I · Memory still 5. Bus: nothing. This is exactly why the E state exists.

Step 3, B reads X. B has a miss and asks on the bus. A sees that it holds X in M, so A writes 7 back to memory and drops to S. B loads 7 and marks it S.

A: S (7) · B: S (7) · Memory 7. B read the correct value.

Step 4, B writes X = 9. B holds X in S, so other copies might exist. B broadcasts invalidate. A's copy goes S → I. B goes S → M.

A: I · B: M (9, dirty) · Memory 7. Bus: 1 invalidate.

Step 5, A reads X again. A has a miss (its copy is I). B holds X in M, so it writes 9 back and drops to S. A loads 9 and marks it S.

A: S (9) · B: S (9) · Memory 9. Every read saw the latest value.

5. The family: MSI, MESI, MESIF, MOESI

ProtocolIdea
MSINo E state. Even when a core is the only owner, its first write must broadcast an invalidate. That is wasted bus traffic for the very common "read, then write" pattern.
MESIAdds E, so the lone owner can write silently.
MESIF (Intel)Adds F (Forward): among the S copies, exactly one is marked F. Only that core answers requests for the line, so the others don't all reply at once.
MOESI (AMD)Adds O (Owned): this core is responsible for the line's latest value even though others hold shared copies.

6. False sharing: a coherence slowdown

MESI tracks whole cache lines, not single variables. If two unrelated variables sit in the same 64-byte line, and two cores each update "their own" variable, every write invalidates the other core's copy. The line ping-pongs between the cores.

The fix

Keep data that different cores write in different cache lines: add padding between the variables, or give each thread its own local copy and combine them at the end.

Common mistakes & exam traps

Slips that cost marks
  • E → M is silent. S → M needs a broadcast. Examiners love this difference.
  • M means dirty and only this core has it. There is never an M copy and an S copy of the same line at the same time.
  • Before leaving M (for S or I), the core must write the value back to memory. Otherwise the update is lost.
  • A read miss goes to E only if no other core has a copy. Otherwise it goes to S.
  • False sharing is a performance problem, not a correctness bug. The answers are still right, just slow.
  • Don't mix up MESI (between caches of different cores) with write policies (between one cache and memory).

Practice

What do the four letters of MESI stand for, and what does each mean?

Modified: only mine, dirty. Exclusive: only mine, clean. Shared: maybe several copies, clean. Invalid: no usable copy.

Why does MESI add the E state to MSI?

So a core that is the only owner can write without any bus message (E → M silently). In MSI, a lone reader's first write still needs a broadcast.

Core A holds X in M. Core B reads X. Give both new states and what A must do.

A writes its value back to memory, then A: M → S. B loads the fresh value and becomes S.

Both cores hold X in S. Core B writes X. What happens?

B broadcasts invalidate. A: S → I. B: S → M.

Trace A-read, A-write, B-write starting with both in I. Give the final states.

A-read: A = E, B = I. A-write: A = M (silent). B-write: B misses, and A writes back and goes to I. B = M. Final: A = I, B = M.

Two threads update different counters, but the program is slow. Profiling shows many cache misses. What could it be?

False sharing: the counters sit in the same cache line, so each write invalidates the other core's copy. Fix: pad them into separate lines, or use per-thread counters.

What does the F in MESIF add?

One shared copy is marked Forward. Only that core answers requests for the line, which avoids many duplicate replies.
