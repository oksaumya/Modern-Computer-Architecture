Heterogeneous computing: big.LITTLE, CPU + GPU, CPU + NPU

A heterogeneous chip mixes different kinds of processors, each good at one kind of job. Every job goes to the part that does it with the least energy. Your phone already works this way.

Think of it like this: a delivery company doesn't use a truck for every parcel. A bicycle takes small, nearby letters cheaply. A truck takes heavy loads. A special refrigerated van takes food. The dispatcher (the scheduler) picks the right vehicle for each job.

Key terms

Homogeneous
All cores are identical (like the SMP chip on the previous topic).
Heterogeneous
The chip has different types of cores or processors.
P-core / big core
A performance core: fast, large, power-hungry.
E-core / LITTLE core
An efficiency core: slower, small, uses very little power.
Scheduler
The part of the OS that decides which task runs on which core.
SoC
System-on-Chip: CPU, GPU and other processors all on one chip.
GPU
Graphics processing unit: thousands of simple cores that do the same maths on lots of data.
NPU
Neural processing unit: a block made to run AI models (inference) with very little power.
ISP / DSP
Image signal processor (cleans up camera images) and digital signal processor (audio, radio signals).
Offload
Sending work from the CPU to another processor.
FPGA
A chip whose logic gates you can rewire after it is made.
ASIC
Application-specific integrated circuit: a chip designed for one job only.

1. Why mix processor types?

Since the power wall, we can't power every transistor at full speed. So the question became: what gives the most useful work per watt? The answer: a special processor for each common kind of job, switched on only when needed.

2. big.LITTLE and P/E cores

  • ARM big.LITTLE (announced 2011) puts a cluster of big cores and a cluster of little cores on one chip. Both run the same instruction set, so a task can move between them.
  • ARM DynamIQ (2017) is the newer version. Big and little cores can sit together in the same cluster.
  • Apple calls them P-cores and E-cores (for example in the M-series chips).
  • Intel added P-cores and E-cores with 12th-gen Core (Alder Lake, 2021). A hardware helper, "Thread Director", gives the OS hints.

4. CPU + NPU

  • An NPU is built for inference: running an already-trained neural network (face unlock, voice commands, photo effects).
  • It works mostly with INT8: 8-bit whole numbers instead of 32-bit decimal (floating-point) numbers. The answers are nearly as good, and much cheaper to compute.
  • Example: a model with 100 million weights needs 100M × 4 bytes = 400 MB in 32-bit float, but only 100M × 1 byte = 100 MB in INT8. That is 4× less memory to store and move.
  • Power budgets are small, often a few watts or less on phones. A CPU doing the same job would use far more energy.

A fair throughput comparison

  1. Fix the workloadSame sample rate, same window size, same run time.
  2. Warm upIgnore the first few seconds.
  3. MeasureThroughput = windows processed ÷ seconds.
  4. Repeat3–5 runs per setup. Report the average.
  5. CompareSpeedup = split ÷ single-core.
Reading the numbers (made-up example)

Say single-core gives 800 windows/s and split gives 1400 windows/s. Speedup = 1400 ÷ 800 = 1.75×. That is less than 2×, because of the queue overhead and the serial parts (Amdahl). Use your own measurements in the report.

Common mistakes & exam traps

Slips that cost marks
  • Saying little cores are "worse". They give more work per watt for light loads. That is the whole point.
  • Assuming the GPU is always faster. For small data, the PCIe copy can make it slower.
  • Mixing up training (learning the weights; usually on big GPUs/TPUs) and inference (using them; what NPUs target).
  • Placing the FPGA and ASIC the wrong way round: an ASIC is more efficient and less flexible.
  • big.LITTLE cores share the same instruction set. That is what lets tasks move between them.

Practice

What problem does big.LITTLE solve?

Most of the time a phone does light work. Running it on big cores wastes battery. Little cores handle light work efficiently, and big cores wake up only for heavy bursts.

Why might a small matrix multiply run slower on a discrete GPU than on the CPU?

The data must be copied to GPU memory over PCIe and back. For small data, that copy time is larger than the time the GPU saves.

A 50-million-weight model: how much memory in 32-bit float and in INT8?

50M × 4 bytes = 200 MB. 50M × 1 byte = 50 MB. INT8 is 4× smaller.

Order CPU, ASIC, GPU, FPGA from most flexible to most efficient.

CPU → GPU → FPGA → ASIC. Flexibility falls and efficiency rises along the list.

What is unified memory and why does it help?

The CPU and GPU share one physical memory pool, so data doesn't need to be copied between them. That saves time and energy.

Single-core: 500 windows/s. Split: 900 windows/s. What is the speedup, and why isn't it 2×?

900 ÷ 500 = 1.8×. The queue adds overhead, and part of the work can't run in parallel (Amdahl's law).
