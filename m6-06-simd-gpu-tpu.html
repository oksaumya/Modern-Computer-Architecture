SIMD, GPUs & AI hardware

Much heavy computing, like graphics, matrix maths and AI, repeats the same operation on huge amounts of data. SIMD does that inside a CPU core, a few numbers at a time. A GPU does it with thousands of simple cores. A TPU is a chip built only for it. This page is an overview.

Think of it like this: stamping 1,000 envelopes. One person with one stamp is the plain CPU. One person with a stamp that hits 8 envelopes at once is SIMD. A hall of 1,000 people each stamping their own envelope is a GPU. A machine that only stamps envelopes is a TPU.

Key terms

Flynn's taxonomy
A 1966 classification of computers by how many instruction streams and data streams they handle.
SIMD
Single Instruction, Multiple Data: one operation applied to several numbers at once.
Vector register
An extra-wide register (128, 256 or 512 bits) holding several numbers side by side.
Lane
One number's slot inside a vector register. A 256-bit register has 8 lanes of 32 bits.
SIMT
Single Instruction, Multiple Threads: NVIDIA's name for the GPU model. Many threads run the same code on different data.
Kernel (GPU)
The small function that every GPU thread runs. (Not the OS kernel.)
Thread / block / grid
CUDA's three-level grouping: threads form blocks, and blocks form a grid.
Warp
A group of GPU threads that the hardware schedules together and runs in lockstep. See section 4.
HBM
High Bandwidth Memory: stacked DRAM chips placed right next to the processor.
BLAS
Basic Linear Algebra Subprograms: a standard, heavily tuned library of vector and matrix maths.
TPU
Tensor Processing Unit: Google's ASIC for neural-network maths.
Chiplet
A small die that is combined with other dies in one package to make a larger chip.

3. GPUs: thousands of simple cores

SIMT and the CUDA hierarchy

In CUDA (NVIDIA's GPU programming system) you write one kernel function. The GPU runs it on thousands of threads at once, and each thread works out which element is "its own" from its ID numbers.

pseudocode · a GPU kernelcode → what it means
kernel add_vectors(A, B, C, N):This function runs once per GPU thread, all at the same time.
i = blockIdx * blockDim + threadIdxWork out "my" element number from my block and thread IDs.
if i < N:Extra threads (the total is rounded up) do nothing.
C[i] = A[i] + B[i]One element's work. No loop: the loop is "all the threads together".
# launch: N = 1000, blockDim = 256We choose 256 threads per block.
# blocks = ceil(1000 / 256) = 44 blocks × 256 = 1024 threads. 24 of them fail the if and just stop.

4. Warps (syllabus term)

Your syllabus lists "warps". This is a real GPU term. NVIDIA's CUDA documentation uses it:

  • A warp is a group of GPU threads that the hardware schedules together. All threads in a warp run the same instruction at the same moment (in lockstep). This is the SIMT model at the hardware level.
  • On NVIDIA GPUs a warp is 32 threads in practice. Technically the size depends on the hardware.
  • Threads in a warp may take different if branches (unlike pure SIMD). But when they diverge, some threads wait while others run their branch, so heavy branching in a kernel slows the GPU down.
  • Practical tip: pick a block size that is a multiple of 32 (e.g. 256). Otherwise the last warp has unused slots. In the example above, 1024 threads = 1024 ÷ 32 = 32 warps.
  • Other GPU APIs have similar ideas under other names: "SIMD groups" (Apple Metal), "waves" (DirectX), "subgroups" (WebGPU).
How much to learn

For the exam, knowing "a warp = a group of (typically 32) GPU threads executed together, SIMT-style" should be enough. If your instructor uses the term differently in class, follow their definition.

HBM: feeding the GPU fast enough

Thousands of cores are useless if data arrives slowly. This is the memory wall again. High Bandwidth Memory stacks several DRAM chips on top of each other, connects them with vertical wires through the silicon (TSVs), and places the stack right beside the GPU on a silicon interposer: a thin silicon base with very dense wiring.

What to write in your lab report

  • Pure Python: O(n³) steps, each with heavy interpreter overhead. Doubling n makes it about 2³ = 8× slower.
  • NumPy: the same O(n³) maths, but done by BLAS in compiled code with SIMD, several threads and cache blocking. Usually hundreds to thousands of times faster than pure Python.
  • CuPy: thousands of GPU threads. There is a fixed cost for copying and launching work, so small matrices can be slower on the GPU. Large ones are much faster.
  • Always plot the times on a log scale. The gaps are too big for a normal axis.

6. TPUs and AI hardware

  • Google TPU (first announced in 2016) is an ASIC built for the tensor maths of neural networks, mostly big matrix multiplies.
  • It uses low precision numbers (8-bit integers, or 16-bit "bfloat16"), which need less silicon and memory than 32-bit floats.
  • It pairs the compute with high-bandwidth memory, and links many chips into "pods" for training large models.

Systolic arrays

An idea from H.T. Kung and Charles Leiserson (late 1970s). A regular grid of simple processors, each wired only to its neighbours. On every clock tick, each cell does a small computation and passes the data along, like a heartbeat ("systole" is the heart's pumping beat).

It suits matrix operations. The same thinking (regular, local, dataflow-style hardware) shows up in today's AI accelerators.

Chiplets

Instead of one huge die, build several smaller dies and join them in one package. Examples: AMD EPYC (CPU chiplets + an I/O die) and Intel Foveros (dies stacked in 3D). UCIe is an open standard for connecting chiplets.

  • Better yield and lower cost (small dies fail less often).
  • Each part can use a different process node (newest node for the CPU, a cheaper node for I/O).

Common mistakes & exam traps

Slips that cost marks
  • SIMD = one instruction on many data values. MIMD = many independent instruction streams (multicore).
  • A 512-bit register holds 16 32-bit values, but only 8 64-bit values.
  • SIMT is not pure SIMD: GPU threads can take different branches, but divergence costs speed.
  • A GPU is not always faster. Small problems lose to transfer and launch overhead.
  • Forgetting to synchronize() when timing GPU code makes it look impossibly fast.
  • NumPy is not "multicore Python". It calls compiled BLAS, which uses SIMD, threads and cache blocking.
  • HBM is DRAM, placed close to the processor. It is not a kind of SRAM cache.

Practice

How many 32-bit floats fit in an AVX (256-bit) register? And how many 64-bit doubles in AVX-512?

256 ÷ 32 = 8. 512 ÷ 64 = 8.

Classify: (a) a quad-core laptop CPU, (b) an AVX add of two arrays, (c) a classic single-cycle MIPS CPU.

(a) MIMD. (b) SIMD. (c) SISD.

A CUDA launch uses blockDim = 128. Which global index does thread 10 in block 3 get?

i = 3 × 128 + 10 = 394.

N = 5000 elements, blockDim = 256. How many blocks? How many threads do nothing?

5000 ÷ 256 = 19.53, so 20 blocks = 5120 threads. 5120 − 5000 = 120 idle threads.

What is a warp, and why choose a block size that is a multiple of 32?

A warp is a group of GPU threads (32 on NVIDIA in practice) scheduled and run together in lockstep. A multiple of 32 fills every warp, so no slots are wasted.

Pure Python takes 3 s for n = 256. Roughly how long for n = 512?

O(n³): doubling n gives 2³ = 8×, so about 24 s.

Why can a 64 × 64 matrix multiply be slower on the GPU than with NumPy?

The actual maths is tiny. The fixed costs (copying data over PCIe, launching the kernel, synchronising) take longer than NumPy's whole run.

Give two advantages of chiplets over one big die.

Higher yield (a defect ruins only a small die), and each chiplet can use the best or cheapest process node for its job. Parts can also be reused across products.
