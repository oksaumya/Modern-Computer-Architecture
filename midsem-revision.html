Module 1 · Digital FoundationsLectures 1–4 · 0s and 1s become arithmetic

L1Boolean algebra & logic gates

Circuits are built from gates, and gates follow algebra you can simplify.
  • Gates: AND = both 1. OR = at least one 1. NOT = flip. XOR = inputs differ. NAND/NOR = AND/OR with the output flipped.
  • Universal gates: NAND alone (or NOR alone) can build everything. NOT A = A NAND A.
  • Laws: A+0=A · A·1=A · A+1=1 · A·0=0 · A+A'=1 · A·A'=0 · A+AB=A (absorption).
  • De Morgan: (A·B)' = A'+B' ("not both") and (A+B)' = A'·B' ("neither"). Break the bar, flip the sign.
  • Architecture vs organisation: architecture = what the programmer sees (instructions); organisation = how it's built (pipeline, caches).

Trap: `+` is OR, not addition, so A+1 = 1. And OR ≠ XOR — check the row where both inputs are 1.

L2Logic minimisation & universal gates

Fewer gates means less area, power, delay and cost — K-maps find the smallest circuit.
  • SOP uses the rows where F = 1: a 1 becomes X, a 0 becomes X'. POS uses the rows where F = 0 and flips that rule.
  • Shorthand: F = Σm(1,3,5,7) = ΠM(0,2,4,6). The two lists are complements.
  • K-map: columns run in Gray code 00, 01, 11, 10. Group 1s in rectangles of 1, 2, 4 or 8. Bigger group = fewer letters. Groups may overlap, and edges wrap around (corners count).
  • Don't-care (X): treat as 1 only when it makes a group bigger.
  • Prime implicant = a group that can't grow. Essential = it's the only one covering some 1.

Trap: reading K-map columns in binary order (00, 01, 10, 11) instead of Gray code, and forgetting the four-corner group.

L3Combinational building blocks & adders

Reusable blocks: choose a signal, route a signal, and add numbers.
  • MUX (many → one): 2ⁿ inputs need n select lines. 2:1 MUX: Y = S'A + SB. A 2ⁿ:1 MUX can implement any n-variable function — this is how FPGA lookup tables work.
  • DEMUX (one → many) and decoder (code → one-hot). A decoder is a DEMUX whose data input is a constant 1. An n-to-2ⁿ decoder needs 2ⁿ AND gates, one per minterm.
  • Half adder: Sum = A⊕B, Carry = A·B. No carry-in, so it can't be chained.
  • Full adder: Sum = A⊕B⊕Cin, Cout = AB + Cin(A⊕B). Build from 2 half adders + OR.
  • Ripple-carry: delay ≈ 2n gate delays (slow). Carry look-ahead: G = A·B (generate), P = A⊕B (propagate), c(i+1) = G + P·c(i) — all carries computed at once.

Trap: mixing up DEMUX and decoder, and wrong select count (an 8:1 MUX needs 3 selects, not 8).

L4Number systems & two's complement · overflow

The same bits mean different numbers — the instruction decides, not the bits.
  • Hex: 1 digit = 4 bits. 0x2A = 0010 1010 = 42. Powers of 2: 2¹⁰ = 1024, 2²⁰ ≈ 1 million, 2³⁰ ≈ 1 billion.
  • Two's complement negate: invert all bits, add 1. +18 = 00010010 → 11101110 = −18. It works both ways.
  • Read it: the MSB has weight −2ⁿ⁻¹. Range: −2ⁿ⁻¹ … +2ⁿ⁻¹−1 (8-bit: −128…+127). Asymmetric: −128 has no positive twin.
  • Sign extension: copy the sign bit, don't pad with zeros. −5 = 1011 → 11111011.
  • Subtract: A − B = A + (~B) + 1.
  • Overflow: signed OF = C(into MSB) ⊕ C(out of MSB); unsigned CF = carry-out. Sign rule: (+)+(+) = (−) or (−)+(−) = (+) means overflow; mixed signs never overflow.

Trap: 10000000 is −128, not −0. And carry-out alone does not mean signed overflow.

Module 2 · Sequential Circuits & MemoryLectures 5–8 · circuits that remember

L5Latches · flip-flops & timing

A feedback loop turns a circuit into memory; a clock decides when it may change.
  • Combinational output = f(inputs now). Sequential output = f(inputs, past state). The difference is one feedback loop.
  • SR latch: 00 hold, 10 set, 01 reset, 11 forbidden (both outputs 0; releasing both causes a race, so the result is unpredictable).
  • D latch: S = D·E, R = ~D·E, so the forbidden state can't happen. Transparent while E = 1.
  • D flip-flop: samples D at the clock edge only, so glitches between edges are ignored. Built master-slave. Latch = level, flip-flop = edge.
  • Timing: D must be steady t_setup before and t_hold after the edge. Breaking that risks metastability (output hovering between 0 and 1); fix with a 2–3 flip-flop synchroniser. It can be made rare, never impossible.
  • Max clock: T ≥ t_cq + t_logic + t_setup; f_max = 1/T. (0.28 ns path + 0.05 ns setup → T ≥ 0.33 ns ≈ 3.03 GHz.)

Trap: in Verilog use <= inside every posedge block, and declare the output reg.

L6Registers & shift registers · counters

Put flip-flops side by side and you get words, shifting and counting.
  • Register = n flip-flops on one clock. Load enable = a 2:1 MUX per bit: load new data, or feed Q back to hold.
  • Shift registers: SISO (delay), SIPO (serial→parallel, UART receive), PISO (parallel→serial, UART transmit), PIPO (plain register). Shift left = ×2, right = ÷2.
  • Ripple counter: each flip-flop clocks the next. Cheap but briefly shows wrong values; f_max = 1/(n × t_pd).
  • Synchronous counter: one shared clock, valid right after the edge. Rule: a bit flips when all lower bits are 1 (T0 = 1, T1 = Q0, T2 = Q0·Q1).
  • Mod-N needs ⌈log₂N⌉ flip-flops (mod-12 → 4). Ring counter = n states; Johnson = 2n states.

Trap: forgetting the reset, and resetting a down-counter to 0 instead of its maximum value.

L7Register files · FSMs

A bank of registers the CPU reads twice and writes once per cycle, steered by a state machine.
  • Register file: 32 registers × 32 bits, 2 read ports + 1 write port. Write = 5:32 decoder picks which, write-enable decides whether. Read = two 32:1 MUXes.
  • The key fact: reads are combinational (no clock, instant); writes are synchronous (clock edge only). That's how `add R1,R2,R3` reads and writes in one cycle. $zero / x0 is hardwired to 0.
  • FSM = states + transitions + outputs. Structure: next-state logic → state register → output logic.
  • Moore: output depends on state only (written in the circle), glitch-free, often one extra state. Mealy: output depends on state + input (written on the arrow), reacts in the same cycle, fewer states.
  • Design flow: diagram → state table → encode states → K-maps → flip-flops + logic.
  • 1011 detector (overlapping): after a match, go to the state for the prefix the trailing bits already give — not back to S0. Mealy needs 4 states, Moore 5.

Trap: N states need ⌈log₂N⌉ flip-flops, and mixing Moore notation (output in the circle) with Mealy (in/out on the arrow).

L8SRAM vs DRAM & the memory stack

Fast memory is small and costly; big memory is slow and cheap — so computers layer both.
  • SRAM: 6 transistors per bit (two cross-coupled inverters). Self-healing, no refresh, a few ns, non-destructive read, low density. Used for caches.
  • DRAM: 1 transistor + 1 capacitor. ~6× denser and cheaper, 50–100 ns, needs refresh (charge leaks within ~64 ms) and every read is destructive, so the sense amplifier writes the value back. Used for main memory.
  • One line: SRAM trades density for speed; DRAM trades speed for density.
  • Hierarchy: registers → L1 → L2 → L3 → DRAM → SSD/disk. Each step is bigger, slower, cheaper.
  • Memory wall: CPU speed grew far faster than DRAM latency, so memory is now the bottleneck.

Trap: saying SRAM needs refresh. It doesn't — it needs power. DRAM needs refresh.

Module 3 · Computer Organization & ISALectures 9–12 · the language the CPU speaks

L9Von Neumann vs Harvard

Instructions are stored in memory as numbers, just like data.
  • Stored program (1945): code and data live in the same memory, so a program can be loaded, compiled or generated at run time (that's also where whole classes of security exploits come from).
  • Von Neumann: CPU + memory over one shared bus. Simple and flexible.
  • Bottleneck (named by John Backus, 1977): instructions and data take turns on one bus, so the CPU waits. It gets worse as CPUs outpace memory.
  • Harvard: separate instruction and data memories and buses, so fetch + data access happen in the same cycle — up to 2× throughput, at the cost of more wires and silicon. Used in DSPs and microcontrollers (Arduino's ATmega328).
  • Modified Harvard = your laptop: split L1-I and L1-D caches inside the chip, one unified DRAM outside.

Trap: "up to 2×" is a ceiling, not a promise — only loads and stores use the data bus.

L10CISC vs RISC

Put the complexity in the hardware decoder, or in the compiler.
  • CISC (x86, VAX): variable-length instructions, one instruction can touch memory and compute, microcode, fewer instructions per program, hard to pipeline.
  • RISC (MIPS, ARM, RISC-V): fixed 32-bit instructions, few formats, load/store only (arithmetic works on registers), many registers, easy to pipeline.
  • The trade: CISC = fewer instructions but complex hardware; RISC = more instructions but simple, fast hardware and a smarter compiler.
  • Iron law: time = instruction count × CPI × cycle time. CISC lowers the first term; RISC lowers the other two.
  • Modern reality: x86 chips decode CISC instructions into RISC-like micro-ops internally, so the line has blurred. RISC-V is open and royalty-free, with modular extensions (RV64GC = base + general + compressed).

Trap: "RISC = fewer instructions" means fewer kinds of instruction, not a shorter program. The program usually has more instructions.

L11MIPS32 registers & instruction formats

Every MIPS instruction is exactly 32 bits, in one of three shapes.
  • 32 registers: $zero (always 0), $v0–$v1 (returns), $a0–$a3 (arguments), $t0–$t9 (temporary — a called function may destroy these), $s0–$s7 (saved — a called function must restore these), $sp (stack), $ra (return address).
  • R-format: op(6) rs(5) rt(5) rd(5) shamt(5) funct(6) — op = 0, the funct field names the operation. For `add`, `sub`, `and`, `or`, `slt`.
  • I-format: op(6) rs(5) rt(5) immediate(16) — for `addi`, `lw`, `sw`, `beq`, `bne`. The immediate is sign-extended.
  • J-format: op(6) address(26) — for `j`, `jal`.
  • Memory: byte-addressed, so words sit 4 apart and must be 4-aligned. `lw $t0, 4($t1)` means "load from address $t1 + 4".
  • Branch offset counts instructions relative to PC+4, not bytes.

Trap: in R-format, the destination is rd; in I-format (including `lw`), the destination is rt.

L12C-to-MIPS translation · functions & stack

Every C construct becomes a fixed pattern of MIPS instructions.
  • if/else: branch on the opposite condition to skip the "then" part, and put j Exit at its end. `if (i==j)` → bne $t0,$t1,Else.
  • Comparisons: MIPS only has `beq`/`bne`, so `<` uses slt $t2,$t0,$t1 (set $t2 to 1 if less) then branch on $t2.
  • Loops: a `for` is a `while`: test at the top, body, update, jump back. Check the exit test carefully for off-by-one.
  • Arrays: address of A[i] = base + 4i, so sll $t1,$i,2 then add $t1,$t1,$base then lw.
  • Calls: jal label saves PC+4 into $ra and jumps; jr $ra returns. Arguments in $a0–$a3, results in $v0–$v1.
  • Stack grows down: push = addi $sp,$sp,-4 then sw; pop = lw then addi $sp,$sp,4. A leaf function calls nobody and may skip the frame; a non-leaf must save $ra, or the recursive call overwrites the way home.

Trap: a non-leaf function that forgets to save and restore $ra loops forever. Also, $t registers are not preserved across a call.

Module 4 · CPU Datapath & PipeliningLectures 13–15 · how it actually runs

L13Fetch-decode-execute & the single-cycle datapath

Wire the parts together and an instruction flows through in one clock cycle.
  • Cycle: fetch (PC → instruction memory, PC = PC + 4) → decode (read registers, read fields) → execute (ALU) → memory (load/store) → write back.
  • Parts: PC, instruction memory, register file, sign extender, ALU, data memory, and MUXes.
  • Control signals: RegDst, RegWrite, ALUSrc, ALUOp, MemRead, MemWrite, MemtoReg, Branch. PCSrc = Branch AND Zero.
  • Per instruction: R-type uses the ALU and writes a register; `lw` uses every stage (longest); `sw` doesn't write a register; `beq` uses the ALU to subtract and checks Zero.
  • Clock period = the slowest instruction (`lw`, about 800 ps in the textbook model), so faster instructions waste time. That's the reason to pipeline.

Trap: the clock is set by the worst-case path, not the average instruction.

L14Pipelining: the 5-stage MIPS pipeline

Overlap instructions like a laundry line: same time each, far more finished per hour.
  • Stages: IF → ID → EX → MEM → WB, separated by pipeline registers (IF/ID, ID/EX, EX/MEM, MEM/WB).
  • Throughput improves; latency does not. One instruction still takes 5 stages — more of them just finish per second.
  • Timing: n instructions on a k-stage pipeline take (k + n − 1) × stage time. 3 loads: 2400 ps single-cycle vs 1400 ps pipelined.
  • Ideal speedup ≈ number of stages, but only if the stages are balanced; the stage time is the slowest stage plus register overhead.
  • Why RISC pipelines well: fixed-length instructions, few formats, memory touched only by load/store.

Trap: don't compute pipelined time as n × stage time — the pipeline has to fill first: (k + n − 1).

L15Hazards, forwarding & scheduling

Overlapping breaks when an instruction needs something that isn't ready yet.
  • Three kinds: structural (two instructions want the same hardware), data (a value isn't ready), control (a branch isn't resolved yet).
  • Dependency names: RAW (read after write) = the true dependency; WAR (write after read) and WAW (write after write) are name clashes fixed by renaming. In an in-order pipeline, only RAW causes hazards.
  • Stall (bubble): freeze the earlier stages and insert a NOP. Correct, but slow.
  • Forwarding: the ALU result already exists in EX/MEM or MEM/WB, so route it straight back to the ALU input instead of waiting for write-back. Removes most RAW stalls.
  • Load-use hazard: the one forwarding can't fully fix — a loaded value isn't ready until after MEM, so you need 1 stall, then forward.
  • Compiler scheduling: reorder independent instructions into the stall slot (the textbook example drops 13 cycles to 11).
  • Control hazards: flush wrongly fetched instructions; deciding the branch in ID cuts the penalty to 1 cycle; predict with a 2-bit saturating counter so a loop mispredicts only once.

Trap: "forwarding removes all stalls" is false — load-use still costs one cycle.

Quick self-test

Simplify A + A'B.

A + B. By the distributive law, A + A'B = (A+A')(A+B) = 1·(A+B).

Write −45 as an 8-bit two's complement number.

45 = 00101101 → invert = 11010010 → +1 = 11010011.

4-bit: 0111 + 0001. Any overflow?

Result 1000. Unsigned 7+1 = 8 is fine (CF = 0). Signed +7+1 should be +8, but 1000 reads as −8, so OF = 1. Carry into the MSB is 1, carry out is 0.

Why are register-file reads combinational but writes clocked?

So one instruction can read two registers and write a third in a single cycle. Reads appear after a gate delay; the write lands on the clock edge, which avoids races and half-written values.

Why does a Moore 1011 detector need one more state than the Mealy version?

A Moore output belongs to a state, so "match" needs its own state (5). A Mealy machine can put the 1 on the arrow, so 4 states are enough.

Which memory needs refreshing, and why?

DRAM. Each bit is charge on a capacitor, which leaks within about 64 ms, so the controller rewrites every row. SRAM holds its bit in a latch and only needs power.

How long do 5 instructions take on a 5-stage pipeline with a 200 ps stage?

(5 + 5 − 1) × 200 = 1800 ps.

Which hazard can forwarding not remove, and what does it cost?

The load-use hazard: lw $2,0($1) followed by an instruction using $2. The data arrives only after MEM, so it costs 1 stall, then forwarding handles the rest. Reordering an independent instruction into that slot removes the stall.
